# Инструменты и источники

Что есть для работы над городом помимо кода: где брать данные и фото, как проверить картинку без экрана, кто чем сейчас занят. Правила работы (ветки, PR, авто-мерж) — в [CLAUDE.md](../CLAUDE.md), устройство проекта — в [README.md](../README.md).

## Кто чем занят

Чтобы два агента не правили одно и то же, перед началом работы добавьте сюда строку (тем же PR, что и работу, или отдельным коротким PR), а после мержа уберите её. Лучше брать разные части города и разные файлы. Если задача задевает чужие файлы из таблицы, сначала влейте свежий `origin/main`. В коммит попадают только свои строки таблицы. Каждый агент работает в своём git worktree и не трогает общий каталог — протокол изоляции в [AGENTS.md](../AGENTS.md).

## Автономный цикл улучшений

Бесконечный конвейер «улучшать то, что есть»: драйвер `tools/improve-loop.ps1` запускает итерации агента, каждая берёт задачу из [docs/improvement-backlog.md](improvement-backlog.md) и доводит её до смерженного PR; когда очередь пустеет — итерация аудирует город (кадры, ошибки консоли, замеры) и наполняет очередь снова. Запуск `npm run loop`, остановка — файл `LOOP-STOP` в корне. Полная документация: [docs/autoloop.md](autoloop.md). Ветки `chatbox/loop-*` зарезервированы за циклом.

## Проверка в браузере без экрана: `tools/shots.js`

Рендерит заданные виды города в JPEG в headless Chromium и выводит ошибки и предупреждения консоли страницы.

```bash
python3 -m http.server 8765 --bind 127.0.0.1
```
```bash
node tools/shots.js shots 0 square:-1440,1300,25:-1487,1263,0 bridge:-1760,1640,15:-1690,1712,0:60
```

- Вид задаётся как `имя:x,z,h:tx,tz,th[:fov]`. Здесь `x,z` — камера, `tx,tz` — точка, куда она смотрит. Высоты `h` и `th` отсчитываются от земли **в точке взгляда**, `fov` в градусах. Время суток: `0` день, `1` вечер, `2` ночь.
- Координаты города: метры, x — на восток, z — на юг, площадь Единства примерно в (−1487, 1263). Из широты и долготы в углу экрана: `x = (lon − 26.54) · 62438.48`, `z = (55.8825 − lat) · 111292.73`. Курс c (0 — север, 90 — восток) смотрит вдоль `(sin c, −cos c)`.
- WebGL запускается **на GPU, если он доступен** (общий хелпер [tools/browser.js](../tools/browser.js): пробует аппаратный рендер, проверяет реальный рендерер WebGL и только при его отсутствии переходит на SwiftShader). На GPU город строится за десятки секунд; на программном SwiftShader (CI без видеокарты) — 3–5 минут, каждый кадр до нескольких минут, тогда запускайте один браузер за раз и в фоне. `DPILS_GPU=0` принудительно включает SwiftShader, `CHROME_PATH=` задаёт путь к браузеру.
- На гибридных ноутбуках (Intel iGPU + NVIDIA dGPU) Windows по умолчанию отдаёт браузеру энергосберегающий адаптер, и headless рендерил на Intel. Хелпер сам закрепляет Playwright chromium за высокопроизводительной видеокартой через per-app настройку DirectX (`HKCU\Software\Microsoft\DirectX\UserGpuPreferences`, `GpuPreference=2` — то же, что «Параметры → Дисплей → Графика», без прав администратора; трогаются только тестовые chromium, не браузер пользователя). `DPILS_GPU_PREF=0` отключает это. Тёплый браузер, запущенный до закрепления, держит старый адаптер до перезапуска.
- Нужен Playwright с Chromium. В облачных сессиях Claude они уже стоят; в другом окружении: `npm i -D playwright` и `npx playwright install chromium`.
- Страница сама даёт отладке `window.__city`: игрок `P`, `camera`, `terrainH(x, z)`, `setTime`, `teleport` и др. (см. конец [src/main.js](../src/main.js)).
- Если поднят тёплый браузер (`tools/warm.mjs`), `shots.js` сам берёт кадры из него за секунды, без загрузки города заново.

## Тесты боя без браузера: `tools/combat-test.mjs`

```bash
npm test        # node tools/combat-test.mjs, ~15 с
```

Проверяет модель попаданий и правила сервера без браузера и без города: геометрию хитбоксов (`rayHit`: зоны голова/торс/ноги, присед, поворот, зазор между ног), урон по зонам и дробовик, защиту после возрождения, проход сквозь товарищей, стены и склон холма (уточнённый `freePath`), лаг-компенсацию положения, высоты глаз и поворота — на `createGame` с плоским вымышленным миром и управляемыми часами. В конце — настоящий бой восьми трудных ботов на плоской арене (12 с реального времени): боты должны стрелять и убивать с маленькими хитбоксами. Падает с кодом 1 при любом провале; CI гоняет его между `npm run check` и `npm run build`.

## Тёплый браузер для проверок: `tools/warm.mjs`

Держит город загруженным в headless-браузере (GPU через [tools/browser.js](../tools/browser.js)): загрузка один раз, дальше каждый прогон `tools/shots.js` только двигает камеру и снимает — секунды вместо полной загрузки. Сам раздаёт репозиторий, отдельный статический сервер не нужен.

```bash
node tools/warm.mjs          # порт 8771 (WARM_PORT=), viewport VW/VH; ждёт «warm: ready»
node tools/shots.js shots 0 square:-1440,1300,25:-1487,1263,0   # автоматически через тёплый (WARM= адрес)
```

- После правок данных или `src/` обновите страницу: `curl -X POST http://127.0.0.1:8771/__warm/reload` (или Invoke-RestMethod).
- Состояние между кадрами сохраняется (время, камера, режим); `/__warm/reload` возвращает чистую прогулку. Произвольный код в странице — `POST /__warm/eval` (тело — JS-выражение, ответ JSON). Ошибки консоли копятся и выдаются `/__warm/errs` (shots.js печатает их сам).
- Один браузер — один кадр за раз: запросы выстраиваются в очередь. Останавливайте процесс, когда проверки больше не нужны.

## Инкрементальная сборка

`vite build` копирует статику (данные города, `models/`, звуки, текстуры — ~25 МБ) в `dist/` **только при изменениях**: файл копируется, если его нет в `dist/`, отличается размер или источник новее копии. Сборка после правок только в `src/` не перекапирует модели; в конце печатается `city-data: N changed static file(s) copied`.

## Предметы без экрана: `tools/shot-items.mjs`

Сам поднимает сервер страницы (порт 8767, `PORT=`), входит в тренировку с ботами в странице (без внешнего сервера, ботов 0), ждёт загрузки GLB-предметов, ставит игрока рядом с одним предметом каждого вида (ящик, аптечка, граната) и бросает гранату; снимки PNG — в `.claude/shots-items` (`OUT=`), ошибки консоли печатает. Браузер запускается через [tools/browser.js](../tools/browser.js) (GPU, если доступен). Снимки делаются через CDP `Page.captureScreenshot`: обычный `page.screenshot` под SwiftShader голодает на ожидании шрифтов. Телепорт в бою делается сразу и в локальной игре (`MP.ws.game.players`), иначе сервер откатывает его сообщением `correct`.

```bash
node tools/shot-items.mjs
```

## Сборка моделей предметов: `tools/items.mjs`

Из распакованных архивов Sketchfab (подпапки `ammo-soviet/`, `nade-m67/`, `med-tedium/`, внутри `x/scene.gltf`; источник по умолчанию — `.claude/items-src`, переопределяется `SRC=`) собирает `models/item_{ammo,nade,med}.glb`: запекание мировых матриц, слияние по материалу, центровка дном в y=0, нормировка габарита в метры, WebP-текстуры и meshopt (`COMPRESS=0` — без сжатия). Авторы и лицензии (CC-BY-4.0) — в [models/README.md](../models/README.md). Зависимости ставятся `npm i --no-save`, в репозиторий не входят.

## Сжатие текстур моделей: `tools/shrink-models.mjs`

Геометрия моделей уже упакована meshopt; оставшийся вес — текстуры (у `fp_ak47.glb` четыре изображения 2048×2048). Инструмент перекодирует встроенные текстуры в WebP (`Q=80`, по умолчанию без потери разрешения; `MAX=1024` дополнительно уменьшает сторону) и перезаписывает GLB только если файл стал заметно меньше; изображение заменяется лишь при выигрыше >20 %. Анимации, скины и материалы сохраняются (gltf-transform round-trip).

```bash
npm i --no-save @gltf-transform/core@4 @gltf-transform/extensions@4 @gltf-transform/functions@4 sharp meshoptimizer
node tools/shrink-models.mjs              # все models/*.glb
node tools/shrink-models.mjs fp_ak47.glb  # только указанные
```

После сжатия проверьте вид оружия в бою без экрана: `node tools/shot-items.mjs` (снимки с автоматом в руках).

## Координаты LKS-92: `tools/lks92.js`

Данные LGIA лежат в латвийской сетке LKS-92 TM (EPSG:3059), высоты — в системе LAS-2000,5 (над уровнем моря). Перевод туда и обратно точен до миллиметра:

```bash
node tools/lks92.js city -1487 1263
```

Есть и подкоманды `ll LAT LON`, `lks E N`. Как модуль: `const { cityToLKS, lksToCity, toLKS, fromLKS } = require('./tools/lks92.js')`. Центр координат города (0, 0) — это E 658875, N 195919.

## Источники

### OpenStreetMap
- **OSM API** — выгрузка всего в небольшом прямоугольнике (до 0,25 квадратного градуса и 50 000 точек):
  ```
  https://api.openstreetmap.org/api/0.6/map?bbox=W,S,E,N
  ```
  Так собраны `parks.js` и `schools.js` и прочитаны теги развязки у моста Единства (`oneway`, `lanes`, `maxheight` → [src/world/street-tags.js](../src/world/street-tags.js)). Из облака работает.
  Весь город целиком — 42 квадрата 0,03° × 0,02° (около 95 МБ, 2–9 МБ на квадрат, ни один не упёрся в лимит точек); цикл выгрузки — в README, «Как обновить parking.js». Так собран `parking.js`.
- **Nominatim** (поиск объектов по названию и типу) работает. Нужен свой `User-Agent` и не чаще запроса в секунду.
- **Overpass** из облачного окружения не отвечает: `overpass-api.de` рвёт соединение, зеркала `overpass.kumi.systems`, `overpass.private.coffee` и `maps.mail.ru` не отвечают по таймауту. Вместо него — OSM API по прямоугольникам.

### Mapillary — уличные фото для фасадов
- API v4: `https://graph.mapillary.com`. Фото по лицензии CC BY-SA 4.0. Используем их как образец, а не как текстуры.
- **Ключ у каждого аккаунта свой**, в репозиторий не кладётся. У владельца он сохранён как сетевой секрет облачного окружения для хоста `graph.mapillary.com`: прокси сам подставляет заголовок `Authorization`. Подходят и `OAuth <ключ>`, и `Bearer <ключ>`. Со своим ключом (`MLY|…`) его можно передать заголовком или параметром `access_token`.
- Поиск снимков в прямоугольнике:
  ```
  /images?bbox=W,S,E,N&fields=id,captured_at,compass_angle,computed_geometry,is_pano,thumb_2048_url&limit=2000
  ```
  Прямоугольник держите маленьким, около 0,004° × 0,004°. На больших API отвечает 502 или пусто.
- Покрытие (ноябрь 2026):

  | Место | Снимков | Годы | Панорамы |
  |---|---|---|---|
  | Центр крепости | ~3 000 | 2019–2025, больше всего 2020 и 2024 | нет |
  | Rīgas iela | ~2 100 | 2016, 2019–2025 | 53 |
  | Церковная горка | ~1 500 | 2019–2021 | нет |
  | Химия (Ķīmiķu ciemats), жилая часть | ~2 800 | 2014–2025, больше всего 2020–2022 | немного |
  | Озеро Губище и Aizpilsētas parks | ~4 100 | 2014–2025, больше всего 2020 | немного |

- **Фасады района разом** — [tools/facades.js](../tools/facades.js). Инструмент берёт жилые дома `citydata.js` внутри границы района (relation OSM) и подбирает на каждую длинную сторону снимок, который смотрит на неё спереди с 12–70 м. Панорамы обрезаются до нужной четверти. Снимки раскладываются на контактные листы 3 × 3 с адресом и стороной света:
  ```bash
  node tools/facades.js citydata.js out --relation 5464161 osm-parking/*.osm
  ```
  Квадраты OSM — те же, что для `parking.js`. Около трети кадров смотрят вдоль улицы, а не на дом; выводы по дому делаются по всем его кадрам и по соседям.

### LGIA — Латвийское агентство геопространственной информации
Открытые данные публикуются через [data.gov.lv](https://data.gov.lv) (поставщик в каталоге — «ĢEOLatvija.lv»). Каталог отвечает из облака, поиск:

```
https://data.gov.lv/dati/api/3/action/package_search?q=…
```

- **Модель рельефа, сетка 20 м** (CC0) — уже используется: [terrain.js](../terrain.js), собирается `tools/terrain.js`.
- **Облака точек лазерной съёмки** (набор «Digitālā augstuma modeļa pamatdati», CC0, без регистрации). Съёмка 2013–2019.
  - Тайлы LAS по 1 × 1 км, около 250 МБ каждый. Список всех 65 917 ссылок:
    ```
    https://s3.storage.pub.lvdc.gov.lv/lgia-opendata/las/LGIA_OpenData_las_saites.txt
    ```
    Адрес одного тайла:
    ```
    https://s3.storage.pub.lvdc.gov.lv/lgia-opendata/las/<лист>/<имя>.las
    ```
  - Имя тайла — `<лист>-<RC>-<rc>`. Лист — квадрат 25 × 25 км. `RC` — квадрат 5 × 5 км внутри листа, `rc` — квадрат 1 × 1 км внутри него. R и r — ряд от южного края (1–5), C и c — столбец от западного (1–5). Город (E 652–666 км, N 189–203 км) лежит на листах **2443** (E 650–675, N 175–200 км) и **3421** (E 650–675, N 200–225 км). Центр — `2443-52-14`.
  - Формат: LAS 1.2, точки формата 1 (по 28 байт). Координаты в LKS-92, плотность в центре около 5,8 точки на м².
  - Классы: 2 — земля, 3/4/5 — низкая, средняя и высокая растительность, **6 — здания**. Класс 14 у воды встречается, но его смысл не проверен.
  - В записи точки: X, Y, Z (int32 со смещений 0, 4, 8), интенсивность (uint16, смещение 12), байт 14 — номер отражения (биты 0–2) и число отражений импульса (биты 3–5), класс — байт 15 (биты 0–4).
  - В классы растительности 4/5 попадают и края крыш, балконы, выступы стен: они яркие (интенсивность от 60) и почти всегда — единственное отражение. Как их отличить от деревьев и хвою от лиственных — раздел README «Деревья по лидару».
  - Границы тайла читаются без скачивания: заголовок `Range: bytes=0-226`, в нём min/max X, Y, Z со смещения 179.
  - Сервер иногда обрывает долгую закачку (`curl: (56) Recv failure: Connection reset by peer`). `tools/lidar.js` в таком случае продолжает тайл с того же байта (`curl -r <байт>-`) и сверяет число прочитанных точек с заголовком.
  - Используется: высоты карнизов и коньков и формы крыш зданий (`tools/lidar.js` → `lidar.js`) и деревья вне лесов (`tools/lidar.js --trees` → `lidar-trees.js`), разделы README «Высоты и крыши зданий по лидару» и «Деревья по лидару». Ещё не используется, но доступно: рельеф точнее 20 м (класс 2).
  - Дата съёмки — во времени GPS у точек (adjusted standard GPS time): центр города снят 13 мая 2017 года.
- **Ортофото 25 см** (7-й цикл, 2019–2021, WMS) — CC BY 4.0, бесплатно, но по регистрации на `e-pieteikumi.lgia.gov.lv`. Даёт цвет и материал крыш, дворы. Пока не подключено.
- **Ортофото городов 1997–2002** (CC0) — облик до перестроек.

## Механизмы движка, появившиеся недавно

- **Мелкая поправка рельефа** (`PATCHES` в [src/world/terrain.js](../src/world/terrain.js)). Это сетка 1 м поверх сетки 20 м в небольшой рамке; её добавляют к высотам и шейдеры, и JS. Для мест, которые сетка 20 м не передаёт. Областей не больше трёх (`NPATCH`, `setPatch`), они не должны пересекаться; шаг может быть и 0,5 м. Примеры — [src/world/underpass.js](../src/world/underpass.js) и [src/world/underpass-rail.js](../src/world/underpass-rail.js), разделы README «Daugavas iela под мостом Единства» и «Рельеф».
- **Улицы на дамбах** (`terrainDams`) — ровный гребень дамбы под улицей.
- **Теги OSM по отдельным путям** ([src/world/street-tags.js](../src/world/street-tags.js)): полосы, загородные участки, односторонние съезды в одну полосу.
