# Итерация цикла улучшений DPILS

Ты — одна итерация автономного цикла улучшений проекта «Даугавпилс 3D». Репозиторий — текущий каталог (cwd); работай от его свежего `origin/main`. Твоя работа: взять одну задачу из бэклога и довести её до смерженного PR. Вопросов владельцу не задавай: всё решают правила ниже. Цикл улучшает то, что уже есть, а не строит новое.

## Обязательно прочитай перед началом

1. `AGENTS.md` и `CLAUDE.md` — изоляция и конвейер (обязательны к исполнению).
2. `docs/autoloop.md` — как устроен цикл.
3. `docs/improvement-backlog.md` — очередь задач и журнал «Сделано».
4. Таблицу «Кто чем занят» в `docs/tools-and-sources.md` — не занимай файлы, которые правят параллельные агенты.

## Выбор задачи

- Возьми верхнюю незавершённую задачу из раздела «Очередь» (P1 раньше P2, P2 раньше P3). Пропускай задачи, помеченные «blocked», и задачи, чьи файлы заняты в таблице «Кто чем занят».
- Если очередь пуста, всё blocked или всё занято — проведи **аудит** (см. ниже).
- Если после последнего аудита в «Сделано» накопилось 8 и более задач — тоже проведи аудит.
- Одна итерация = одна задача = один небольшой PR. Не объединяй несколько задач. Не добавляй новые районы и возможности, которых нет в бэклоге.

## Аудит (когда задач нет)

1. В своём worktree подними тёплый браузер на своём порту: `$env:WARM_PORT='8779'; node tools/warm.mjs` (дождись «warm: ready»). Кадры снимай с `$env:WARM='http://127.0.0.1:8779'`.
2. Сними кадры `node tools/shots.js` (он сам пойдёт через тёплый): площадь Единства (−1440,1300 → −1487,1263), Rīgas iela, крепость, Химия (Ķīmiķu ciemats), Стропы (больница), университет, вокзал — день (время 0) и ночь (время 2). Рассмотри кадры глазами, собери ошибки консоли (shots.js печатает их сам).
3. Измерь производительность через `POST /__warm/eval`: `renderer.info.render` (calls, triangles), время кадра; сравни с прошлым аудитом, если он отмечен в бэклоге.
4. Впиши в «Очередь» 5–12 конкретных задач: место и координаты, что не так, примерное направление правки, критерий приёмки (измеримый: нет ошибок консоли, fps не ниже, соответствует фото-образцу). Приоритеты P1–P3. Не выдумывай проблемы, которых не видно в кадрах и замерах. Кандидатов из бэклога подтверди или отклони по кадрам и замерам.
5. Обнови отметку «Последний аудит» (дата, краткие цифры: calls/triangles/fps по местам).
6. Проведи обновление бэклога через обычный конвейер как docs-PR. Тёплый браузер останови (только свой процесс).

## Выполнение задачи

1. `git fetch origin`. Создай свой worktree от свежего `origin/main`: ветка `chatbox/loop-<тема>-<HHmm>` (префикс `chatbox/loop-` зарезервирован за циклом), путь `.claude/worktrees/loop-<тема>-<HHmm>`; `node_modules` — junction из общего каталога. Впиши свою строку в «Кто чем занят» (только свою).
2. Реализуй задачу минимальным диффом, не задевая лишнего.
3. Проверки: `npm run check`, `npm test`, `npm run build`. Новый runtime-файл (текстура, модель, звук, данные) — в список `STATIC` в `vite.config.mjs`: продакшен VPS отдаёт только `dist/`. Визуальная проверка изменённого места: тёплый браузер + `tools/shots.js` на своём порту либо свой сервер на свободном порту (8766 и 8771 могут быть заняты соседями). Ошибок консоли быть не должно; для задач производительности — замеры до и после.
4. В том же PR обнови `docs/improvement-backlog.md`: задачу — в «Сделано» (номер PR, одна строка результата), новые замеченные проблемы — в очередь. Заметное изменение опиши в `README.md`.
5. Убери свою строку из «Кто чем занят». Коммить с трейлером `Co-authored-by: Chatbox <chatbox@chatboxai.com>`, запушь ветку, `gh pr create --base main --fill`, `gh pr merge --auto --merge --delete-branch` (если GitHub отвечает «in clean status» — мержи сразу: `gh pr merge --merge --delete-branch`). После мержа обнови VPS — единственный продакшен: `ssh kicad-vps "bash -lc 'source ~/.nvm/nvm.sh; cd ~/dpils && git pull && npm run build && pm2 restart dpils'"`.
6. CI красный или конфликт с `main` — влей `origin/main`, исправь, заново прогони проверки, запушь. Если довести до зелёного не получается — закрой PR (`gh pr close`), пометь задачу в бэклоге «blocked: причина», заверши итерацию.
7. Уборка: останови свои процессы (фильтр по CommandLine, без mass-kill), удали junction (`cmd /c rmdir "<wt>\node_modules"`), затем `git worktree remove <wt>` и `git worktree prune`.

## Строго запрещено

force-push; коммиты прямо в `main`; `--no-verify` и пропуск проверок; правки в общем каталоге и чужих worktree; удаление чужих файлов; обновление локального `main` в общем каталоге; ожидание деплоя Pages (продакшен — VPS, обновляется сразу после мержа) и открытие продакшен-сайта после мержа.

## Финальное сообщение

Одна строка: «merged PR #N: <задача>», либо «audit: добавлено N задач, PR #N», либо «blocked: <причина>».
