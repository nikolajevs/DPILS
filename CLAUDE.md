## Параллельные агенты: изоляция обязательна

Общий каталог `C:/Users/igors/Desktop/DPILS` — чужая рабочая зона: там может лежать незакоммиченная работа соседа (однажды `checkout` + `reset` в общем каталоге уже стёрли её). Полный протокол — в [AGENTS.md](AGENTS.md), главное:

- работай в **своём worktree** от `origin/main`: `git worktree add -b claude/<branch> .claude/worktrees/<branch> origin/main`, `node_modules` — junction из общего каталога;
- в общем каталоге и чужих worktree запрещены `checkout`/`switch`/`reset`/`restore`/`stash`/`clean`, правки и удаление чужих файлов, mass-kill процессов; локальный `main` там не обновляй — только `fetch`;
- коммить рано и часто: несохранённая работа не переживает чужие ошибки;
- тестовые серверы — на своих портах (8766 может быть занят соседом), временные файлы — в своём sandbox, не в `tools/`;
- после мержа убери свой worktree (сначала junction `node_modules`, потом `git worktree remove`).

## Задача доводится до сайта без вопросов

**Продакшен — только VPS (объявление от 19.11.2026).** Владелец проверяет только готовый результат на сайте: https://dvinsk.lat (VPS `kicad-vps`, pm2 `dpils` с `STATIC=dist` отдаёт собранный `dist/`). GitHub Pages больше не используется — ни для деплоя, ни для проверок. Поэтому коммит, пуш, PR, мерж и обновление VPS агент делает сам, без подтверждения:

1. Работать в своей ветке (не в `main`) и в своём worktree (см. «Параллельные агенты» выше и [AGENTS.md](AGENTS.md)), созданным от свежего `origin/main`.
2. Проверить локально:
   - `npm run check` и `npm run build`;
   - в браузере: сервер `dpils` из `.claude/launch.json` (http://localhost:8766/), нет ошибок в консоли, изменённое место выглядит как задумано. Без экрана (облачная сессия) — рендер видов `tools/shots.js`, он же выводит ошибки консоли.
   - новый runtime-файл (текстура, модель, звук, данные) добавлен в список `STATIC` в `vite.config.mjs`: VPS отдаёт только `dist/`, файл вне списка даст 404.
3. Описать сделанное в README.md, если это новая часть города или заметное изменение.
4. Закоммитить, запушить ветку, открыть PR в `main`.
5. Включить авто-мерж обычным merge-коммитом: `gh pr merge <номер> --auto --merge --delete-branch` (в приложении Claude — его авто-мерж PR с методом `merge`). В репозитории авто-мерж разрешён: GitHub сам смержит PR, когда CI станет зелёным, сидеть и ждать CI не нужно. Если GitHub отвечает, что PR «in clean status», значит CI уже зелёный и мержить можно сразу: `gh pr merge <номер> --merge`.
6. Если CI красный, исправить и запушить снова: красный PR GitHub не смержит. Если есть конфликт с `main`, влить `main` в ветку, разрешить конфликт, проверить ещё раз.
7. После мержа агент сам обновляет VPS: `ssh kicad-vps "bash -lc 'source ~/.nvm/nvm.sh; cd ~/dpils && git pull && npm run build && pm2 restart dpils'"` (`npm ci` — если менялись зависимости; установка и обновление — в [server/deploy/README.md](server/deploy/README.md)). Живые проверки на сайте делает владелец; агент не открывает продакшен-сайт и не гоняет по нему браузер: работа заканчивается на зелёном CI, смерженном PR и обновлённом VPS.
8. В итоговом ответе дать ссылку https://dvinsk.lat и сказать, где смотреть: улицу, место или координаты.

Нельзя: force-push в `main`, коммиты прямо в `main` мимо PR, пропуск хуков и проверок.
