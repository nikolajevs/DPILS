Город, по которому можно пройтись пешком или пролететь: [index.html](index.html) (код — в [src/](src/), см. «Разработка» ниже), данные города [citydata.js](citydata.js), транспорта [transit.js](transit.js), крепости [fortress.js](fortress.js), рельефа [terrain.js](terrain.js), школ [schools.js](schools.js) и парков [parks.js](parks.js).

- **Расписание транспорта** — официальный GTFS «Daugavpils satiksme» ([satiksme.daugavpils.lv/saraksti/GTFS.zip](https://satiksme.daugavpils.lv/saraksti/GTFS.zip)): трамвайные и автобусные маршруты, остановки и время каждого рейса. Сборка — `tools/trains.js` → [trains.js](trains.js).
- **Междугородние и пригородные автобусы** — GTFS VSIA Autotransporta direkcija (все региональные автобусы Латвии, [data.gov.lv](https://data.gov.lv/dati/lv/dataset/atd-gtfs)). Сайт atd.lv из облака не отвечает, поэтому взята копия из каталога Mobility Database. Сборка — `tools/intercity.js` → [intercity.js](intercity.js).

Фасады и крыши нарисованы процедурно, это не фотографии.

## Дом Единства и гостиница «Латгола»

Два здания на площади Единства построены вручную, а не общим генератором фасадов (`lmUnityHouse` в [src/landmarks/unity-house.js](src/landmarks/unity-house.js) и `lmLatgola` в [src/landmarks/latgola.js](src/landmarks/latgola.js)). Размеры сняты с фотографий и сверены с контуром кадастра: ширина портика 29,4 м, карниз ≈18 м, шесть колонн ≈12 м.

- **Дом Единства** (Vienības nams, арх. Вернер Витандс, 1936–1937): портик с шестью коринфскими колоннами и лоджией, пилоны с рустом и надписью «VIENĪBAS NAMS», театральные витрины, сценическая коробка с флагом, крылья с магазинами на Rīgas iela и Ģimnāzijas iela, вход в концертный зал, терраса юго-западного крыла, двор.
- **Park Hotel Latgola** (бывшая гостиница «Latvija», 1975–1985, реконструкция 2000-х): волнообразная кровля над остеклённым верхним этажом, рамка двухсветного окна, стеклянный объём лестниц, часы на крыше (показывают время города), вывески HOTEL и PLAZA; рядом жёлтый торговый центр Latgola.
- **Клумбы**: ковровая клумба перед портиком (шалфей, цинерария, бархатцы, бегонии) с двумя пятишаровыми канделябрами и скамейками, клумба у входа в концертный зал.
- **Сама площадь** (`lmSquare`; план — пешеходная зона OSM, way 818019765, мощение — по снимку сверху). В полукруге, врезанном в сквер, круглый рондель с красно-коричневым диском. От него по юго-западной половине площади расходятся кольца из тёмной брусчатки, остальная часть разбита сеткой квадратов. Вдоль стоянки у гостиницы ряд круглых бетонных вазонов с цветами, вдоль трамвайных путей ряд вазонов поменьше. Высокие фонари, на двух цилиндрические гирлянды. Со стороны сквера группа высоких елей. Перед гостиницей асфальтовая стоянка по контуру OSM с разметкой и машинами в косых местах.

Источники фото: Wikimedia Commons (категории *Latgola Hotel*, *Vienības laukums (Daugavpils)*, файл *Vienības nams.jpg* в латышской Википедии), [visitdaugavpils.lv](https://www.visitdaugavpils.lv/en/?p=3245) (в том числе снимки 1937 года), [celotajs.lv](https://www.celotajs.lv/en/e/vienibasnams), [militaryheritagetourism.info](https://militaryheritagetourism.info/lt/military/sites/view/891), [neighborhood.lv](https://neighborhood.lv/en/real-estate/daugavpils-architectural-guide/); проект реставрации фасада Дома Единства — Daugavpils pilsētas dome, 2010.

## Даугавпилсская региональная больница в Стропах

Кампус по адресу Vasarnīcu iela 20 (`lmHospital` в [src/landmarks/hospital.js](src/landmarks/hospital.js)) сверён по [плану LGIA 1:2 000 и ортофотоснимку 7-го цикла](https://kartes.lgia.gov.lv/) и фотографиям больницы. Исправлены привязка и ориентация 12-этажной башни, положение отдельного корпуса лучевой терапии, юго-западный входной портал с двумя постами скорой и основная парковка к северо-западу от главного корпуса. Фасады башни, открытые торцевые галереи, низкие крылья, навес, пандус, подъездной круг и парковочная разметка собраны отдельными деталями; остальная планировка благоустройства показана в масштабе генплана.

Отдельно смоделирован существующий блок лучевой терапии и низкий новый корпус, соединённый с ним. Новый блок отражает расширение, строительство которого город описывал в 2025 году; публикация 2026 года указывала план завершить объединение корпусов к 30 июня. Детальный рабочий проект фасадов и благоустройства в открытых источниках не найден, поэтому объёмы и посадка нового корпуса показаны как приближённая 3D-реконструкция. Основной корпус открыт в Стропах в 1986 году; его высота и этажность сверены по городским данным и фотографиям больницы.

Источники: [фото главного фасада больницы](https://slimnica.daugavpils.lv/drs-uzdevums-pasreizejos-apstaklos-nodrosinat-pakalpojumus-pilna-apjoma/), [фото комплекса от Министерства здравоохранения](https://www.vm.gov.lv/lv/jaunums/abu-meri-daugavpils-regionalas-slimnicas-darbiba-ir-stabila-attistibai-japarskata-parvaldibas-modelis), [история открытия 12-этажного корпуса в 1986 году](https://www.daugavpils.lv/pilseta/par-daugavpili/pilsetas-zinas/daugavpils-regionalajai-slimnicai-40-gadi), [ход строительства лучевого блока](https://www.daugavpils.lv/pilseta/par-daugavpili/pilsetas-zinas/sparu-svetki-toposaja-sia-daugavpils-regionala-slimnica-staru-terapijas-bloka), [изменения движения и срок объединения корпусов](https://www.daugavpils.lv/pilseta/par-daugavpili/pilsetas-zinas/pie-daugavpils-regionalas-slimnicas-staru-terapijas-bloka-mainisies-satiksmes-kustibas-organizacija). Размеры и невидимые на снимках стороны реконструированы приблизительно.

## Даугавпилсский университет

Три корпуса университета тоже построены вручную (`lmDUMain`, `lmDUParades`, `lmDULab` в [src/landmarks/university.js](src/landmarks/university.js)). Контуры взяты из кадастра, детали сняты с фотографий.

- **Старый корпус**, Vienības iela 13 (арх. Алексей Богаченков, 1952–1956; строился для обкома, достроен для пединститута). Фасад на сквер с фонтаном 76,7 м: глухие угловые пилоны по 8,4 м, одиннадцать осей по 5,45 м между десятью пилястрами высотой в четыре этажа, с капителями на уровне верхних окон. Окна парные, этажи через 3,95 м, в трёх средних осях дубовые двери в каменных обрамлениях. Во фризе высотой 3 м бронзовые буквы DAUGAVPILS UNIVERSITĀTE, карниз на модульонах на отметке 21,5 м, в центре аттика картуш с флагом. Охристая штукатурка рустована под квадры, цоколь гранитный. Сзади три крыла (план «Ш»). Перед фасадом гранитная лестница, ряд туй и бюст Райниса (1967).
- **Новый корпус**, Parādes iela 1 (1980-е, у Дубровинского парка). План восстановлен по кадастру и схемам этажей с информационного стенда университета. Пятиэтажные коридорные крылья (одно повёрнуто на 45°) облицованы бежевой керамической плиткой, крыша низкая, шиферная. Лестничные башни из красного кирпича. Внутри угла двухэтажные кирпичные корпуса: вестибюль, библиотека на колоннаде, концертный зал, спортзал. У них ленточные окна в белых рамах с белыми подоконными поясами и кирпичная решётка. Портик входа с двухстрочной стальной надписью DAUGAVPILS UNIVERSITĀTE. На внешнем углу одноэтажный блок амфитеатральных аудиторий, на крыше спутниковая антенна.
- **Лабораторный корпус**, Parādes iela 1A (SIA «Nams», 2014; площадь застройки 3568 м², два этажа). Белые трёхслойные железобетонные панели с высоким ленточным окном, сверху витраж Schüco FW50+ с тёмными горизонтальными ламелями на южных и западных фасадах. Белый входной объём с консолью над дверями, стеклянный атриум, техника на крыше, застеклённый переход к новому корпусу.

Источники фото и сведений: Wikimedia Commons (категория *Daugavpils University*: Igors Jefimovs 2011, Dāvis Kļaviņš 2010, снимки panoramio), статьи о Даугавпилсском университете в латышской и русской Википедии, [du.lv](https://du.lv/en/about-us/environmental-accessibility/macibu-korpuss-parades-iela-1/) (схемы этажей корпуса на Parādes iela 1), [archidea.lv](https://archidea.lv/lv/portfolio/portfolio/archidea/architecture/71/) («Gada labākā būve Latvijā 2014»: описание и фото лабораторного корпуса).

## Бывший кинотеатр «Ренесанс»

Кинотеатр «Oktobris» (1978), позже «Renesanse», Vienības iela 30; с 2022 года в нём Daugavpils Inovāciju centrs (`lmRenesanse` в [src/landmarks/renesanse.js](src/landmarks/renesanse.js)). В OpenStreetMap здание нарисовано частями-отношениями (building:part), которые сборка данных не скачивала. Поэтому в `citydata.js` его не было: от общего контура остался только центр (место «Daugavpils inovāciju centrs»). Ещё уцелела единственная часть-линия: полоса 27 × 2,5 м перед зданием, то есть козырёк над фойе. В городе она стояла отдельным «домиком», теперь убрана. План привязан к этому козырьку и поставлен перпендикулярно Vienības iela. Модель сама добавляет свой контур для столкновений, карты и посадки деревьев. Точный план по фото не восстановить, поэтому глубина корпусов приблизительная.

Здание целиком из жёлтого кирпича:

- большой зал на западе со скруглённым углом и вентиляционной решёткой;
- фойе между залами: лента верхних окон над толстым козырьком со скруглённым краем, под ним остекление в чёрных рамах с матовым орнаментом и светодиодная вывеска Инновационного центра;
- более высокий восточный объём со скруглённым фасадом;
- малый зал и служебный корпус позади;
- гранитная терраса, лестница и пандус со стальными перилами.

Запрос [tools/queries/q_rel.txt](tools/queries/q_rel.txt) теперь скачивает и отношения building:part, а `tools/process.js` превращает их в здания. Данные появятся после следующей пересборки `citydata.js`. Участок кинотеатра зарезервирован за ручной моделью.

Источники: Wikimedia Commons (категория *Cinemas in Daugavpils*: «Daugavpils oktobris cinema», «Кинотеатр Ренесанс — panoramio»), [lsm.lv](https://www.lsm.lv/raksts/dzive--stils/tehnologijas-un-zinatne/daugavpili-atvertais-inovaciju-centrs-vilina-gan-bernus-gan-pieaugusos.a486412/) (фото 2022 года), [visitdaugavpils.lv](https://www.visitdaugavpils.lv/en/turisma-objekts/daugavpils-innovation-centre/).

## Динабургская крепость: валы, рвы и ворота

Земляные укрепления строятся из OpenStreetMap ([fortress.js](fortress.js), собирается `tools/fortress.js`). В OSM подпорные стены и насыпи рисуются так, что низкая сторона справа от линии: замкнутая подпорная стена — это контур поднятого укрепления (бастион, люнет, контргард), главный эскарп — полоса между двумя линиями. По ним строится рельеф с шагом 2 м:

- **рвы** — дно на 4 м ниже города вдоль канав, нарисованных в OSM по дну рвов, и по полигонам рвов; в мокрых рвах — заболоченное дно и вода в канавах;
- **эскарп** — облицовка из бутового камня (гранитные валуны) высотой 1,6 м над уровнем города, за ней берма под дерновым покрытием, затем откос до гребня бруствера 5,2 м и терреплейн 4,2 м;
- **дороги** держат свой уровень, к валам и рвам от них идут земляные откосы; дорожки ложатся на рельеф;
- по валам и во рвах можно ходить: высота шага берётся из того же рельефа, облицовка рвов не пускает спрыгнуть вниз.

Ворота смоделированы по фотографиям (Wikimedia Commons, visitdaugavpils.lv, militaryheritagetourism.info):

- **Николаевские** — внешний фасад из красного кирпича со стрельчатой аркой в гранитном обрамлении, боковыми стрельчатыми нишами с решётками, бойницами, алебардами, фризом с надписью «НИКОЛАЕВСКІЯ», аркатурой и аттиком с двуглавым орлом; внутренний фасад — розовая штукатурка с белыми деталями, тюдоровская арка с открытыми дубовыми створками, боковые арочные ниши с окнами; деревянный мост на козлах через ров с кирпичными столбами и орлами у контрэскарпа.
- **Михайловские** — гранитные порталы в египетском стиле с карнизом-выкружкой, крылатым диском и ликторскими секирами; со стороны крепости — изогнутые подпорные стены из песчаника, по верху которых спускается вал.
- **Александровские** — кирпичные порталы с полуциркульной аркой в гранитном обрамлении и фризом-меандром.
- **Потерны** — малые кирпичные проходы сквозь вал.

- **Константиновские** (`fortKonstantin` в [src/fortress/gates.js](src/fortress/gates.js), геометрия и земля — [src/fortress/konstantin.js](src/fortress/konstantin.js)). Сами ворота снесены: на карте крепости visitdaugavpils.lv они подписаны «Konstantīna vārti (nojaukti)». Осталась прорезь в валу в северо-западном углу крепости, по ней Lidotāju iela выходит из крепости. Остатки смоделированы по фото Mapillary 2020 года и контурам OSM: двум постройкам «Konstantīna vārti» (way 733209162, 733209163) и двум изогнутым городским стенам (1523618446, 1523618447). Вдоль проезда шириной 6,9 м идут две подпорные стены по 22 м: внизу оштукатуренный бут, сверху красный кирпич с осыпавшимся верхом. Земля вала подходит под самый их верх. У наружной и внутренней граней вала стоят кирпичные торцевые блоки с пилястрами. Со стороны города стены расходятся изогнутыми крыльями. Их верх идёт чуть выше земли, которую они держат: с юго-западной стороны он опускается вместе с внутренним откосом вала, с северо-восточной, где вал шире, остаётся высоким. Штукатурка серая, в потёках, местами отвалилась до бута (своя текстура, `fortTex(6)`). Раньше на этом месте стояли два жёлтых домика с окнами: так город рисовал постройки из OSM, теперь они убраны.
  Сетка рельефа крепости с шагом 2 м идёт под 45° к воротам, и вертикальную стену с землёй вровень с верхом на ней не построить. Поэтому вокруг ворот сетка оставляет свои клетки пустыми, а рельеф там рисует отдельная мелкая сетка (`fortFine` в [src/fortress/ground.js](src/fortress/ground.js)) с шагом 0,4 м, повёрнутая вдоль проезда. По краю зоны она плавно сходит на высоты общей сетки.

Здания крепости по фотографиям (категории Wikimedia Commons *Artillery arsenal (Daugavpils fortress)* и *Engineering Arsenal (Daugavpils Fortress)*) и контурам OSM:

- **Артиллерийский арсенал** (с 2013 года — Центр Марка Ротко): П-образное здание 119 × 42 м, открытое во двор. Первый этаж рустован, группы из трёх высоких окон между белыми пилястрами, фриз с сухариками; над каждой группой — люнет в широком белом архивольте с замковым камнем; белый карниз, вальмовая кровля из фальцевой стали с круглыми вентиляционными шапками. ## Rīgas iela

Пешеходная Rīgas iela (около 850 м от Vienības laukums до вокзала) прорабатывается по кварталам (`lmRigas`, `lmStreetHouse` в [src/landmarks/rigas.js](src/landmarks/rigas.js)).

- **Мостовая** по всей пешеходной части: красная бетонная брусчатка, по оси гранитная полоса, вдоль домов гранитные плиты (по фото 2010-х).
- **Генератор исторических домов.** Дом описывается одной строкой в `RIG_HOUSES`: точка внутри кадастрового контура, этажи и высоты, цвет штукатурки или красный кирпич, число осей, первый этаж (витрины, арочные окна, двери, проезд с воротами), тип окон (прямые, лучковые, полуциркульные). Дальше идут декор и крыша:
  - наличники, сандрики и фронтончики над окнами, филёнки под окнами;
  - руст, междуэтажный пояс, угловые квадры, лопатки;
  - карниз на кронштейнах или с сухариками, аттик с фронтоном, балконы с коваными решётками;
  - металлическая крыша со скатом к улице и трубами.

  Фасад по Rīgas iela собирается полностью. Стены на другие улицы получают тот же фасад, но с окнами вместо витрин. Дворовые стены получают простые окна, брандмауэры остаются глухими. Столкновения дают кадастровые контуры.
- **Готово:** первые два квартала от площади Единства по южной стороне (9 домов). Этажность и контуры взяты из кадастра. Отдельных фото этих домов в открытых источниках нет, поэтому фасады собраны в типичных для Rīgas iela формах по общим снимкам улицы (Wikimedia Commons, категория *Rīgas iela (Daugavpils)*). Уточняются по фото конкретных домов.

## Железнодорожный вокзал

Вокзал Даугавпилса (Stacijas iela 44, 1951), модель `lmStation` в [src/landmarks/station.js](src/landmarks/station.js). План — контур OpenStreetMap (way 115889829), облик — фото из категории Wikimedia Commons *Daugavpils Railway Station*.

Здания в `citydata.js` не было. В OSM внутри контура нарисован навес над входом как часть здания (building:part=roof), и сборка данных подставила эту часть вместо всего вокзала, так что остался навес 11 × 3 м. Теперь `tools/process.js` отдаёт контур частям, только если они покрывают больше половины его площади, а части-навесы рисует как навесы на столбах. Подействует при следующей пересборке; до неё навес отброшен вручную, а модель сама регистрирует свой контур.

- Охристая штукатурка на красно-коричневом цоколе.
- Посередине объём через всё здание под двускатной крышей с фронтонами с обеих сторон.
- К площади: портик с двумя квадратными столбами, к нему 17 ступеней с тремя поручнями и боковой площадкой. Над портиком глубокая полуциркульная ниша с архивольтом и замковым камнем, она врезается во фронтон; в нише крылатое колесо, эмблема железной дороги. В боковых пилонах ряды узких окон.
- К перронам: заглублённая ниша с остеклёнными дверями и большим окном, бронзовые буквы DAUGAVPILS, год «1951» в люнете фронтона.
- По сторонам залы ожидания: по четыре высоких окна между пилястрами на обоих фасадах, слуховые окна на крышах.
- По краям двухэтажные корпуса под вальмовыми крышами с трубами, окна в четыре оси, ромбики между окнами второго этажа, решётки подвальных окон в цоколе.
- Низкий асфальтовый перрон по контуру OSM с белой кромкой.

## Поезда и станция

Через Даугавпилс по расписанию Vivi в сутки идут 16 поездов: Рига – Даугавпилс и обратно, а также Рига – Краслава и Рига – Индра. Модуль — [src/transit/trains.js](src/transit/trains.js), данные — [trains.js](trains.js).

- **Рейс** хранится как подход от предыдущей остановки (её время и расстояние по линии), стоянка в Даугавпилсе и отход до следующей. На карте лежит только сама станция. Две линии от неё до края карты — на северо-запад к Риге и на восток к Краславе — проложены по нарисованным путям тем же сопоставлением, что трамваи (`route-match.js`), и соединены в точке остановки поезда из OSM.
- **Ход.** Поезд разгоняется и тормозит не круче 0,5 м/с² и встаёт серединой у точки остановки. Конечный поезд стоит у перрона до ближайшего обратного рейса (до 4 часов, в том числе ночью). Один и тот же поезд под двумя названиями в разные дни (на Краславу и на Индру) показывается один раз.
- **Поезд** — трёхвагонный дизель-поезд по 25 м (линия не электрифицирована) с кабиной на обоих концах: белый, зелёная полоса, жёлтый лоб, тёмные окна; ночью горят окна, фары спереди и красные огни сзади. Над поездом подпись «Поезд → назначение», на карте — зелёная точка, в панели часов — число поездов на линии. У вокзала табло показывает ближайшие отправления поездов.
- **Станция** (`lmStationYard` в [src/landmarks/station-yard.js](src/landmarks/station-yard.js), по OpenStreetMap):
  - островные перроны — низкие, асфальт с белой кромкой, фонари через 30 м и скамейки;
  - пешеходный мост над путями к юго-западу от вокзала — стальной настил на высоте 6,8 м на опорах между путями, перила и лестницы, как в OSM;
  - 20 переходов через пути — резиновые настилы в уровень с головками рельсов; переезды — шире, со шлагбаумами, поднятыми у обеих сторон, и парой красных фонарей;
  - 51 светофор, как в OSM: выходные на мачтах 5 м с тремя огнями (горит красный), маневровые — низкие у пути (горит синий); стоят с той стороны и смотрят в ту сторону, что указано в OSM;
  - упоры в тупиках.
- **Щебень** (все пути города): лента щебня пути доходит до середины промежутка до соседнего параллельного пути, если он ближе 9 м. Пути станции и парков лежат на одном поле щебня, а не каждый на своей полосе среди газона.

## Автовокзал

Daugavpils autoosta, Viestura iela 10. Модель — `lmAutoosta` в [src/landmarks/autoosta.js](src/landmarks/autoosta.js), автобусы — тот же движок, что у городского транспорта ([src/transit/transit.js](src/transit/transit.js)).

- **Навес над перронами.** В OSM он нарисован как amenity=shelter (way 835547039), и сборка данных сделала из него пятиэтажный дом высотой 14,6 м. Теперь он убран из общих зданий (`LM_DROP_BIG` в [src/landmarks/core.js](src/landmarks/core.js)) и нарисован как навес:
  - приподнятый мощёный перрон с жёлтой кромкой;
  - плоская кровля на стальных стойках через 7 м, вынесенная на 0,8 м над автобусами;
  - синий фриз с надписью AUTOOSTA (ночью светится);
  - номера стоянок 1–3 над передом каждой стоянки, скамейки вдоль стены здания, урны.

  Здание вокзала — прежнее, с высотами по лидару. Уличных фото автовокзала найти не удалось (на Mapillary снимков там нет, Commons из облака не ответил), поэтому навес нарисован простым и современным.
- **Стоянки.** Восточнее навеса, в 9,7 м от края перрона, идёт собственный проезд автобусов (service, access=no) от Lāčplēša iela к Viestura iela. Автобусы едут по нему на юг: перрон у них справа, у дверей. Проезд сделан односторонним, и на нём автобус встаёт у самого перрона, а не посреди полосы. Полоса между перроном и проездом заасфальтирована, три стоянки по 12,5 м размечены. Междугородние автобусы занимают стоянки по очереди прибытия и отправления, чтобы соседние по времени не встали в одно место.
- **Междугородние и пригородные автобусы.** В фиде ATD 356 рейсов, у которых есть остановки в пределах карты (в будний день через автовокзал около 270): Рига, Резекне, Екабпилс, Илуксте, Краслава, Дагда, сёла района.
  - `tools/intercity.js` берёт из каждого рейса только часть внутри карты. Там, где его линия пересекает край карты (6,2 км от центра), рейс получает безымянную остановку. Её время рассчитывается по расстоянию между соседними остановками по обе стороны края, так что автобус въезжает с края карты и уезжает за него.
  - Формат такой же, как у `transit.js`. Страница добавляет эти рейсы к городским и прокладывает их по улицам тем же сопоставлением, что городские автобусы.
  - Над автобусом указан номер маршрута и конечная всего рейса («→ Rēzekne 2»), на карте — оранжевая точка, в панели часов — число междугородних.
  - На табло у автовокзала видны их отправления.
  - Своих павильонов у них нет: в городе они встают на городские остановки, на автовокзале — к перрону.
- **Модель** — междугородний автобус 12,4 м: серебристый, тонированные окна во всю длину, оранжевая полоса, багажные отсеки внизу, дверь спереди.

## Дворец культуры

Самый большой зал города (1060 мест), фойе на двух этажах, в верхнем — самый большой витраж Латвии «Uguns un nakts» (Эгонс Цесниекс и Андрис Пурвиньш, 1971). В 2019 году здание утеплили, облицевали светлыми фиброцементными панелями и заменили окна и двери (проект REM PRO).

План — контур OpenStreetMap (way 115667998). Облик — по фото visitdaugavpils.lv и dkp.lv и снимкам с дрона rem.lv. Как и с вокзалом, самого здания в `citydata.js` не было: в OSM спортзал и навес над входом нарисованы частями здания, и от дворца остались только они.

- **Фасад к стоянке**, 96,5 м: 16 пролётов между квадратными пилонами под глубоким фризом. В пролётах в три ряда утоплено остекление фойе: внизу витрины над тёмно-синими панелями, в среднем ряду окна с двумя вертикальными рёбрами, вверху окна второго фойе.

- **Спортзал**: цоколь из тёмных антрацитовых панелей, под карнизом окна между светлыми рёбрами. Вход под тёмным козырьком, рядом табличка KULTŪRAS PILS / SPORTA ZĀLE.

- **Smilšu iela 92A.** В OSM это building=bunker, в кадастре — резервуары и бункеры. Раньше рисовался белым куполом высотой 9 м, теперь это обвалованный земляной холм.

Ways 173944046 (131;132) и 643576917 (631;632) двухцепные: одна опора несёт обе цепи, по три фазы на сторону; 133/290/291 и 313/314 одноцепные. ## Первомайка (Jaunā Forštadte): мосты

Новый Форштадт, «Первомайка», отделён от центра железной дорогой. Туда ведут два пути, оба по мостам.

**Воздушный мост** (`lmAirBridge`; в OSM way 37794110, «gaisa tilts uz Jauno Forštadti») — пешеходный мост над сортировочными путями между Minskas iela и Slāvu iela. Раньше он лежал на земле: оба его конца стоят на земле, и общий генератор мостов клал настил на их высоту. Теперь он сделан по проекту ремонта 2024 года (SIA «Vektors T» для SIA «Tilts»).
- **Настил**: 200,3 м в плане с двумя поворотами, пролёты 27+27+27+27+2,4+18,5+27+2,4+27+15 м. П-образные преднапряжённые балки, ширина 3,25 м, проход 2,9 м между стальными перилами, около 6,7 м над рельсами.
- **Опоры**: сборные железобетонные стойки с ригелями, на настиле фонари с шарами.
- **Лестницы**: Т-образная 15+9+9 м к Minskas iela, прямая 26 м вниз между путями, прямая 21 м к Slāvu iela.
- По мосту можно пройти пешком.

**Развязка Latgales iela** (`lmJunction`, 2009–2011; Vikipēdija, подрядчик Binders). Latgales iela около 900 м идёт в выемке глубиной около 7 м, по две полосы в каждую сторону. Над ней четыре моста, контуры взяты из OSM:
- **Путепровод Piekrastes iela**: однопролётная бетонная рама 75,9 м, низ которой изгибается и уходит в оба откоса, как арка. Тротуары отделены красными перилами, на мосту фонари.
- **Два железнодорожных моста**, 52,7 и 54,4 м: плиты с белыми парапетами на рядах круглых колонн под ригелями, у разделительной полосы и у обочин.
- **Пешеходный мост** на тонких колоннах с красными перилами.

Все линии на мосту (дорога, тротуары, пути) берут высоту с его оси, так что у них общий настил.

**Выемка** (`cutCarve`, `cutY` в [src/world/cutting.js](src/world/cutting.js)). Модель рельефа с сеткой 20 м сглаживала такую узкую выемку до 3–4 м с волнистым дном. Под железнодорожными мостами между дорогой и низом настила оставалось 2–3 м. Теперь у выемки свой профиль по оси между двумя проезжими частями:

- он нигде не выше земли вдоль оси (сглаженной по ±40 м), поэтому подходит к обоим круговым движениям на их высоте;
- под каждым мостом опущен так, чтобы до низа настила было 5 м (настилы держат высоту земли у своих концов, какой она была до выемки);
- уклон не круче 4,5 %, переломы скруглены на ±25 м.

От восточного кругового (10,5 м) дорога спускается к железнодорожным мостам (2–3 м), за путепроводом Piekrastes iela идёт на 4–5 м и выходит к западному круговому на 3,8 м. По бокам 8–14 м, то есть выемка глубиной 6–8 м.

Сетка рельефа берёт этот профиль в пределах 15 м от оси, дальше откосы 1 : 1,8 до земли. На грубой сетке земля у дороги повторяет его лишь примерно. Поэтому дорога, её тротуары, пешеходы, машины, фонари и ноги опор мостов берут сам профиль — в пределах 12,5 м от оси, с переходом к земле к 16 м. Для пешеходов, транспорта и фонарей это делает `bridgeY`: вне настилов мостов он возвращает поправку выемки.

Мост поднимает машину или фонарь, только если идёт в ту же сторону. Пешехода — только если настил на высоте, где он стоит. Поэтому автобусы на Latgales iela больше не подпрыгивают на высоту путепровода, а пешеход под мостом остаётся внизу.

**Концы мостов.** Откосы выемки на сетке 20 м доставали до концов мостов, и настилы висели в воздухе до 3 м. Теперь в пределах 22 м от каждого конца земля дальше 9 м от оси не копается: устои, пути и дорога на мост сходятся с ним на одной высоте. Земля у концов равна высоте настила: путепровод 10,0 и 10,1 м, железнодорожные мосты 7,4 и 8,9 м, 8,5 и 8,8 м, пешеходный мост 7,2 и 7,7 м.

**Подпорные стены** (OSM barrier=retaining_wall): три бетонные стены у подножия откосов под мостами, в 17–25 м от оси. Одна у путепровода Piekrastes iela, по одной с каждой стороны под железнодорожными и пешеходным мостами. Тротуары внизу идут прямо вдоль них. На стороне стены сетка дальше 15 м от оси не копается, ступень берёт сама стена:
- стена поднимается от дороги до земли за ней, сверху бетонный парапет. Под железнодорожными мостами — только до низа настила: мост опирается на неё;
- перед стеной ровная полоса травы на высоте дороги. Сетка 20 м не может держать стену и всё равно поднимается к ней, полоса это закрывает;
- тротуары перед стеной до самой стены берут профиль выемки, а за ней — землю;
- за концом стены ровное дно сужается обратно до обычной выемки на протяжении 20 м, откос огибает конец стены. Тротуар там выходит из выемки подъёмом, а не ступенькой;
- пешеход у стены не проходит сквозь неё. Отбойники и стены не мешают идти по мостам над ними.

**Отбойники** (OSM barrier=guard_rail): стальная волна высотой 0,45–0,8 м на столбиках через 4 м. В разделительной полосе по всей длине, с волной с обеих сторон. По внешним краям дороги волна смотрит к дороге. Лежат на профиле выемки, как дорога.

**Полосы и переходы.** Обе проезжие части — по две полосы (lanes=2 из OSM), с прерывистой линией между ними на всём протяжении. Переходы вокруг Latgales iela и обоих круговых взяты из узлов OSM (`CROSSINGS_LAT` в [src/world/street-tags.js](src/world/street-tags.js)): зебра там, где переход размечен, и никакой угаданной зебры там, где он не размечен.

**Уступи дорогу на круговых** (`roundabouts` в [src/world/signals.js](src/world/signals.js)). Движение по кольцу едет первым. Кольцо — замкнутая круглая улица радиусом 8–40 м: оба круговых Latgales iela, Vidzemes, Smiltenes iela и ещё несколько в городе. На каждой улице, что в него входит, поперёк входящих полос прерывистая линия, в 0,8 м от внешнего края кольца. Если ровно там зебра, линия встаёт за ней. OSM хранит односторонний путь по направлению движения. Поэтому из пары односторонних проезжих частей у кольца въезжает та, что на нём кончается (линия на всю ширину), а та, что начинается, — выезд. Парой считаются два пути, что расходятся из одного узла, или две проезжие части одной улицы рядом. Двусторонняя улица получает линию на правой половине.

Здания. Контуры, этажность и высота остаются кадастровыми (берутся те части, что лежат внутри школьного здания OSM; крыша рисуется общим генератором с городскими текстурами), фасад — один из трёх наборов, подобранный по фотографиям Wikimedia Commons (Panoramio и др.):
- **советский типовой** (1960–80-е): широкие классные окна в три створки, узкие окна лестниц на торцах, ленточные верхние окна спортзалов, плоская крыша за парапетом, вход — остеклённый одноэтажный тамбур с козырьком и названием школы на стороне улицы (или у главного входа, отмеченного в OSM). Стены — бледный силикатный кирпич с окнами в поясах из красного кирпича (11. pamatskola, прежние снимки 13-й школы; у Centra vidusskola — красные обрамления окон по снимкам Kandavas iela 17) или, после утепления, белая штукатурка с цветными вставками: пастельные квадраты и оранжевые торцы (бывшая 13-я, 18. novembra iela 197V, снимок 2021 года), розовые простенки и красные колонны вдоль первого этажа (бывшая 10-я, Tautas iela 11), жёлтые, оранжевые и зелёные полосы (корпуса Iespēju на Valkas iela по аэрофото «Губище, школа, стадион»);
- **сталинский** (1950-е): штукатурка с пилястрами, карниз, вальмовая крыша (бывшая 17-я, Valmieras iela 5; Stropu pamatskola);
- **исторический**: красный кирпич с арочными окнами (Польская гимназия, Varšavas iela 2), белый с арочными окнами первого этажа над серым цоколем (Государственная гимназия), охра с белыми наличниками и поясами (6-я школа, Komunālā iela 2), светлая штукатурка между простенками красного кирпича с арочными окнами (Vienības pamatskola, Ģimnāzijas iela 32).
Здания без фотографий получают кирпичный советский набор — самый частый облик школ города. Набор и цвета каждого здания — в таблице `SPEC` по идентификатору OSM; там же вывески с нынешними названиями.

Площадки — как в OSM: искусственный газон с полосами покоса, трава, тартан, асфальт, песок; разметка футбола (ворота по размеру поля), баскетбола (кольца по тегу hoops), волейбола и тенниса с сетками, яма для прыжков в длину; беговые дорожки из красного тартана с разметкой полос (площадь, прямая или замкнутый овал вокруг поля, как у 8-й школы в Гриве); заборы — сетка-рабица, стальные прутья, доски или бетонные плиты; флагштоки с флагами Латвии, ЕС и города, скамейки, велостоянки, тренажёры и детские площадки.

Пересобрать `schools.js`: скачать карту OSM API вокруг каждой школы (список школ — поиск Nominatim `[school]` и `[college]` в границах города), затем
```bash
node tools/schools.js schools.js maps/*.osm
```

## Церковная горка

Четыре храма четырёх конфессий на Церковной горке (Baznīcu kalns, Новое Строение) построены вручную по фотографиям ([src/landmarks/church-hill.js](src/landmarks/church-hill.js)), а не общим генератором церквей. Контуры — из кадастра и OSM (ways 88592954, 88592806, 88592868, 129571412); у каждого храма своя система координат вдоль длинной стороны, здание стоит на склоне ровно, как остальные дома.

- **Свято-Борисоглебский кафедральный собор** (1905, русский стиль): белый с голубым узором. Базилика: в нижнем ярусе большие арочные окна в голубых обрамлениях между столбиками голубых квадратов и по два входа с щипцами на каждой стороне, выше световой ярус с окнами поменьше. Над восточной частью квадратный объём с кокошниками; на нём золотая луковица на голубом барабане с окнами и четыре малые вокруг, на углах голубые шатры с маковками. Колокольня над западным входом: икона над дверью, звонница с парными проёмами, четыре щипца и высокий голубой восьмигранный шатёр со слуховыми окнами, золотая луковица и крест. Всего 13 глав.
- **Собор Мартина Лютера** (1893, неоготика): красный кирпич со светлыми каменными деталями. Стрельчатые окна с витражами между контрфорсами, крутая серая кровля, трансепт с высокими щипцами и розами, многогранная апсида. Западная башня с щипцами на каждой грани, восьмигранным серым шпилем около 51 м и пинаклями.
- **Костёл Непорочного Зачатия Девы Марии** (1902–1905, необарокко): белый. Пропорции фасада сняты с фронтального снимка: башни шириной 9 м с карнизами на 9,9, 17,4, 25,2 и 31,2 м, обелисками на углах ярусов, круглыми окнами внизу, тёмными главками, фонариками и шпилями (кресты на 43 м). Между башнями три двери, большое окно между колоннами и изогнутый фронтон с нишей Девы Марии. Неф над двумя приделами, на востоке три апсиды трилистником, средняя высокая под серой полукупольной кровлей.
- **Староверческая церковь Рождества Богородицы** (1908): розовые стены, белые наличники с килевидными навершиями. Двухэтажный притвор, над западным крыльцом с колоннами белый килевидный щипец с иконой, за ним колокольня с тройными проёмами и маленькой золотой луковицей на красном барабане. Высокий основной объём с поясом белых арочек под карнизом на сухариках и выступами с килевидными щипцами по бокам, над ним большая золотая луковица на красном восьмигранном барабане, над алтарём малая синяя главка.

Смотреть: «Места» → «Церковная горка» (вид с 18. novembra iela на собор Лютера и костёл; Борисоглебский собор правее, за собором Лютера, староверческая церковь позади, в 170 м).

Источники фото: Wikimedia Commons, категории *Daugavpils Ss Boris and Gleb Orthodox Cathedral*, *Evangelical Lutheran Church of Martin Luther in Daugavpils*, *Church of the Immaculate Conception of Blessed Virgin Mary in Daugavpils*, *Old Believers Church of the Nativity of the Theotokos in Daugavpils*.

## Стоянки

Все стоянки города из OpenStreetMap (`amenity=parking`, файл `parking.js`, собирает [tools/parking.js](tools/parking.js)): 407 открытых площадок и карманов вдоль улиц, около 7 тыс. мест. Рисует их `lmParking` в [src/landmarks/parking.js](src/landmarks/parking.js).

- **Что берётся из OSM**: контур стоянки с дырами (мультиполигоны), вид (площадка, карман вдоль улицы, полоса), покрытие, вместимость, доступ, платность; проезды `service=parking_aisle`, размеченные места `amenity=parking_space`, шлагбаумы. Подземные, многоэтажные и на крыше не рисуются: это здания.
- **Чьи машины** (определяет инструмент): двор (среди многоквартирных домов или `access=private`), магазин (`access=customers`, рядом супермаркет, торговая зона), работа (промзона, больница, школа, офисы) или прочее. По городу: 141 двор, 117 магазинов, 73 работы, 82 прочих.
- **Покрытие** по тегу `surface`: асфальт (по умолчанию), бетон, плитка и брусчатка, гравий и грунт, газонная решётка. По краю, где стоянка граничит с газоном (не с улицей, дорожкой или домом), — низкий бордюр 12 см.
- **Места** 2,5 × 5 м:
  - где места размечены в OSM — по ним;
  - иначе поперёк размеченных проездов по обе стороны (проезд 5,2 м), без мест в 3 м от конца проезда и у поворотов;
  - иначе (или если проезды покрывают меньше трети площадки) рядами вдоль длинной стороны: ряд у края, проезд 6 м, два ряда спина к спине и так далее; карман уже 4,4 м — машины друг за другом, в карман до 7 м — один ряд поперёк;
  - мест нет на проезжей части и проездах, на дорожках, рельсах, в домах и у самой стены, на площадках заправок; не больше вместимости из OSM (лишние убираются равномерно).
  - Белые линии — на твёрдом покрытии у магазинов и на работе и примерно в половине дворов.
- **Машины** — три силуэта (седан, хэтчбек, минивэн), цвет у каждой свой. Сколько их, зависит от времени суток на часах города (пересчёт каждые 10 минут):
  - двор: ночью ~85 % мест, днём ~45 %;
  - магазин: ночью почти пусто, днём ~55 %, вечером (17–19) до ~80 %, в выходные пик днём;
  - работа: с 8 до 17 ~80 %, ночью и в выходные почти пусто;
  - прочее: ~30 % ночью, ~60 % днём.
  
  По городу в будний день в 13:00 стоит около 4 тыс. машин, в 3:00 — около 2 тыс. У каждой стоянки свой множитель ±15 %, каждое место занято или свободно по своему порогу, поэтому машины не мигают при пересчёте, а прибавляются и убывают. Пешеход в машины упирается (только в стоящие сейчас). Машины рисуются по квадратам 1 км и только в 1,5 км от камеры.
- **Деревья**: лидарное дерево у края стоянки отодвигается за край (не больше половины кроны над стоянкой), а дерево глубоко внутри остаётся — вокруг него газонный островок с бордюром, места вокруг не размечаются (98 островков).
- **Фонари** вдоль контура стоянок от 1000 м² через 28 м (если ближе 14 м нет уличного фонаря), **знак «P»** у въезда (точка контура, ближайшая к улице или проезду; не у частных дворов), **шлагбаумы** из OSM.
- На миникарте стоянки серые.
- Стоянки, которые рисуют сами ориентиры, пропускаются (только деревья с них так же убираются): у гостиницы «Латгола» (площадь Единства), у Дворца культуры, за Комендантским домом в крепости, у больницы и в паддоке спидвея.

Посмотреть: Rimi Hyper и Lidl на Cietokšņa iela, стоянка Ditton nams, дворы Химии и Новых Строений днём и ночью (время суток выбирается на стартовой карточке, часы — в панели).

## Парки и скверы

22 парка и сквера города из OpenStreetMap проработаны отдельным модулем ([src/landmarks/parks.js](src/landmarks/parks.js)). Среди них Дубровинский и Центральный парки, Пороховка, сквер Андрея Пумпура, Скульптурный парк, сквер Славы, сквер у Гайока, парк у Эспланады, сквер в крепости. Данные — [parks.js](parks.js): контуры парков, дорожки с покрытием, площадки, ограждения и живые изгороди, клумбы, ряды деревьев, скамейки, урны, фонари, фонтаны, памятники, скульптуры. Облик — по фотографиям Wikimedia Commons (Дубровинский парк 2013 года, его фонтан ночью и мемориал, бюсты Пумпурса и Райниса, Центральный парк, фонтаны Эспланады и крепости).

- **Деревья**: в парках их стало примерно вчетверо больше (шаг около 9,5 м вместо 18 м), крупнее. Вдоль нанесённых в OSM рядов деревьев высажены аллеи. Деревья не встают на дорожки, клумбы, площадки и к фонтанам и памятникам.
- **Газон и цветы**: под дорожками парков лежит газон с фотографической текстурой травы (слой ниже улиц, поэтому дорожки остаются поверх), площадки и собачьи выгулы — с текстурой земли. По газону инстансированы три вида цветов (до 40 на парк, до 500 на город; каждый цветок файла — несколько мешей, части делят общий буфер матриц) ([src/landmarks/flora.js](src/landmarks/flora.js), модели ez-tree, MIT): они не встают на дорожки, клумбы, площадки, воду и дороги. Текстуры — `textures/ground_grass.webp`, `textures/ground_dirt.webp`.
- **Фонари**: чёрные чугунные столбы с фонарём-«короной» вдоль мощёных дорожек через 24 м в шахматном порядке, плюс нанесённые в OSM. Ночью стекло светится, под фонарями световые пятна.
- **Скамейки** развёрнуты сиденьем к ближайшей дорожке, рядом урны. Столы для пикника, мангалы, кабинки туалетов, колонки с питьевой водой, велостоянки — где нанесены.
- **Площадки** (детские, спортивные, тренажёры), ограждения — как у школ. Площадки для собак огорожены сеткой, BMX-трассы из утоптанной земли.
- **Клумбы** приподняты за гранитным бордюром и засажены цветами, **живые изгороди** подстрижены, низкие стенки из камня.
- **Тростник** — по зарослям, нанесённым в OSM (`natural=wetland`): пучки тонких листьев через 0,7 м, у каждого листа свой наклон и высота (1,5–2,5 м), зелёные снизу, оливковые и соломенные к концам, у трети пучков — тёмные метёлки. Сейчас это четыре заросли у пруда Пороховки.
- **В меню «Места»** добавлены сквер Пумпура, Центральный парк, Эспланада и Пороховка.
- **Фонтаны**: высокая струя с кольцом малых в пруду Дубровинского парка (ночью подсвечена), струи сквера у университета, гранитные чаши — «Девушка с лилией» в сквере Пумпура, чаша Эспланады, ступенчатое основание с двумя чугунными стволами в крепости.
- **Памятники**: бюсты Андрея Пумпурса и Райниса на гранитных постаментах, статуя Павла Дубровина, мемориал из тёмных гранитных стел в Дубровинском парке, стела павшим в Афганистане, памятные камни и доски. **Скульптуры**: металлические диски и кольца, абстрактная бронза, «Дерево любви» в Центральном парке, солнечные часы из чёрного мрамора 1910 года.

Пересобрать `parks.js`: скачать карту OSM API вокруг каждого парка (список парков — поиск Nominatim `[park]` в границах города), затем
```bash
node tools/parks.js parks.js maps/*.osm
```
Парк, который OSM знает только точкой (Aizpilsētas parks), берёт контур из полигонов OSM, перечисленных в `NODE_PARKS` в начале `tools/parks.js`. Сборка по всем квадратам города (как для `parking.js`) нашла бы ещё 5 безымянных парков, которых сейчас в `parks.js` нет (один из них — сквер у площади Единства, которую рисует её ориентир); их не добавлял.

## Спидвей-стадион «Локомотив»

Стадион Lokomotīve на Jelgavas iela 54, домашний трек спидвей-клуба «Локомотив»: открыт в 1963 году (405 м), с 1996 года длина круга 373 м. Модель `lmSpeedway` в [src/landmarks/speedway.js](src/landmarks/speedway.js).

Откуда взята геометрия:

- **OpenStreetMap**: внешняя кромка трека (площадь raceway, relation 20362487), граница травяного поля (way 803378638), точка старта и финиша, контуры трибун (ways 130274825 и 130274821), навес боксов (way 803378635) и двенадцать мачт освещения.
- **Схема стадиона клуба** ([lokomotive.lv](https://www.lokomotive.lv/stadiums/lokomotiv), 2026): главная трибуна A вдоль Jelgavas iela с секторами A–F и VIP, трибуна B напротив, боксы и паддок со стороны Arodu iela, линия старта перед сектором VIP, ворота на трек в вершинах виражей. Там же ширина трека: 11,2 м на прямых, 16,3 м в виражах. По OSM выходит столько же.
- **Облик** — фотографии из галереи клуба.

Что построено:

- **Трек.** Кромки сглажены, внешняя ведётся по нормалям от внутренней, поэтому ограждение и надувные борта идут параллельно полотну. Гранитное покрытие темнее на траектории у бровки и светлее у забора, где лежит отброшенная крошка. У бровки белый бортик. Поле выкошено полосами поперёк трека.
- **Старт.** Меловая линия старта и финиша и четыре стартовые позиции. Три ленты стартовой машины натянуты между столбиками на поле и у забора. На заборе и на поле клетчатые щиты.
- **Ограждение.** Тёмные доски на белых столбах с поручнем. Вдоль прямых рекламные щиты, в виражах оранжевые надувные борта секциями по 5 м. В вершинах виражей открыты ворота: из паддока и для скорой.
- **Трибуны A и B.** Пятнадцать рядов по 0,8 м с подъёмом 0,42 м над стенкой высотой 1,3 м с проходом. Около 6200 синих сидений (инстансы), на трибуне A каждый четвёртый ряд жёлтый. Бежевые (на B — белые) лестницы с половинными ступенями между секторами, чёрные поручни. Ограждение по фронту, портал тоннеля к треку под первыми рядами. Задняя стена — каркас с пилястрами и дверями, на A главный вход с Jelgavas iela за сектором VIP.
- **Навес над центром трибуны A** (секторы C, VIP, D): десять пологих сводов из светопрозрачного листа на консольных фермах, колонны в задней стене. Под навесом жёлтая кабина комментаторов и пять прожекторов над домашней прямой.
- **Трибуна B.** Жёлтые рифлёные щиты вдоль верхнего прохода, перила по задней стене, за ней флагштоки с флагами стран гонщиков.
- **Мачты.** Серые опоры с двумя светильниками, повёрнутыми к треку. Вечером и ночью светятся и дают пятна света на дорожке.
- **Боксы.** Десять боксов под синими двускатными крышами, открытые к паддоку, в каждом верстак. Асфальт в паддоке и перед трибунами, плитка у главного входа; стоянку у трибуны B рисуют общие [«Стоянки»](#стоянки), с машинами по времени суток.
- **Рельеф и проходы.** Площадка стадиона выровнена: земля там падает на 1,5 м к Jelgavas iela. По трибунам можно ходить: на них поднимаются с переднего прохода и идут по рядам вверх. Забор пускает на трек только через ворота.

## Заправки

Все 20 АЗС города построены одним генератором (`lmFuel`, таблица `FUEL` в [src/landmarks/fuel.js](src/landmarks/fuel.js)). Раньше навесы многих из них рисовались домиками с окнами: в кадастре навес записан как маленькое здание. Магазины были обычными домами, а подземные топливные ёмкости — девятиметровыми силосами на площадке.

Откуда взята геометрия:

- **OpenStreetMap**: точки `amenity=fuel` и то, что нарисовано вокруг них. Это навесы (`building=roof`), магазины, мойки, участки (`landuse=retail`), стелы (`advertising=totem`), флагштоки, газовые и топливные ёмкости, компрессоры и крытые проезды под навесами.
- **Кадастр**: контуры, которых нет в OSM. Это навес и магазин Virši-A на Cietokšņa iela, навес Viada на 18. novembra iela, магазин Viada «Daugavpils 2».

Таблица собрана по выгрузке OSM от 14 ноября 2026 года. Кадастровые навесы, магазины, мойки и ёмкости на участках АЗС генератор зданий пропускает.

Что строится на каждой станции:

- **Площадка.** Участок в асфальте; где участка нет, асфальт вокруг навеса. Под навесом бетон.
- **Навес.** Контур из OSM, потолок на 4,7 м, фриз 1 м в цветах марки. Название марки на всех свободных сторонах длиннее 5 м. На потолке светильники, ночью под навесом пятно света. Фризы, потолки и стелы — светящиеся панели: днём они чуть подсвечены в свой цвет, ночью ярче.
- **Островки.** Ставятся между крытыми проездами, нарисованными под навесом. При одном проезде — по обе его стороны, если проездов нет — вдоль длинной стороны навеса. На островке колонка в цветах марки с экранами и пистолетами, две колонны навеса, отбойные столбики и урна.
- **Магазин.** Стеклянный фасад с дверью смотрит на навес, остальные стены в цвете марки. Наверху фриз с названием, на крыше кондиционер.
- **Стела.** Стоит в точке из OSM и повёрнута к ближайшей улице. Сверху марка, ниже табло с ценами: 95/98/D, на станциях с газом ещё LPG, на газовых только LPG. Цены условные, только для вида.
- **Прочее.** Мойки самообслуживания (навес с перегородками между боксами и стойкой в каждом), флаги марки на флагштоках, компрессоры. У Intergaz четыре газовые ёмкости за оградой, у Viada на востоке — площадка топливных ёмкостей. Газовая колонка Latvijas Propāna Gāze у Neste Daugavpils II стоит под своим маленьким навесом.

Оформление марок по фотографиям:

- **Circle K** — красный фриз с оранжевой полосой, тёмно-серый магазин.
- **Neste** — синий фриз с салатовой полосой, зелёные колонны и колонки, белый магазин.
- **Viada** — красный фриз, наклонённый наружу, белые круглые колонны, белый магазин с красным фризом.
- **Virši-A** — зелёный фриз над синей полосой, тёмный магазин.
- **Latvijas Propāna Gāze** — белый с зелёным.
- **Intergaz** — белый с синим.

Фотографий станций Ingrīda (местная сеть) не нашлось, они белые с тёмно-синей полосой. Станция на Silenes iela 1 известна только по безымянной точке 2011 года: у неё нет навеса ни в OSM, ни в кадастре. Там поставлен один островок под маленьким навесом между домом и проездом.

## 18. novembra iela: путепровод у тюрьмы

Улица (трасса A13) вместе с обоими трамвайными путями проходит над главным ходом на Индру и подъездными путями к востоку от вокзала. Мост длиной 45 м (OSM way 127382597) стоит у Daugavgrīvas cietums. С запада, от примыкания 1. Preču iela, к нему ведёт подъём около 150 м. На востоке улица выходит на плато к x ≈ −90. С тротуаров к боковым улицам спускаются лестницы. Модель: `ovPrep`, `lmOverpass` в [src/world/overpass.js](src/world/overpass.js).

**Что было не так.** Модель рельефа (сетка 20 м) сглаживает насыпи до нескольких метров, а мост из неё вырезан. Поэтому настил ложился почти на рельсы, а подъёмы шли по земле.

**Профиль.** Теперь у участка свой профиль высот:

- настил на 8,2 м выше рельсов, под балками 6,6 м — состав проходит с запасом;
- с запада прямой подъём около 5 %;
- над путями ровно, с лёгким горбом;
- на востоке пологий выход на плато;
- переломы скруглены на 40 м, и профиль нигде не уходит под землю.

По этому профилю идут проезжие части, трамвайные пути, тротуары, лестницы, фонари, трамваи с автобусами и пешеход. Для них участок — мост с собственным профилем (`B.prof`), и высоту они берут из того же `bridgeY`.

**Устройство моста:**

- **Покрытие** — сплошной асфальт на всю ширину. Он рисуется раньше слоёв земли и пишет глубину: полосы и пути ложатся на него, а то, что проходит под мостом, им закрыто.
- **Четыре полосы** на мосту и восточном подъёме, как на снимке Street View. Проезжая часть идёт от отбойника до отбойника (до 0,4 м от них), посередине двойная сплошная, между полосами прерывистые линии. Трамвайные пути лежат во внутренних полосах. За концом участка улица за 12 м сужается до обычных двух полос (`ovWidths` в [src/world/streets.js](src/world/streets.js), `ovRoadHW` в [src/world/overpass.js](src/world/overpass.js)).
- **Насыпи** — травяные откосы 1 : 1,5 от края до земли. Деревья на насыпи не растут, кадастровые постройки под подъёмами убраны.
- **Опоры и пролёт** — бетонные устои со стороны путей, плита с карнизами, шесть балок. Две опоры на трёх колоннах стоят в промежутках между семью путями и развёрнуты вдоль них. Верх устоя спрятан под плитой. Раньше он поднимался на 0,2 м над дорогой и лежал бортиком поперёк улицы на обоих концах моста.
- **Ограждения** по снимку Google Street View (апрель 2024): по краям перила из вертикальных прутьев серо-голубого цвета на низком бортике. Стальные отбойники между проезжей частью и тротуарами стоят на мосту и на восточном подъёме. На западном подъёме у тротуаров отбойников нет: один отбойник идёт между проезжей частью и трамвайным полотном, там, где пути лежат сбоку от дороги. Пешеход не падает с подъёмов, кроме мест, где спускаются лестницы.

**Западный подъём.** В OSM здесь две встречные проезжие части по одной полосе. У моста между ними лежат трамвайные пути. Около 90 м от подножия пути пересекают полосу на запад и уходят на своё полотно с северной стороны, где растёт трава. У 1. Preču iela проезжие части расходятся вокруг островка. Раньше каждая полоса рисовалась как целая улица шириной 11 м, поэтому осевые, краевые линии и тротуары двух проезжих частей накладывались друг на друга. А опора контактной сети, поставленная у дальнего борта «своей» проезжей части, оказывалась во встречной полосе. Как это исправлено, описано в разделах «Две проезжие части» и «Рельсы и контактная сеть трамвая».

## Daugavas iela под мостом Единства

У северного конца моста Единства Daugavas iela расходится. Одна проезжая часть поднимается на дамбу к каплевидной развязке у моста. Другая — OSM way 22734923, односторонняя, `maxheight=3.9` — идёт ниже вдоль берега и ныряет под последний пролёт моста. Модуль [src/world/underpass.js](src/world/underpass.js); облик — по Google Street View (апрель 2024).

**Что было не так.** Модель рельефа (сетка 20 м) опускала конец моста до 3,9 м над площадью Единства, на 2 м ниже развязки, к которой он ведёт. Нижняя дорога шла на высоте настила и упиралась в насыпь моста. Съезды развязки рисовались двухполосными улицами по 11 м, их разметка перекрещивалась, а у узлов края съездов сходились буквой V.

- **Конец моста** — на высоте развязки: она берётся в 10 м за концом моста на его оси. На этой высоте лежат и площадка за концом моста, и начала съездов: до 15 м по оси моста, на 3 м шире настила. Откос над габионом их не срезает. Сбоку к ним подходит бетонная стена коробки с крыльями. Раньше откос опускал землю на метр сразу за концом настила, и мост висел в воздухе.
- **Нижняя дорога** идёт своим профилем: прямо от одного конца пути до другого, под мостом на 5 м ниже настила (просвет 3,9 м под балкой 1,1 м), уклон не круче 4,5 %, углы скруглены.
- **Мелкая поправка рельефа.** Это сетка 1 м поверх сетки 20 м, её добавляют к высотам и шейдеры, и JS (`PATCHES` в [src/world/terrain.js](src/world/terrain.js); их три: здесь и у обоих концов ж/д моста). Дорога лежит ровно поперёк. По сторонам стоят габионы (1,8 м со стороны дамбы, 0,8 м к реке), над ними откосы 1 : 1,5. Конец моста — на своей площадке. Внутри поправки земля и линии дробятся мельче (до 1–1,5 м), а под землёй вместо сетки глубины 20 м — частая, 2 м.
- **Под мостом — бетонная коробка:** стены вдоль дороги до балки, пролёт из пяти балок между крайними, знак «3,9 м» на балке с обеих сторон. Насыпь моста над дорогой открыта, стальные пролёты доходят до коробки, как на фото.
- **Полоса** одна, слева заштрихованный край, тротуара нет. Габионы — камни в проволочной сетке ярусами по метру. Над обрывом к реке стоит отбойник. Фонари и деревья в коробку не ставятся.
- **Под мостом, а не по нему.** Машины, едущие вдоль нижней дороги, и пешеходы, идущие по ней, проходят под мостом, а не взлетают на настил: машины — по направлению, пешеходы — по высоте, на которой стоят.
- **По мосту и под ним можно пройти пешком.** Раньше игрока не пускали на настил у северного конца и под мост: стены коробки и перила настила — линии столкновений на плане, без высоты, и перила, стоящие над улицей, перегораживали саму улицу. Теперь у таких линий есть метка: стены настила (перила, метка 1) не мешают тому, кто стоит на земле ниже настила на 2 м и больше, а стены под настилом (стенки коробки, метка 2) мешают только ему (`upLow` в [src/world/underpass.js](src/world/underpass.js), `collide` в [src/game/player.js](src/game/player.js)). От Grīva до берега у площади Единства мост проходится целиком, нижняя улица — с обеих сторон.
- **Въезд на мост со стороны Grīva.** За 17 % уклона улица спускается к началу настила, а высота ходока и автобуса за 2 м до него резко падала на полметра: автобус «проваливался» перед мостом. Теперь добавка высоты вырастает плавно на последних 4 м (`vbLift` в [src/world/terrain.js](src/world/terrain.js)), скачок ходьбы по мосту не больше 5 см.
- **Съезды каплевидной развязки** односторонние, в одну полосу (по тегам OSM в [src/world/street-tags.js](src/world/street-tags.js)): краевые линии и бордюры, без осевой и тротуаров. Разметка съездов прерывается там, где они пересекаются. Там, где два съезда расходятся из конца двусторонней дороги, они начинаются бок о бок, каждый в своей половине дороги, и расходятся на первых 30 м.

## Две проезжие части

Многие главные улицы нанесены в OSM двумя односторонними линиями рядом, а в данных нет ни признака одностороннего движения, ни числа полос. Поэтому линия считается одной из двух проезжих частей, если у большинства её точек сбоку (а не впереди, как у следующего куска той же улицы) есть другая линия с тем же названием и классом, параллельная, в 3–26 м. Таких линий 124, вместе 18,6 км: 18. novembra, Jātnieku, Mendeļejeva, Latgales, Imantas, Viestura и другие. Код: `dualOf` в [src/world/streets.js](src/world/streets.js).

- **Ширина** по расстоянию до второй проезжей части: одна полоса, если они идут в 8 м или ближе, две полосы с прерывистой линией между ними — от 11 м.
- **Узкий разделитель — асфальт**: уже 4 м, а если в нём лежат трамвайные пути (у путепровода), уже 4,5 м. Если он уже 1,4 м, его делит двойная сплошная. Если шире, у полос сплошные края, а между ними косая штриховка. С трамвайными путями он асфальтовый без разметки, рельсы утоплены заподлицо, как на мосту. Более широкий разделитель остаётся землёй или травой. Ширина берётся средней по ±30 м, участки короче 25 м присоединяются к соседним. Раньше разделитель шириной 4–5 м (Latgales iela) каждые несколько метров менялся с окрашенного на траву и обратно, а две проезжие части решали это каждая сама.
- **Тротуар, бордюр и фонари** — только с внешней стороны. Там, где вдоль внешнего края идёт трамвайное полотно, тротуара нет. Фонари не встают на трамвайные пути.
- **Место, где пара отходит от одной дороги.** OSM сводит обе проезжие части в концевую точку той дороги, от которой они отходят. Так у западного конца моста путепровода две проезжие части подъёма сходятся в один узел. На последних 15 м их оси сбегались, и края, бордюры и тротуары ложились клином поперёк четырёх полос моста: тротуар выходил в форме V. Теперь у такого узла (на нём кончаются вторая проезжая часть и ещё одна линия той же улицы) последние 30 м каждой проезжей части продолжают её прямо, как она идёт в 30–55 м от конца. Две проезжие части остаются на своём расстоянии и продолжают края моста. Код: `splitAt` и начало `dualOf` в [src/world/streets.js](src/world/streets.js).
- Для движения и контактной сети у проезжей части её собственная ширина, а не ширина целой улицы.

## 18. novembra iela: полосы и загородные участки по OSM

В `citydata.js` у линии есть класс, название и форма, но нет числа полос и признака загородной дороги. Для 18. novembra iela эти теги прочитаны из OSM через Overpass (ноябрь 2026) и записаны таблицей в [src/world/street-tags.js](src/world/street-tags.js). Линия находится по двум концам, они совпадают с концами пути OSM. Код: `streetTags`.

- **Четыре полосы** (lanes=4) от моста путепровода на восток до перекрёстка у x ≈ 1135, около 1,5 км. Проезжая часть шириной 13 м: посередине двойная сплошная, между полосами прерывистые линии. Где трамвай идёт посередине улицы (у путепровода), пути лежат во внутренних полосах. Где на своём полотне сбоку, полотно остаётся в 11–13 м от оси, за тротуаром. Дальше на восток — две полосы.
- **Две проезжие части на западе** — по две полосы в каждой (lanes=2 у односторонних путей OSM). Раньше ширина угадывалась по расстоянию между ними. У западного конца они сходятся до 9 м, и угаданная полоса там становилась одной, а прерывистая линия между двумя полосами оставалась, так что штриховка разделителя попадала внутрь полос. Теперь полос по две на всём протяжении, а разделитель в 2,7 м у конца заштрихован. Короткие куски с третьей полосой для поворота перед перекрёстком у x ≈ −660 нарисованы с двумя. Линия между полосами теперь рисуется только там, где полос действительно две, и у других пар проезжих частей.
- **Загородные участки** — 70 км/ч и без тега освещения, тогда как остальная улица 50 км/ч и почти везде lit=yes: x ≈ 2517–3590 и 4405–4784. Здесь нет бордюров, тротуаров и фонарей, по краям гравийные обочины. Отдельные пешеходные дорожки из OSM остаются.

## 18. novembra iela: светофоры, стоп-линии и переходы по OSM

Узлы светофоров и переходов на улице прочитаны из OSM (ноябрь 2026) и записаны в ту же таблицу [src/world/street-tags.js](src/world/street-tags.js) (`SIGNALS`, `CROSSINGS`). Код: [src/world/signals.js](src/world/signals.js).

- **Регулируемые перекрёстки и переходы.** Узлы светофоров ближе 35 м друг к другу — один перекрёсток или переход. На улице 13 мест со светофорами: перекрёстки у Pilsētas poliklīnika, Baznīcu kalns, Ventspils, Jelgavas, Tukuma, Valkas iela и другие, и отдельные переходы, например у западного конца и у Čiekuru iela. Каждая улица, которая в него входит, — подход. Встречные машины едут справа: на двусторонней улице по правой половине, у пары односторонних проезжих частей по правой из них.
- **Стоп-линия** шириной 0,4 м поперёк входящих полос: за 1,2 м до пересекаемой проезжей части или за 0,8 м до зебры перед ней.
- **Стрелки на полосах** за стоп-линией, длиной 5 м. Направления берутся из того, какие улицы выходят из перекрёстка: прямо, налево, направо. Одна входящая полоса получает все направления. Из двух левая идёт прямо и налево, правая — прямо и направо. Двумя полосами считаются проезжая часть в четыре полосы или одна из пары шириной в две. Линия между двумя полосами на последних 20 м перед стоп-линией сплошная.
- **Уступи дорогу.** Там, где второстепенная или жилая улица примыкает к 18. novembra iela или пересекает её дальше 40 м от светофоров, главная улица едет первой. На входящих полосах боковой улицы — прерывистая поперечная линия: штрихи 0,5 м через 0,4 м, ширина 0,3 м, за 0,8 м до проезжей части 18. novembra или до зебры перед ней. Главные и второстепенные дороги, которые продолжают концы улицы (Daugavas, Krāslavas iela), такой линии не получают.
- **Светофор** на столбе у правого бордюра у стоп-линии, лицом к водителям: три линзы на чёрном щите. Линзы светятся одинаково днём и ночью.
- **Пешеходные светофоры** с двумя линзами — у обоих концов каждой зебры перекрёстка.
- **Цикл** длится 60 с:
  - 18. novembra iela: зелёный 30 с, жёлтый 3 с, затем красный;
  - 2 с горит красный во все стороны;
  - поперечная улица: красный с жёлтым 2 с, зелёный 18 с, жёлтый 3 с;
  - снова красный с жёлтым для 18. novembra.

  Пешеходы через 18. novembra идут на зелёный, пока она стоит. Пешеходы через боковую улицу идут, пока стоит она. У каждого перекрёстка своё место в цикле, так что соседние переключаются не разом. Цикл считает шейдер линз по часам страницы (`U.time`): каждый кадр JavaScript ничего не делает, а погашенная линза сжимается в точку. Роль линзы, её цвет и сдвиг перекрёстка записаны в нормали вершин — освещение линзам не нужно. Часы расписания на светофоры не влияют. Транспорт на сигналы пока не смотрит.
- **Зебры** на 18. novembra iela теперь стоят по узлам переходов OSM: где переход размечен (marked, zebra, uncontrolled, со светофором), там зебра, где не размечен — нет. Догадка по пешеходным линиям на этой улице больше не используется.

## Разметка на перекрёстках и пешеходные переходы

Раньше разметка проходила сквозь каждый перекрёсток. Краевые линии, осевые и бордюры одной улицы пересекали проезжую часть другой, и на 18. novembra iela каждый перекрёсток был в сетке белых линий. Теперь разметка собирается, пока улицы кладутся, и рисуется, когда известны все. Код: `mark`, `clipRuns`, `zebras` в [src/world/streets.js](src/world/streets.js).

- **Разметка обрывается** там, где входит в проезжую часть пересекающей улицы или в окрашенный разделитель. Следующий кусок той же улицы (то же название и класс), её вторая проезжая часть и улицы, идущие вдоль (угол меньше 20°), разметку не режут. Где отрезок линии входит в полосу улицы и где выходит, считается точно: полоса — отрезок с закруглёнными концами.
- **Служебные проезды и въезды** размыкают только бордюр, краевые и осевые линии идут дальше.
- **Пешеходные переходы.** В OSM переход часто нанесён короткой пешеходной линией поперёк улицы. Если такая линия (короче 45 м) пересекает проезжую часть главной улицы (классы 0–2) под углом больше 65°, на ней рисуется зебра: полосы шириной 0,5 м вдоль улицы, длиной 4 м, через всю проезжую часть. Осевые и линии между полосами на зебре прерываются. По городу 294 зебры, на 18. novembra iela 30.
- **Порядок.** Проезжие части кладутся от служебных проездов к главным улицам. Раньше порядок зависел от сортировки, и служебный проезд мог лечь поверх полосы 18. novembra iela.
- **Стыки кусков одной линии.** OSM делит улицу на пути во многих узлах, где больше ничего не сходится. Каждый кусок кончался прямым срезом поперёк своего последнего отрезка. Где два куска в узле поворачивают хоть на несколько градусов, между ними проглядывал клин земли от оси до внешнего края тротуара. Так было в крепости у Константиновских ворот (x ≈ −3060, z ≈ −628), где две жилые улицы сходятся под углом 3°. Теперь, если в узле кончаются ровно две линии одного класса и поворот меньше 60°, оба конца срезаны по биссектрисе, как лента на изломе внутри линии, и куски сходятся край в край, бордюры тоже. По городу таких стыков 3056, из них 959 у проезжих частей. Между линиями разных классов (улица переходит в дорожку) концы остаются прямыми: узкий кусок не закрыл бы внутренний угол широкого. Прямыми остаются и концы на поворотах круче 60°, и там, где угол среза ушёл бы за первую точку линии. Код: `jointEnds` и `frame` в [src/world/streets.js](src/world/streets.js).

Ограничения высоты 4,9 и 4,6 м на улице у Marijas iela и Ventspils iela относятся к трамвайным проводам над перекрёстками, а не к мостам.

## Рельсы и контактная сеть трамвая

- **Железная дорога** (215 км путей): объёмные рельсы — тёмная шейка и светлая стальная головка высотой 0,17 м на шпалах. Шпалы стали серее, ближе к бетонным.
- **Трамвайные пути.** Где путь лежит в проезжей части, рельсы утоплены заподлицо в бетонную полосу и шпал нет: так на путепроводе и вдоль большинства улиц. На обособленном полотне — щебень, шпалы и объёмные рельсы. Какой случай, определяется по тому, проходит ли путь внутри проезжей части.
- **Контактная сеть** (`lmTramWires`, 600 В): контактный провод на 5,8 м над каждым путём, опора через 32 м.
  - В проезжей части стальные опоры стоят у обоих бортов, поперёк улицы натянута растяжка, провода подвешены к ней. Растяжка перекрывает обе проезжие части пары, а не только ту, где лежит путь. Так же, если пути лежат в разделителе уже 6,5 м.
  - На полотне сбоку от улицы опора стоит с дальней от дороги стороны, длинная консоль идёт над обоими путями: так на 18. novembra iela западнее путепровода.
  - На полотне между проезжими частями или в стороне от улиц — центральная опора между путями с консолями над обоими.
  - У одиночного пути — боковая опора с консолью, со стороны от улицы.
  - Пара путей получает одну опору. Высоты учитывают мосты и путепровод.

## Трамваи и автобусы на линиях

Транспорт идёт по расписанию GTFS «Daugavpils satiksme» ([src/transit/transit.js](src/transit/transit.js)). Линии маршрутов в GTFS проведены от остановки к остановке прямыми (вершина в среднем через 100 м, до километра), поэтому срезают все повороты. Раньше каждый кадр нос и хвост вагона отдельно «прилипали» к ближайшему рельсу или дороге. На стрелках и перекрёстках точка перескакивала на соседний или поперечный путь, а где линия GTFS отходила от рельсов дальше 3,4 м (треть линий трамвая), вагон ехал мимо них.

- **Маршрут по сети модели** ([src/transit/route-match.js](src/transit/route-match.js)). При загрузке каждая линия GTFS один раз прокладывается по рельсам или улицам модели, как навигатор:
  - у каждой вершины (остановки) берутся места на сети в пределах 30–40 м, ближайшее от каждого пути в каждую сторону движения (иначе изогнутый путь у развязки занимал все места и соседний путь в выбор не попадал);
  - выбирается цепочка мест (скрытая марковская модель, алгоритм Витерби): место тем лучше, чем ближе к своей остановке, а шаг тем лучше, чем ближе путь между местами к прямой между остановками;
  - путь между местами — кратчайший по сети (Дейкстра по направленным рёбрам) без поворотов круче, чем может вагон: трамвай — до 75°, разворот только в тупике; автобус разворачивается лишь за «цену», на конечных.
- **Починка сети.** В `citydata.js` линии упрощены, и у сквозной улицы иногда пропала общая с примыкающей вершина: 1 454 конца дорог лежали на соседней улице без соединения. Такой конец врезается в отрезок, на котором лежит (в пределах 0,6 м). Дороги, пересекающиеся на одном уровне (не мосты), соединяются в точке пересечения.
- **Где в сети разрыв**, вагон идёт плавной дугой по направлениям путей на обоих концах; вне сети — прямо. У трамвая разрывов нет; у автобуса осталось 7 мест: улицы внутри крепости, линия за краем карты и пара коротких.
- **Трамвай — по правому пути.** Путь, справа от которого идёт параллельный, считается встречным. Против хода по нему идёт 0,4 % длины маршрутов (на конечных и в петлях).
- **Автобус — в правой полосе:** на двусторонней улице на полпути к бордюру, на проезжей части пары — в крайней правой полосе. Против направления такой проезжей части ехать можно, но «дорого»: на случай, если пара распознана неверно. Где модель доводит конец пары прямо, автобус идёт по нарисованному асфальту. Повороты сглажены на ±7 м.
- **Итог:**
  - трамвай стоит на рельсах в 99,9 % точек пути (раньше у трети точек расхождение было больше 3,4 м);
  - автобус идёт в 1,9 м от оси дороги, дальше 4 м — 0,7 % точек, в основном в крепости и за краем карты (раньше 11 % точек были дальше 8 м от дороги);
  - пути всех 109 линий строятся около секунды.
- **Обе тележки** вагона (и обе секции сочленённого трамвая) стоят на одном пути, кузов — хорда между ними.
- **Ход.** На остановке вагон стоит (до 20 с при перегоне длиннее 40 с). Потом разгоняется не круче 0,9 м/с² (трамвай) или 1,1 м/с² (автобус), едет с постоянной скоростью и так же тормозит. Ускорение нарастает и спадает плавно. Если по расписанию времени мало, половину перегона вагон разгоняется, половину тормозит.
- **Остановки** стоят у бордюра справа по ходу, вдоль дороги и открыты к ней:
  - у автобуса — в 2,4 м за бордюром той улицы, по которой проложен маршрут;
  - у трамвая — за бордюром улицы, в которой лежит путь, а на обособленном полотне — в 2 м от пути.

  Если на месте павильона дом или другая проезжая часть, он сдвигается вдоль бордюра до 8 м, иначе ставится только столб со знаком. Раньше павильон вставал у ближайшей дороги, а ею у перекрёстка бывала поперечная, при этом повёрнут он был по прямой линии GTFS. Поэтому павильоны стояли развёрнутыми.

## Высоты и крыши зданий по лидару

Высота дома раньше бралась из этажности (OSM или кадастр, этаж около 3 м), а форма крыши — двускатная или вальмовая — выбиралась по контуру со случайностью. Теперь у большинства зданий и то и другое измерено: по облакам точек аэролазерной съёмки LGIA 2013–2019 (CC0, тайлы LAS 1 × 1 км; где их брать — в [docs/tools-and-sources.md](docs/tools-and-sources.md)). Данные — [lidar.js](lidar.js), инструмент — [tools/lidar.js](tools/lidar.js), применение — [src/buildings/lidar.js](src/buildings/lidar.js) и `buildBuildings`.

Как считается (для каждого здания `citydata.js`):

- **Точки.** Точки класса «здание» внутри контура (в LKS-92, `tools/lks92.js`), при перекрытии контуров — в меньшем. Земля — средняя высота точек земли в клетках 4 м в 2–7 м снаружи стен, медиана.
- **Форма крыши** подбирается методом наименьших квадратов в осях повёрнутого прямоугольника контура:
  - плоская;
  - двускатная с коньком вдоль длинной стороны или поперёк;
  - вальмовая;
  - рамочная — скаты от карниза до плоского верха в 1,5–10 м от стен, как у больших кварталов.
  
  Контуры OSM и кадастра часто захватывают крыльцо, пристройку или полосу двора, поэтому конёк может уходить от середины до 60 % полуширины. Скатная форма берётся, если она поднимается от карниза хотя бы на 1 м и подходит лучше плоской хотя бы на 0,1 м (среднеквадратично), или на 0,7 м и 0,2 м. Если ни одна форма не подходит точнее 1,2 м, крыша считается сложной.
- **Высоты над землёй:** карниз (где скат встречает стены; у плоской крыши — медиана её точек) и верх (конёк или плоский верх подобранной формы, а не перцентиль, куда попали бы трубы).
- **В модели:** стены до измеренного карниза; при разнице больше 2,5 м этажи масштабируются вместе с высотой. Крыша нужной формы, уклон подобран так, чтобы конёк был на измеренной высоте; двускатная поперёк поворачивает прямоугольник. Не трогаются храмы, части зданий на других частях, ориентиры и типовые 5–9-этажки со своими моделями. Казармы и склады крепости, которые рисует `buildBuildings`, измеренные высоты и крыши получают; здание, которое забирает себе модуль крепости, — нет. Мелкая постройка, которую лидар счёл плоской, сохраняет скатную крышу.
- **Итог по городу.** Измерено 37 106 зданий из 48 594 (у остальных, в основном мелких построек, слишком мало точек). Формы крыш: плоских 16 816, двускатных вдоль 9 419 и поперёк 6 950, вальмовых 2 218, рамочных и сложных 1 703. Высоты карнизов в среднем совпали с прежними оценками (медиана разницы по типам домов от −0,4 до +0,3 м); дома, ошибавшиеся больше чем на 3 м, — около 1 100 из 37 тысяч.
- **Сверка.** `lidar.js` хранит число зданий и ключ `citydata.js`; если `citydata.js` пересобран без него, страница пишет предупреждение и строит дома по-старому.

Пересобрать (около 35 минут: 157 тайлов, около 30 ГБ скачивания потоком, на диск ничего не пишется):
```bash
node tools/lidar.js lidar.js
```

## Типовые советские 5–9-этажки

Около 340 жилых домов — типовые проекты 1960–80-х. Они распознаются по контуру и этажности и рисуются секциями настоящего ритма, а не общими ячейками окон (`serBuild`, `seriesAtlas`, `seriesMaterial` в [src/buildings/series.js](src/buildings/series.js)). Фасады показаны такими, какими были построены, до утепления.

Длину секции дали сами контуры. 5-этажки глубиной 10,5–12,5 м встречаются длиной 48, 64–65, 80, 96 и 128 м, то есть 3, 4, 5, 6 и 8 секций по 16,1 м. Облик снят с фото из категории Wikimedia Commons *Apartment buildings in Daugavpils*: Stadiona iela 4, Cietokšņa iela 55A, Andreja Pumpura iela 55, Krišjāņa Valdemāra iela 5, Nometņu iela 25.

- **k5** (282 дома): 5-этажный дом из силикатного кирпича.
  - На одной стороне подъезды с козырьками, дверями и ступенями, над ними лестничные окна между этажами.
  - На другой стороне пары колонн балконов (часть застеклена) или одни окна.
  - На торце колонка окон, водостоки на стыках секций.
  - Низкая двускатная или плоская крыша с парапетом, по признаку из кадастра.
- **p5** (48): 5-этажный панельный дом глубиной 13–17 м: швы панелей, лоджии во всю длину с перегородками и выборочным остеклением.
- **n9** (17): 9-этажный панельный дом. Его длина кратна секции 25,9 м: 26, 52, 78 и 104 м. На подъездной стороне лестничные окна, на другой — по две колонны лоджий на секцию с ребристыми экранами, часто красно-коричневыми. На крыше машинные отделения лифтов.
- **t9** (9): 9-этажный кирпичный дом из секций около 19 м: колонны балконов, на части домов красные экраны.

Атлас хранит одну секцию на один этаж: первый, типовой и верхний этаж каждого фасада и торец. Шейдер повторяет ячейки по секциям и этажам, ночью зажигает окна вразнобой. Цвет кирпича или панелей берётся из палитры серии. Какая сторона подъездная, а какая балконная, выбирается случайно: в данных этого нет.

Для домов, проверенных по фото (пока это Химия, см. [«Химия»](#химия-ķīmiķu-ciemats)), шейдер умеет больше:
- стена из панелей с каменной крошкой (зерно гаснет вдали, швы панелей) или ровная штукатурка утеплённого дома вместо нарисованного кирпича;
- красно-кирпичные пояса на уровне перемычек и подоконников;
- остеклённая лестничная клетка над подъездом, от козырька до крыши, ночью светится.

Геометрией добавляются кирпичные пилястры через полсекции, выше парапета, и красные торцы. Г-, П-образные и ступенчатые корпуса режутся на прямоугольные крылья глубиной 10,3–18,5 м. Торцов на стыках нет, куски на стыках закрыты глухими вставками.

## Озеро Губище и Aizpilsētas parks

**Озеро Губище** (Gubiščes ezers, relation [6865444](https://www.openstreetmap.org/relation/6865444)) — цепочка из трёх плёсов между Химией и 18. novembra iela, наполовину заросшая. В OSM парк отмечен только точкой без границ, поэтому в [tools/parks.js](tools/parks.js) появился список таких парков с контуром из соседних полигонов OSM (лес западной части и луг набережной). Парк рисует общий модуль парков: 32 дорожки с фонарями вдоль мощёных, 18 лавок, 15 урн, два стола для пикника с мангалами, велопарковки, детская площадка, площадка для собак, памятный камень (2013) и статуя. Кроме того:
- **набережная** (way 366853568, 2022): 4,2 м, серая плитка для пешеходов и красная полоса для велосипедов со стороны озера;
- **«Kuģītis»** («Кораблик»), инсталляция Ингуны Левши у северного конца озера: белый корпус с мачтой и парусом на стальном каркасе, синяя полоса вдоль борта, ночью светится изнутри.

Посмотреть: настил с востока (около Smilgu iela), набережная с велодорожкой от смотровой площадки на север, «Кораблик» ночью, озеро сверху с юга.

## Деревья по лидару

Вне лесов деревья стоят там, где их нашла аэролазерная съёмка LGIA, той высоты и с той шириной кроны, что измерены. Данные — [lidar-trees.js](lidar-trees.js), инструмент — `tools/lidar.js --trees` (тот же проход по тайлам, что и для зданий), расстановка — `buildTrees` в [src/world/trees.js](src/world/trees.js).

- **Поиск.** По каждому тайлу строится модель высоты растительности с шагом 1 м: самая высокая точка средней и высокой растительности над землёй.
  - Съёмка весенняя (центр — 13 мая 2017 года), лиственные кроны редкие, поэтому пустые клетки закрываются наибольшим из соседних 3 × 3.
  - Дерево — вершина от 4 м, наибольшая в окне 3–5 м, с хотя бы 0,35 точки растительности на м² вокруг; реже — это столб, провод или куст.
  - Крона идёт по восьми направлениям (до 14 м), пока высота не упадёт ниже 55 % или не начнёт расти к соседней кроне. Старые деревья Дубровинского парка — 24–29 м в высоту, радиус кроны 8–10 м.
  - Дерево, разрезанное стыком тайлов, остаётся один раз. Деревья в лесах `citydata.js` отброшены: леса страница сажает сама.
- **Не деревья.** Классификация съёмки относит к растительности и края крыш, балконы, выступы стен. Такие «вершины» яркие (интенсивность отражения от 60), почти все точки у них — единственное отражение импульса, точек вокруг мало, и стоят они в 1–2 м от стен. Они отбрасываются: в центре это почти половина найденного, по городу — пятая часть.
- **Порода.** В данных её нет; она определяется по точкам середины кроны (`kindOf` в инструменте), правила подобраны на деревьях известной породы: старых лиственных Дубровинского парка, елях у площади Единства и сосновом лесу у Стропских озёр.
  - В мае лиственные кроны голые или только зеленеют: точки тусклые (интенсивность 20–28), единственных отражений меньше 12 %. Хвоя ярче (30–55), единственных отражений 12–45 %, и крона не шире половины высоты — **хвойное**.
  - У ели крона спускается до земли, точки в среднем ниже 0,66 высоты — **ель**, иначе **сосна**. Из 10 елей у площади Единства елями опознаны 9.
  - Лиственная крона посередине (уже в листве: ярче или чаще единственное отражение) и не шире 0,45 высоты считается **берёзой** — она зеленеет первой; среди них будут и тополя, ивы. Остальные — **лиственные**.
- **Итог по городу** (157 тайлов): найдено 402 864 вершины, 216 396 из них в лесах и 4 910 за краем карты, 34 466 — не деревья. В файле 147 092 дерева: 114 601 лиственное, 18 972 берёзы, 8 504 сосны, 5 015 елей (1,18 МБ, 6 байт на дерево). В Дубровинском парке — 42 лиственных, 7 берёз и одна ель высотой около 24 м с кронами радиусом около 8 м; у Стропского озера две трети деревьев — сосны.
  - Интенсивность в разных тайлах (разные полёты и годы) в разной шкале: по тайлу её приводят к тому, что голые лиственные кроны (плотные, почти без единственных отражений) дают в среднем 24.
- **В модели.** Модель нужной породы растягивается до измеренной высоты и радиуса кроны.
  - С лидарными деревьями уходят угаданные: деревья OSM, ряды деревьев парков и деревья, разбросанные по классам земли, кроме лесов и кустарника.
  - Деревья, поставленные ориентирами вручную (ели у площади Единства, газоны магазинов), остаются; лидарное дерево ближе 4 м к такому уступает.
  - **Место в модели** (`treeRoom` в [src/world/tree-room.js](src/world/tree-room.js)). Лидар находит дерево по вершине кроны, а улицы, дорожки и площадки модели нарисованы шире или чуть в стороне от настоящих, контуры домов тоже неточны, и кроны в модели круглые, хотя настоящая растёт прочь от стены. Поэтому:
    - ствол не ставится в дом, на улицу с тротуарами, пешеходную дорожку, грунтовку, рельсы и трамвайные пути (не ближе 0,6 м к их краю), на спортивную и детскую площадку и стоянку (не ближе половины радиуса кроны к краю, чтобы над ними нависало не больше половины кроны; дерево глубоко внутри стоянки остаётся на газонном островке, см. [«Стоянки»](#стоянки)). Его выталкивают кратчайшим путём, всего не дальше 2,5–5 м (60 % радиуса кроны) от места, где его увидел лидар, иначе дерево не ставится;
    - крона не входит в стены: ствол отходит от ближайшей стены на 0,85 радиуса кроны в пределах того же сдвига, а если места всё равно мало, крона сужается — не больше чем вдвое, иначе дерево не ставится (оно стоит вплотную к дому или между двумя домами).
  - По городу так сдвинуто около 20 тыс. деревьев, сужено около 2 тыс. крон, не поставлено около 11 тыс. (раньше не ставились только деревья внутри домов и глубоко на проезжей части). Счётчики — `window.__city.treeStats`.
- **Кроны сосен не мерцают.** Крона — облако карточек хвои с атласом листвы 2 × 2, номер ячейки атласа приходит в шейдер интерполированным и бывает на волос меньше целого (2,9999998 вместо 3). `mod`/`floor` от такого числа уводили хвою сосны в ячейку за краем атласа: карточка или её половина пропадала и возвращалась от малейшего качания ветра или движения камеры, в том числе в карте теней. Теперь номер округляется (`LEAF_GLSL` в [src/world/trees.js](src/world/trees.js)); задевало это только ячейку сосны.
- **Хвойные проработаны** (`treeGeo` в [src/world/trees.js](src/world/trees.js)). Раньше ель была редким конусом из карточек-«звёзд» с просвечивающим стволом, а сосна — шаром хвои на гладком столбе. Теперь:
  - **Ель** — мутовки поникающих ветвей: вдоль каждой от ствола к концу идёт ряд карточек хвои (к основанию крупнее и темнее, на конце мельче и с наклоном вниз), у самого ствола ещё по карточке на ярус, чтобы он не просвечивал. Ярусы неровные по высоте и радиусу, силуэт лохматый, конусовидный, вершина — узкий шпиль. Ветви — настоящие tapered-лимбы, а не только карточки.
  - **Сосна** — открытая крона из отдельных плоских «подушек» хвои на раскидистых ветвях, между ярусами видно небо (просветы задаёт геометрия, а не дырки в текстуре). Ствол голый внизу, кора плавно переходит от серо-бурой к оранжевой по высоте (градиент в `solid`, без резких колец), несколько сухих сучков. Верх кроны — пара мелких подушек и лидер.
  - **Атлас хвои**: ячейка сосны — мелкие сизовато-зелёные иглы вдоль частых веточек, сплошной массой (не радиальные «звёзды»); ячейка ели — густые короткие иглы по обе стороны веточки со светлой молодой приросткой на конце.
  - **Кора стволов** — как у берёзы, фотографическая текстура поверх цвета вершин (`uBark`/`uBarkPine`/`uBarkSpruce` в [src/world/trees.js](src/world/trees.js); номер породы в `aCard.z` округляется в шейдере, чтобы интерполяция не уводила кору к соседней породе). Сосна — высокие плиты с глубокими вертикальными трещинами и тонкими горизонтальными слоями отслоения; ель — мелкие неправильные чешуйки, чуть выпуклые, с тёмными зазорами. Обе текстуры нейтрально-серые и бесшовные: оттенок ствола даёт цвет вершин (у сосны — градиент от серо-бурого к оранжевому). Генератор — `tools/gen-bark.py` (`textures/bark_pine.webp`, `textures/bark_spruce.webp`); повтор вокруг ствола целый, чтобы шов сходился. Лиственное дерево коры-фотографии не имеет.
  - Ветер, карта теней и impostor-бейк дальних деревьев берут ту же геометрию; округление ячейки атласа (фикс мерцания) не тронуто. Производительность почти не изменилась: деревья инстансированы, и карточки крон — малая доля треугольников кадра.
- **Перенастройка пород** без новой закачки тайлов: прогон с `--raw trees-raw.bin` сохраняет все найденные вершины с их признаками (высота, радиус, плотность, высота точек, интенсивность, доля единственных отражений), а `node tools/lidar.js --from trees-raw.bin --trees lidar-trees.js` заново сортирует их по `kindOf` за секунды.

## Деревья и вода

Деревья не ставятся в воду: ни в водные полигоны (реки, озёра, пруды в опущенном русле) ближе 1,2 м к урезу, ни на ленты ручьёв. Для скорости используется растровая маска воды с ячейкой 4 м; точная проверка делается только у берегов.

**Вода** — по воде игры [nikolajevs/game](https://github.com/nikolajevs/game) (`public/js/gfx/water.js`), без лишних проходов отрисовки. Код: [src/world/water.js](src/world/water.js).

- **Рябь**: две копии карты нормалей бегут навстречу друг другу. Карта — текстура игры [textures/water_normal.webp](textures/water_normal.webp), её делает `tools/gen-textures.mjs` игры.
- **Небо** отражается по углу взгляда (Френель): тот же градиент, свечение у солнца и облака, что на небе города. По ряби играют блики солнца.
- **Цвет толщи** по глубине: зеленее у берегов, тёмно-сине-зелёный на стрежне.
- **Подстроено под реку и озёра**, а не под море игры: рябь в метрах (около 34 и 13 м) плывёт со скоростью около трети метра в секунду, цвета темнее, нет прибоя и зыби, ночью вода тёмная.
- **Глубина** — это расстояние до берега: поле расстояний на сетке 8 м, до 64 м, сглаженное. Клетка считается водой, если её центр лежит в водоёме: так поле отсчитывается от самого уреза. Игра брала глубину из карты острова.
- **Берег мягкий.** Над мелководьем вода полупрозрачная, как в игре, а от уреза проявляется на первых 3,5 м. Видимый край идёт по гладкой линии поля расстояний, а не по прямым сторонам и углам контура OSM. Стенки берега рисуются только там, где земля выше воды больше чем на 0,8 м: у низкого берега стенка лишь обводила контур тёмной линией.
- **Рвы крепости** не входят в маску воды, поэтому вода в них считается в 6 м от берега.
- **Мелкие и узкие водоёмы** — пруды в парках, копанки, узкие протоки — сетка 8 м не берёт: вода в них почти не проявлялась бы. Если вода проявляется полностью меньше чем на половине площади водоёма, он считается, как рвы крепости, в 6 м от берега. Так рисуется 357 водоёмов из 408 (0,4 км² из 10,8), в том числе пруд Дубровинского парка и кольцевой пруд у Эспланады.

## Рельеф

Город не плоский. Высоты земли — цифровая модель рельефа Латвийского агентства геопространственной информации (LGIA): голая земля по аэролазерному сканированию 2013–2019 годов, сетка 20 м, система высот LAS-2000,5, открытые данные ([data.gov.lv](https://data.gov.lv/dati/lv/dataset/digitlais-reljefa-modelis-ar-tkla-soli-20m)). В отличие от спутниковых моделей в ней нет леса и крыш, и русло Даугавы, насыпи и выемки дорог, овраги лежат на своих местах. Данные лежат в [terrain.js](terrain.js). Перепад по городу около 60 м: вода Даугавы — 88–89 м, центр — 93 м, Церковная горка — 108 м, Химия — 117 м, возвышенность к югу от Гривы — до 150 м.

- **Привязка сетки.** Координаты в файле LGIA сдвинуты на одну ячейку. Сверка с OpenStreetMap дала один и тот же сдвиг по трём независимым признакам: по рвам крепости, руслам ручьёв и воде вдоль берегов (сдвиги 18–20 м на восток и 20–22 м на юг). Поэтому каждый узел читает сетку на 20 м восточнее и южнее своего места (`LGIA_SHIFT` в [tools/terrain.js](tools/terrain.js)). Без этой поправки выемка Latgales iela лежала в 20 м от дороги, а рвы и берега были сдвинуты на столько же.
- Каждая вершина поднимается на высоту земли под ней прямо в шейдерах three.js (общие куски `project_vertex` и `worldpos_vertex`, в том числе в материалах теней), так что за рельефом следуют земля, улицы, деревья, фонари, трамваи и автобусы.
- **Вода** лежит на своём уровне: в модели это самая низкая земля вокруг, поэтому поверхность реки или озера в каждой точке — минимум высот в радиусе 50 м; берега спускаются к ней откосом.
- **Железная дорога** идёт ровным профилем: на сетке 20 м узлы попадают то на полотно, то на откос насыпи или бровку выемки, и высоты вдоль пути скачут на метры. Для каждого пути строится профиль (медиана высот по ±70 м, среднее по ±150 м, уклон не круче 1,2 %), сетка в 10 м от пути получает его, а к 30 м плавно возвращается к рельефу — получаются насыпь или выемка. Мосты не трогаются.
- **Улицы на дамбах** — прежде всего Daugavas iela на противопаводковой дамбе вдоль Даугавы у Эспланады и к востоку от моста Единства. На сетке 20 м узлы попадают то на гребень, то на откос, и улица прыгала по высоте на 2–3 м через каждые несколько десятков метров, а поперёк кренилась до 2 м. Если вдоль улицы с обеих сторон в пределах 15 м идут линии насыпей OSM (дальше 40 м от мостов), она получает профиль гребня: самая высокая земля в 6 м поперёк, медиана и среднее по ±60 м, уклон не круче 3 %. Сетка в 14 м от оси берёт этот профиль и к 34 м возвращается к рельефу. Получаются ровный гребень и откосы к реке и к городу.
- **Насыпи из OSM** (`man_made=embankment`) уже есть в рельефе: лидарная модель — это голая земля. Поэтому они не рисуются ещё раз. Раньше на линии, которую OSM проводит по верхней бровке, вставал гребень высотой 3 м и шириной 10 м. На дамбе Daugavas iela два таких гребня стояли стенами по сторонам улицы и закрывали проезжую часть. Без рельефа гребни рисуются, как прежде.
- Обычные дома стоят ровно, на самой низкой точке своего контура; на склоне их цоколь уходит в землю.
- Мосты держат прямой настил от высоты одного берега до другого; Vienības tilts сохраняет свой изгиб над серединой, опоры доходят до воды.
- Земля разбита на треугольники там, где рельеф изгибается. Треугольник делится по длинной стороне, пока не ляжет на рельеф с точностью 0,35 м (вода — 0,4 м; `subTris` в [src/world/terrain.js](src/world/terrain.js)). Проверка точная: берутся все узлы сетки 20 м внутри треугольника и каждая сторона целиком. Раньше смотрели только середины сторон. Такая проверка пропускала бугор внутри большого треугольника: земля проходила под ним на 2–4,5 м ниже, и деревья, фонари и дома стояли выше нарисованной земли. Глубокая сетка глубины (ниже) прятала такую землю: например, тёмный клин на траве восточнее крепости, у (−1982, −397). Заодно старая проверка делила ровную землю из-за шума. Треугольников столько же, сколько было (≈0,5 млн у базовой земли и столько же у участков), плюс «зелёные» половинки конформного прохода (ниже). Сторону, которую соседний треугольник поделил пополам, целый треугольник за ним тоже получает через середину («зелёное» дробление, без новых точек): иначе стык T-образный — целая сторона провисает до 0,35 м ниже середины, которую несёт поделенная сторона соседа, и с низкой камеры в субпиксельную щель просвечивает нижний слой земли светлой полосой-«разломом» на травяном откосе (например, у ж/д моста со стороны Lielā iela, взгляд с (−2754, 490) на северо-запад). Проход даёт каждой целой стороне середину, которую уже несёт сосед; дети наследуют остальные помеченные стороны, три помеченные стороны дают четыре треугольника. Новые стороны здесь — половинки и внутренние диагонали, которые никто не несёт целиком, поэтому одного прохода достаточно. Улицы, тротуары и рельсы ложатся на линии, которые `densify` дробит там, где рельеф изгибается. Здесь тоже теперь проверяется весь отрезок (`lineGap`), а не только середина, поэтому улицы больше не проходят под буграми. Слои земли рисуются без записи глубины, поэтому под ними две невидимые сетки глубины. Каждая клетка 20 м в них режется по той диагонали, при которой оба треугольника остаются под землёй. Первая, глубокая, рисуется до слоёв: холмы заслоняют землю за собой и отбрасывают тень. Она лежит на 0,5 м под землёй, а там, где маленький треугольник земли у острой бровки опускается ниже, — под ним. Раньше она лежала на 0,5 м ниже самого низкого соседнего узла, на склоне это метры вниз. Тогда улицы и участки за бугром, нарисованные позже, проступали сквозь его подножие, например у путепровода на 18. novembra iela (−181, 1436). Вторая лежит на 0,25 м под землёй и рисуется после слоёв. Эта сетка закрывает людей, деревья и дома за гребнем холма. Раньше их было видно сквозь склон, если смотреть снизу вверх, а игрок на вершине горки просвечивал сквозь неё. Обе сетки обходят воду, крепость (у неё своя земля), мелкую поправку у моста Единства и дорогу в выемке Latgales iela ([src/world/ground.js](src/world/ground.js)). Вода прозрачная, поэтому рисуется после всего непрозрачного, а в клетках с водой сеток нет. Раньше без сеток оставалась и каждая клетка, которой коснулся запас растра воды в 4 м, то есть полоса до 25 м от берега. Сквозь землю, дорогу и тротуар в этой полосе была видна река вдали, и край тротуара обрывался квадратами клеток. Так было на Daugavas iela на дамбе, у (−2173, 1402). Теперь сетки пропускают только клетки, которых вода касается на самом деле (растр 4 м без запаса, `WMASK.o`).
- **Ближняя плоскость камеры** подстраивается под поле зрения и форму экрана: её дальний угол всегда в 0,22 м от глаза. Раньше она стояла на 0,3 м, и при широком поле зрения (в игре до 100°) её углы уходили на 0,5–0,8 м. Игрок держится в 0,45 м от стены, поэтому взгляд вдоль стены или вверх по ней срезал стену и открывал то, что за ней. Высоко в полёте плоскость отодвигается дальше ради точности глубины ([src/game/loop.js](src/game/loop.js)).
- Крепость стоит на выровненной площадке с высотой окружающей местности.
- Пешеход поднимается в горку и спускается в низины; в полёте нельзя опуститься ниже 2 м над землёй. Приседание (C, удерживать) опускает взгляд с 1,7 до 1,1 м и замедляет ход до 1,8 м/с — работает и на прогулке, и в бою ([src/game/player.js](src/game/player.js)).

Пересобрать `terrain.js`: скачать и распаковать `DTM_Latvija_20m.7z` (≈400 МБ, внутри текстовый файл 4,7 ГБ, строки «восток север высота» в LKS-92 TM), затем
```bash
node tools/terrain.js citydata.js terrain.js --lgia DTM_Latvija_20m.txt
```
Запасной источник — AWS Terrain Tiles (EU-DEM, сглаженный; тайлы кешируются в папке):
```bash
node tools/terrain.js citydata.js terrain.js --tiles terrain-tiles
```

## Пешеходы

По тротуарам города ходят люди ([src/world/pedestrians.js](src/world/pedestrians.js)): те же модели мужчины и женщины Quaternius (CC0), что и в шутере, со случайной внешностью — причёска, цвет волос, борода. **Маршруты.** Каждый идёт по маршруту в точку за 200–450 м по сети пешеходных путей, кратчайшим путём:
- сеть — тротуары, дорожки и пешеходные улицы (по их линии) и улицы (по тротуару, справа по ходу: полширины проезжей части и ещё 1,2 м);
- точки ближе 0,5 м — один узел: пути OSM сходятся в общих точках на перекрёстках;
- улица стоит чуть дороже дорожки, так что где есть дорожка, идут по ней;
- углы маршрута срезаны по биссектрисе. Если точка тротуара попадает в дом или воду, человек идёт ближе к оси.

Дойдя, человек берёт следующий маршрут оттуда, чей первый шаг не ведёт назад; обратно — только из тупика. Поворачивает плавно. Раньше люди ходили взад-вперёд по одному отрезку улицы: разворачивались без причины каждые 6–16 с и пропадали в конце отрезка. И шли спиной вперёд: модель человека повёрнута на пол-оборота внутри своего корня (файл смотрит в другую сторону), а пешеходу угол писали прямо в этот корень и стирали поворот. Теперь человек стоит в своей группе, которую и поворачивают, как модель игрока.

Число зависит от кадров в секунду (до 10 при бодрых кадрах, 7 и 4 при просадках) и времени суток (ночью меньше половины). Вокруг игрока держится до 12 человек, дальше 160 м они скрыты, дальше 180 м — убраны. Новые появляются в 40–150 м от игрока на узле сети вне поля зрения: за камерой или дальше 90 м. Анимации — полный цикл ходьбы из `anims.glb`, скорость шага согласована с анимацией. В онлайн-игре пешеходов нет (чтобы не путать с игроками), в прогулке — есть. Модели грузятся вместе с городом (те же файлы, что и у игроков онлайн-шутера), поэтому пешеходы выходят на улицы с первой минуты прогулки.

## Карта города

Кнопка «Карта» (M) открывает карту на всё окно, мини-карта в углу — та же карта рядом с игроком ([src/ui/map.js](src/ui/map.js)).

- **Масштаб и сдвиг.** Колёсико (вокруг указателя), кнопки «+», «−», «Где я», «Весь город», клавиши + − 0 C и стрелки; карта сдвигается перетаскиванием, на сенсорном экране — пальцем, масштаб — щипком. От всего города до улицы в 6 точках на метр. Щелчок без сдвига, как и раньше, переносит туда (в игре — нет). Первое открытие показывает весь город, дальше карта открывается там, где её оставили.
- **Подписи.** Названия улиц стоят вдоль их самых прямых участков, по ходу улицы и не вверх ногами, одно и то же название — не чаще чем через 260 точек. Сначала главные улицы, потом остальные: второстепенные с 0,3 точки на метр, жилые — вблизи. Ещё на карте Daugava (у реки в данных нет названия, её середина задана точками), места из списка «Переместись» с точками и курсивом — именованные места данных города (с 0,45 точки на метр). Подписи не налезают друг на друга. Они расставляются для одного масштаба и при сдвиге едут вместе с картой; после смены масштаба или большого сдвига расставляются заново.
- **Под указателем** в шапке видно место, улицу или воду и координаты.
- **Вид.** Дороги с обводкой: главные — жёлтые, остальные — белые. Железная дорога вблизи с белыми штрихами, трамвайные пути красные, тропы и грунтовки пунктиром. Дома — с контурами вблизи, сараи светлее. Тоном выделены жилая и промышленная застройка, пашни, огороды, площадки и пешеходные площади. Есть ночная палитра (когда на стартовой карточке выбрано время суток «ночь»), масштабная линейка и легенда транспорта.
- **Живая.** Трамваи, автобусы, междугородние автобусы, поезда и игрок движутся по открытой карте. Вне игры 3D-картинка под картой не перерисовывается (остаётся последний кадр), поэтому карта двигается плавно и на слабой видеокарте.
- **Как рисуется.** Карта собирается из квадратов по 256 точек на уровнях масштаба через пол-октавы. Квадрат рисуется один раз и запоминается: мини-карта держит 20 квадратов, большая — 64 и сбрасывает их при закрытии. За кадр новых квадратов рисуется не дольше 10 мс, на месте ещё не готового показан квадрат вдвое грубее. Что попадает в квадрат, ищется по сетке участков, домов и линий с клетками 400 м. Линии одного класса рисуются одним путём.

## Онлайн-шутер: командный бой и «каждый сам за себя» на карте города

**Стартовая карточка по шагам** ([src/ui/start.js](src/ui/start.js)). Сначала только выбор из трёх больших кнопок: «Начать прогулку», «Тренировка с ботами», «Играть онлайн». Между выбором и служебными кнопками — строка «Время суток» (день, вечер, ночь): это настройка до начала игры, в самой игре время суток не переключается — кнопки «Время» в панели и клавиши N больше нет. Выбор запоминается в браузере (`dpils-time`), первый визит следует теме страницы (тёмная — ночь). Под ними «Настройки», «Моя статистика», «Таблица лидеров» и свёрнутый список клавиш «Управление». Настройки выбранного варианта открываются следующим шагом, с кнопкой «← Назад» (или Esc). Внутри шага поле появляется, только когда оно что-то значит:
- в тренировке сначала карта, потом режим, число ботов и сложность. «Команда» показывается только в командном режиме, «Где появиться» — только в открытом городе: на арене игрок появляется на своей базе;
- причёска и цвет волос — только для мужчины или женщины, борода — только для мужчины;
- в онлайне аккаунт, игрок и список серверов. Поле адреса спрятано под «Другой сервер» и раскрывается само, если список пуст или в поле стоит адрес не из списка; список опрашивается, только пока он на экране.

Выбрать тренировку или онлайн и заполнить поля можно, пока город ещё строится; кнопки «Тренироваться» и «Играть» включаются, когда он готов. Кнопка «?» в панели возвращает карточку на первый шаг с раскрытыми клавишами; строка времени суток при этом скрыта — время уже выбрано.

В шаге «Играть онлайн»: ник, команда (красные, синие или по балансу), место появления (любое из списка «Места» или случайное) и сервер. Игра — шутер от первого лица, до 16 игроков. Режим выбирает сервер переменной `MODE`: `team` (по умолчанию) — красные против синих, побеждает команда, набравшая 30 убийств; `ffa` — каждый сам за себя, побеждает первый, у кого 20 убийств. Через 10 с начинается новый раунд. Прогулка по городу осталась как была.

- **Управление:** WASD — быстрый шаг (лёгкий бег, 6 м/с), Shift — спринт (11 м/с), пробел — прыжок, C (удерживать) — присесть (тише шаги, точнее стрельба, ниже хитбокс), 1–5 или колесо мыши — автомат, дробовик, снайперская винтовка, пистолет и пулемёт, правая кнопка мыши — прицел (встроенный снайперский, коллиматор или оптика 8x, если установлены), Y — чат всем, U — чат команде (Enter и Shift+Enter в строке сообщения тоже), V (удерживать) — рация, мышь — прицел, левая кнопка — огонь (можно держать), R — перезарядка, G — граната (зажать ЛКМ — сила броска, отпустить — бросок), I — инвентарь, H — использовать аптечку, Tab — таблица очков, M — карта (без переноса), «Выйти из игры» — в панели внизу. Полёта, переноса по местам и списка мест в игре нет.
- **Оружие:** автомат-хитскан (магазин 30, перезарядка 1,8 с, тело 22 урона, голова 40, дальность 160 м) и дробовик (магазин 6, перезарядка 2,6 с, выстрел в 0,8 с раз, восемь дробин веером: тело 9, голова 16 за дробину, дальность 45 м, урон падает с расстоянием до 40 %). Пистолет (магазин 12, перезарядка 1,4 с, 6 выстрелов в секунду по одному нажатию, тело 20, голова 42, дальность 90 м, самый точный). Пулемёт (магазин 100, перезарядка 4,5 с, до 16 выстрелов в секунду очередью, тело 16, голова 28, дальность 140 м, разброс большой и быстро растёт в очереди, отдача невелика). Урон автомата, дробовика и снайперской — как выше. Снайперская винтовка (магазин 5, перезарядка 2,8 с, выстрел раз в 1,3 с, тело 70, голова 100, дальность 400 м): правая кнопка мыши включает прицел (поле зрения 66° → 20°, мышь медленнее, круглая маска), только из прицела и стоя на месте выстрел точный, с ходу и без прицела разброс большой; стены и рельеф останавливают пулю и на 400 м. Здоровья 100. Сервер получает от клиента луч каждой дробины и судит каждую сам; попадание в ноги берёт 75 % урона тела (см. «Хитбоксы»). После возрождения 2,5 с защиты. Погибший возрождается через 3 с: в любом месте списка, в случайном или рядом с товарищем по команде (выбор на экране смерти). По своим огонь не идёт: пули проходят сквозь товарищей. Выстрелы рассеиваются: чуть всегда, сильнее на ходу, на бегу, в прыжке и в длинной очереди, в приседе вдвое меньше; динамический прицел показывает разброс (см. «Прицел»). Убитый падает навзничь и лежит три секунды. Звуки: выстрел, попадание, попадание в голову, убийство, удар по вам.
- **Машины непроходимы.** Припаркованные машины (стоянки, зависят от времени суток) и стоящие (полиция, больница, площади) — твёрдые: игрока выталкивает из них ([src/game/player.js](src/game/player.js), `staticCarPush` в [src/world/cars.js](src/world/cars.js)), а пуля в них останавливается: капсула 0,95 м вокруг оси машины, высота 1,5 м ([src/world/car-hit.js](src/world/car-hit.js), стоянки подключают свой замер через `carProbes`). Игрок стреляет через `freePath(…, cars)`, чужие трассы с сервера (он машин не знает) обрезаются на странице. След попадания — тёмная отметина и 9 искр без пыли, звук — металл ([src/game/sfx.js](src/game/sfx.js), вид `'metal'`): два удара листа разной высоты, глухой гул кузова, иногда рикошет.
- **Хитбоксы** ([server/combat.mjs](server/combat.mjs) — `HIT`, `rayHit`; страница предсказывает попадания тем же кодом, [src/game/mp.js](src/game/mp.js)). Тело — не одна капсула, а части: голова — сфера радиусом 0,18 м с центром на 10 см ниже глаз, торс — капсула радиусом 0,25 м от шеи (26 см ниже глаз) до таза (половина высоты глаз над землёй), ноги — две капсулы радиусом 0,11 м, разнесённые на 26 см вдоль собственной оси игрока: пуля между ног пролетает. Ноги берут 75 % урона тела, голова и торс — как прежде (у автомата 40 и 22). Присед (высота глаз 1,1 м вместо 1,7) сжимает торс и ноги, голова сохраняет размер и опускается вместе с глазами; ноги поворачиваются вместе с игроком. Сервер проверяет на луче каждой дробины всех живых врагов и берёт ближайшее попадание, а не только названную клиентом цель; трасса обрывается у тела. Лаг-компенсация отматывает назад не только положение, но и высоту глаз с поворотом (сервер хранит секунду истории): цель, присевшая 150 мс назад, считается присевшей. Запас у стены — 5 см. Проверка без браузера — [tools/combat-test.mjs](tools/combat-test.mjs): 41 тест, включая настоящий бой ботов, гоняет CI.
- **Прицел** ([src/game/mp.js](src/game/mp.js) — `crossTick`, [src/style.css](src/style.css)). Четыре штриха с точкой в центре вместо одной точки; зазор между штрихами — настоящий разброс выстрела (`spreadNow`), переведённый в пиксели экрана через текущее поле зрения: растёт на ходу, в прыжке и в очереди, вдвое меньше в приседе, сглаживается за десятую долю секунды. У каждого ствола своя форма: автомат — штрихи 9 px, пулемёт — шире и толще, пистолет — короткий и узкий, снайперская без прицела — редкие тонкие штрихи (с ходу разброс большой). Дробовик вместо штрихов рисует кольцо диаметром в конус дроби (0,05 рад ≈ 46 px на экране высотой 600 px при поле зрения 66°; присед сжимает кольцо). Цвет предупреждает о магазине: янтарный, когда патронов не больше четверти или идёт перезарядка, красный — когда магазин пуст; в перезарядку вокруг прицела загорается кольцо-прогресс (SVG-дуга убывает по мере перезарядки). В снайперском прицеле обычный прицел скрыт, вместо него сетка duplex: толстые внешние лучи, тонкие нити с 12 метками mil-dot (шаг 6 vmin), красная точка в центре, блик стекла и тень ободка трубы. Настройки прицела — в панели настроек: шесть цветов (белый, зелёный, голубой, жёлтый, красный, розовый), точка в центре вкл/выкл, динамический разброс вкл/выкл (выкл — фиксированный зазор); хранятся в `localStorage` вместе с остальными настройками. Прицел не пропадает, когда открыты настройки или чат: снятие захвата мыши больше не прячет его в бою ([src/game/input.js](src/game/input.js)).
- **Гранаты** ([src/game/mp.js](src/game/mp.js) — `nadePrep`/`nadeAimTick`, [src/game/nades.js](src/game/nades.js), [server/game.mjs](server/game.mjs)). Две на жизнь. Клавиша G берёт гранату в руку (оружие прячется, руки достают гранату и выдёргивают чеку — как выглядит бросок, см. следующий пункт): мышь целится, светящаяся дуга и диск радиуса поражения на земле показывают, куда граната полетит и где взорвётся. Зажатая левая кнопка мыши набирает силу броска — две дуги вокруг прицела заполняются за 1,1 с от слабой до максимальной (скорость 6 → 24 м/с, на полной силе они горят и пульсируют, загорается «макс»), отпускание бросает с набранной силой; быстрый щелчок — слабый бросок под ноги. Правая кнопка или повторная G убирает гранату обратно (не тратя её), смена оружия, перезарядка, инвентарь, чат и смерть тоже отменяют замах. Бросок раз в 0,9 с, направление — по взгляду с небольшим подъёмом; граната падает, отскакивает от земли, крыш и стен домов и взрывается через 2,5 с. Урон в радиусе 8 м убывает линейно от 100 в центре до нуля, стена между взрывом и игроком гасит его, по товарищам урона нет, по себе вполовину. Полёт и взрыв считает сервер (шаг гранаты — `server/physics.mjs`, скорость броска клиент шлёт в сообщении `throw`, сервер ограничивает её 6–24 м/с; боты кидают со средней скоростью 15), страница рисует свою копию и по сообщению о взрыве ставит её туда, где она взорвалась; дуга прицела считается той же физикой, что и полёт. Как выглядит и звучит взрыв — через пункт. Число гранат — рядом с патронами. Летящая граната — готовая модель M67 со Sketchfab (CC-BY-4.0, `models/item_nade.glb`), в полёте она центрируется вокруг точки сервера; пока модель грузится, летит прежний шар-заготовка.
- **Бросок гранаты** ([src/game/viewmodel.js](src/game/viewmodel.js) — `nadePose`, [src/game/nades.js](src/game/nades.js) — прицел, полёт, рычаг; [src/game/mp.js](src/game/mp.js) — `nadeView`, `nadeAimTick`; жест у других игроков — `throwArm` в [src/game/avatar.js](src/game/avatar.js)). Гранату держат те же руки в перчатках, что и оружие: правая рука поднимает снизу M67 настоящего размера (модель карты разобрана на корпус и кольцо с чекой — `splitNade` в [src/game/props.js](src/game/props.js)), левая подходит, цепляет кольцо, выдёргивает чеку (тихий щелчок) и уходит с ней вниз из кадра. Пока зажата левая кнопка, бросок «заводится»: граната уходит назад за правое плечо в угол кадра, левая рука выходит вперёд к цели. Отпускание — хлёсткий мах вперёд, граната срывается с руки (своя летящая граната стартует прямо из руки и за десятую долю секунды переходит на траекторию сервера), рука уходит вниз и поперёк, оружие возвращается анимацией доставания. Прицел: дуга полёта на весь запал (2,5 с) — светящаяся лента из руки, сначала она изгибается из гранаты в руке на настоящую траекторию, по ней к цели бегут импульсы; цвет теплеет от янтарного к раскалённо-оранжевому с силой броска, у ленты тёмный кант, чтобы читалась и на светлой мостовой, а ширина растёт с расстоянием, так что на экране она всегда в несколько пикселей. После первого касания отскоки и качение — бледный пунктир, на месте касания маленькое кольцо; где лента прячется за домом, она просвечивает призраком. Там, где граната взорвётся, на земле, крышах и склонах лежит диск радиуса поражения (8 м): красный пунктирный обод медленно вращается, от центра к ободу бежит «сонарная» волна, в центре — метка прицела, над ней стоит мягкий световой столб, видный издалека. Справа от прицела — метры до точки взрыва. Ночью дуга и столб светятся (их подхватывает bloom). В полёте граната кувыркается через себя по ходу броска и катится по земле, за ней тянется тонкий след воздуха; в момент броска с неё слетает рычаг — стальная планка отлетает вправо вверх, падает, подпрыгивает и лежит несколько секунд. Другие игроки и боты при броске делают замах рукой из-за головы. Всё нарисовано несколькими заранее созданными мешами и пулами (лента, диск, столб, восемь следов, шесть рычагов), прицеливание только переписывает их вершины; шейдеры прогреваются вместе с городом. Без экрана фазы броска снимает [tools/shot-items.mjs](tools/shot-items.mjs) (`MP.nadePose` замораживает руки в нужном моменте).
- **Взрыв гранаты** ([src/game/nades.js](src/game/nades.js) — `blast`, свет и звук — `flashLit`, `deafen` в [src/game/mp.js](src/game/mp.js), `boomSound` в [src/game/sfx.js](src/game/sfx.js)). Взрыв осколочной гранаты нарисован так, как он выглядит на видео, а не огненным шаром. Сначала на несколько сотых секунды белая вспышка: она освещает улицу, стены и людей вокруг (единственный свет вспышек выстрелов на это время переезжает к взрыву, становится белым, потом оранжевым и дальнобойным, 45 м). Небольшой огненный шар выгорает за пятую долю секунды, во все стороны летят раскалённые осколки-штрихи. Ударная волна гонит по земле кольцо пыли, оно тормозит, клубится и оседает. Вверх летят комья земли (на дороге — серый щебень, на крыше — крошка кровли), крупные тянут за собой пыльный след, падают и миг лежат. Тёмное облако дыма с пылью вспухает, на мгновение светится изнутри оранжевым от огня, потом поднимается, сносится ветром на восток-юго-восток, сереет и редеет за 6–10 с, низкая пыльная дымка держится до 13 с. После взрыва на земле или крыше остаётся чёрное пятно гари с лучами копоти. Оно ложится по склону рельефа и гаснет за 45 с (одновременно не больше 10 пятен). Взрыв в воздухе (выше 1,3 м над поверхностью) земли не поднимает и пятна не оставляет. Дым освещается сценой как обычная поверхность: днём он серый, ночью тёмный, во вспышке рыжий. Его квады изогнуты как поверхность шара, поэтому у каждого клуба есть светлая и теневая сторона. Огонь, свечение и осколки ярче белого, их подхватывает bloom. Все частицы — два инстансированных меша (дым и огонь) с атласами, нарисованными один раз из шума; дым сортируется от дальнего к ближнему. В бою материалы не создаются, а программы шейдеров компилируются заранее, при прогреве города. Рядом со взрывом (до 32 м) камера вздрагивает, толчок гаснет за полсекунды и приходит с задержкой звука; при `prefers-reduced-motion` тряски нет. Белая вспышка на экране (до 14 м) полная, только если смотреть на взрыв, сбоку или со спины она слабее. Ближе 11 м после хлопка глохнут уши: весь звук игры уходит в низкочастотный фильтр и возвращается за 1–4 с, и звенит в ушах тихий писк 3,3–4,3 кГц, тем дольше, чем ближе. К записи взрыва добавлены эхо от домов и, ближе 70 м, стук падающих комьев земли (на дороге и крыше — щебня; после взрыва в воздухе стука нет). Урон по-прежнему считает сервер, это только картинка и звук.
- **Инвентарь** ([src/game/inventory.js](src/game/inventory.js), [server/game.mjs](server/game.mjs)). Клавиша I открывает тактическую панель снаряжения в стиле арена-консоли: пять карточек оружия с силуэтами, магазином по патронам и сравнительными полосами урона, темпа и дальности (щелчок по карточке или её клавиша берёт ствол в руки, полоса перезарядки тикает прямо в карточке), гранаты и аптечки со счётчиками и кнопкой лечения, здоровье, убийства/смерти и общий боезапас. R и G закрывают панель и сразу действуют, Esc — просто закрывает; на телефоне карточки перестраиваются в две колонки. Запас патронов у каждого ствола свой (автомат 90, дробовик 24, снайперская 15, пистолет 36, пулемёт 200), перезарядка черпает из него, а не из бесконечного магазина; пустой запас — ищите ящики. По карте разложены 18 предметов: ящики патронов (пополняют запас всего оружия), гранаты (до 3), аптечки (до 2, лечат 50 HP по клавише H), коллиматоры и оптика 8x (по одному каждого вида на игрока, считая установленный). Предмет подбирается автоматически, если пройти мимо (в пределах 1,7 м); подобранный возвращается на то же место через 25–60 с (патроны 25 с, гранаты 30 с, аптечки 35 с, коллиматор 45 с, оптика 60 с), в новом раунде все предметы на месте. Содержимое карманов считает сервер (магазины, запас, гранаты, аптечки, перезарядка и лечение) и шлёт клиенту; страница рисует предметы, подсказку о ближайшем и панель, а боты пользуют аптечки и перезаряжаются по тем же правилам. Число гранат и аптечек — рядом с патронами, запас каждого ствола — в слотах 1–5. Сами предметы — готовые модели со Sketchfab (CC-BY-4.0): советский ящик патронов, граната M67 и белый кейс-аптечка с красным крестом (`models/item_*.glb`, сборка [tools/items.mjs](tools/items.mjs), загрузка и клоны — [src/game/props.js](src/game/props.js)); пока модель едет, рисуется прежний предмет из боксов. Атрибуция авторов — в [models/README.md](models/README.md), проверка без экрана — [tools/shot-items.mjs](tools/shot-items.mjs).
- **Прицелы-предметы** ([src/game/viewmodel.js](src/game/viewmodel.js) — `SIGHT_MOUNT`/`placeScope`, [src/game/mp.js](src/game/mp.js), [server/combat.mjs](server/combat.mjs)). Коллиматор и оптика 8x лежат в городе как предметы (по три каждого, с кольцом-маркером, как прочие): подбор ходьбой кладёт прицел в карман, панель инвентаря ставит его на любое из пяти оружий и снимает обратно в карман; установленный прицел виден на стволе в руках и у других игроков. Правая кнопка мыши — прицеливание: коллиматор поднимает ствол к центру окна линзы (поле зрения 66° → 50°, вскидывается быстрее оптики), в центре красная точка, разброс втрое меньше (у дробовика конус уже на четверть); оптика 8x даёт поле зрения 10° и сетку duplex на любом стволе (руки прячутся, как у снайперской), точный выстрел только из прицела и стоя на месте. У снайперской без установленной оптики остаётся встроенный прицел 20°. Боты ставят подобранный прицел на ствол в руках. Модели со Sketchfab (CC-BY-4.0): открытый коллиматор с козырьком и труба 8x (`models/item_sight.glb`, `models/item_optic.glb`, сборка [tools/sights.mjs](tools/sights.mjs)); атрибуция авторов — в [models/README.md](models/README.md).
- **Наблюдатель.** После смерти камера смотрит глазами живого игрока — вид от первого лица включён по умолчанию: сначала убийцы, потом своих. Клавиша F или кнопка на экране смерти переключает «от первого лица ↔ из-за спины» (выбор запоминается в браузере); в виде от первого лица тело наблюдаемого скрыто, чтобы не закрывать обзор, camera стоит в его глазах и повторяет его взгляд. ← → или Q и E, либо щелчок меняют игрока. Слышно и метки считаются из точки наблюдаемого. Возрождение — кнопка или пробел (выбор места внизу экрана).
- **Настройки** (кнопка «Настройки», клавиша O в игре, кнопка на стартовой карточке): панель с табами «Игра / Графика / Звук / Прицел / Клавиши» — чувствительность мыши, поле зрения (в прицеле считается от него), качество графики (авто или фиксированный уровень, тот же выбор, что кнопка «Качество» в игре), громкость звуков, голоса и окружения отдельно, инверсия вертикали, прицел (цвет из шести, точка в центре, динамический разброс) и переназначение 20 клавиш, сгруппированных по назначению (движение, бой, общение); занятая клавиша меняется местами с прежним владельцем. Активный таб запоминается между открытиями, стрелки ←/→ переключают табы с клавиатуры; на телефоне таб-бар прокручивается, а содержимое таба скроллится внутри панели. «Сбросить всё» возвращает значения по умолчанию, не закрывая панель. Хранятся в `localStorage`, [src/game/settings.js](src/game/settings.js).
- **Подсказка по клавишам.** Первые 25 с первых двух игр внизу экрана полоса с главными клавишами (как их назначил игрок), потом только по просьбе: F1 или кнопка «Клавиши» открывают полную таблицу, там же клавиши, которых нельзя менять (мышь, Enter, M, Esc). Код — [src/game/help.js](src/game/help.js).
- **Итог раунда.** Раунд заканчивается, когда команда набрала нужное число убийств (30, `WIN_SCORE=…` меняет): всем приходит таблица раунда (убийства, смерти, попадания в голову, нанесённый урон, точность выстрелов) с лучшим игроком, победителем и отсчётом 10 с до нового раунда; потом счёт и статистика обнуляются. Статистику ведёт сервер.
- **Список серверов.** В шаге «Играть онлайн» вместо одного поля: список серверов с числом игроков, пингом и состоянием раунда (обновляется каждые 8 с, кнопка «Обновить»). Список — это сам сервер, с которого открыта страница (игровой сервер с `STATIC=dist` отдаёт и страницу, отвечает `/health` рядом с ней и сразу виден в списке под своим `SERVER_NAME` — кто открыл страницу хоста, тому не надо ничего вводить), [servers.json](servers.json) рядом со страницей (`{"servers": [{"name": "…", "url": "wss://…"}]}`, пуст по умолчанию), серверы, на которых игрок уже играл (запоминаются в браузере), `?server=wss://…` и на localhost локальный `ws://localhost:8787`. Щелчок по строке подставляет адрес, ниже можно ввести любой другой. У каждого сервера свой `SERVER_NAME=…`; список читает его ответ `/health` (с разрешением CORS). Страница на https не может открыть `ws://`, такие строки помечены «нужен wss://».
- **Тренировка с ботами, без сервера.** Шаг «Тренировка с ботами» стартовой карточки: карта (открытый город или арена), режим (команды или каждый сам за себя), сколько ботов (2–12) и сложность (лёгкая, средняя, трудная). Игра идёт целиком в браузере: те же правила, что на сервере, потому что это тот же код ([server/game.mjs](server/game.mjs)), которому страница даёт соединение «внутрь себя» ([src/game/local.js](src/game/local.js)), город — уже построенный (дома и рельеф). Работает на GitHub Pages сразу, не требуя ни сервера, ни сети.
- **Боты** ([server/bots.mjs](server/bots.mjs)). Бот — игрок без соединения: видит врага, только если тот в пределах его зрения (70, 100 или 130 м по сложности) и между ними нет дома; поворачивается к нему с ограниченной скоростью, ждёт время реакции (0,75, 0,4 или 0,2 с), стреляет очередями с ошибкой прицела своего уровня (хуже на ходу и вдаль), целится в грудь, иногда в голову — ошибка настроена под маленькие хитбоксы, выбирает оружие по расстоянию (дробовик вблизи, снайперская издалека, на трудной в середине пулемёт), в бою двигается боком и держит дистанцию оружия, раненый отходит, на средней и трудной иногда кидает гранату, после смерти возвращается сам. Ходит по маршрутам: поиск пути A* по сетке 4 м с запасом от стен, вода, река, пруды и рвы (рельеф ниже −2 м) считаются непроходимыми; по умолчанию идёт к базе врага. Судит выстрелы бота тот же код, что игроков: промахнуться он может.
- **Арены с базами команд** ([server/arenas.mjs](server/arenas.mjs)), девять штук: «Центр города», «Динабургская крепость», «Вокзал и Рижская улица», «Центральный парк», «Церковная горка», «Пороховка» (пруд), «Спидвей «Локомотив»», «Дворец культуры», «Грива, левый берег» (радиус 260–520 м). Для каждой проверено, что между базами красных и синих есть путь (поиск у ботов до 60 000 клеток: в «Центре города» от площади Единства до базы синих обход около 800 м). У арены круглая граница (за неё не выйти, на карте красная пунктирная окружность), у каждой команды базы (квадратики на карте): на них игроки и боты появляются, выбирая точку подальше от врагов, и в сторону середины арены; в режиме «каждый сам за себя» базы — просто точки появления. На экране смерти вместо списка мест «на своей базе» и «рядом с товарищем». Без арены город открыт и игрок появляется там, где выбрал.
- **Каждый сам за себя (`MODE=ffa`).** Каждый игрок — команда из одного: по всем можно стрелять и бросать гранаты, товарищей нет (нет рации «по всей карте», чата только команде, метки на карте у врагов только после выстрела, возрождения рядом с товарищем). Фигурки раскрашены по игроку, а не по команде; в углу «Вы: N · лидер: имя M · до 20», таблица очков по убийствам, итог раунда называет победителя. Сервер сообщает режим, арену и число ботов в `/health` и в приветствии, страница подстраивается; в списке серверов он подписан. `WIN_SCORE` по умолчанию 20 для `ffa` и 30 для `team`. Боты и арена есть и у выделенного сервера: `ARENA=center|fortress|station|park|church|pond|speedway|culture|griva`, `BOTS=6`, `BOT_LEVEL=easy|normal|hard` (боты занимают свободные места и уступают их живым игрокам).
- **Модель игроков.** Другие игроки — готовая анимированная модель солдата [models/Soldier.glb](models/Soldier.glb) (реалистичный оператор спецназа: каска с ПНВ, балаклава, разгрузка; голова в пропорции) с готовыми моделями оружия в руках: автомат — АК-47 из [fp_ak47.glb](models/fp_ak47.glb) (см. ниже «АК-47»), дробовик, снайперская, пистолет и пулемёт — из [fp_shotgun.glb, fp_sniper.glb, fp_pistol.glb и fp_mg.glb](models/README.md) (Sketchfab, CC BY 4.0, авторы и источники в [models/README.md](models/README.md)). Анимации стоит, идёт, бежит, прыжок и смерть выбираются по скорости движения и по сообщению об убийстве, ходьба и бег ускоряются вместе с игроком; руки всегда в позе «держит оружие», вспышка на стволе при выстреле. Оружие в руках игрока соответствует выбранному (оно передаётся в состоянии игрока). Шлем красится в цвет команды или игрока, куртка и штаны получают камуфляж: пятна трёх тонов этого цвета (красные в красно-бурых, синие в сине-серых, в режиме «каждый сам за себя» по цвету игрока). Узор считает шейдер по положению точки на теле в покое, поэтому при ходьбе и беге он сидит на теле, а не плывёт; текстур для него нет. Модель реалистичная: тело — «FSB Operator» SpatialNeglect, анимации — Mixamo-клипы fauze (Sketchfab, CC BY 4.0, атрибуции в [models/README.md](models/README.md)); собирается конвейером [tools/soldier.mjs](tools/soldier.mjs) с ретаргетом клипов на скелет оператора (тело — дельтой от rest-позы, руки клипа Carry — по абсолютной мировой ориентации). Модель грузится вместе с городом (2,7 МБ, автомат 3,7 МБ и четыре ствола по 0,2–1,4 МБ, люди Quaternius ~6 МБ — см. «Модели игроков и оружия грузятся с городом» ниже), так что с первого кадра игры все игроки и оружие в руках — готовые модели; простые фигурки и коробки остались только на случай, если файл не пришёл. Код — [src/game/avatar.js](src/game/avatar.js); `three/addons` (GLTFLoader, SkeletonUtils) приходят через import map. Попадания считаются по хитбоксам (см. «Хитбоксы»); присевший игрок приплюснут по высоте визуально, но голова в хитбоксе сохраняет размер.
- **АК-47** ([src/game/viewmodel.js](src/game/viewmodel.js), [models/fp_ak47.glb](models/fp_ak47.glb)). Автомат — модель с Sketchfab «FPS Character Animation Pack Ak-47» (Cristian David Duque Camacho, CC BY 4.0, автор указан на стартовой карточке и в [models/README.md](models/README.md)), ужатая [tools/fp-ak.mjs](tools/fp-ak.mjs) со 117 до 6 МБ.
  - **От первого лица** видны руки в перчатках и камуфляжной куртке, они держат автомат: правая на рукоятке, левая на цевье. Руки дышат на месте, качаются при ходьбе, при беге опускают автомат. При выстреле автомат отдаёт, при смене оружия руки берут его заново. Перезарядка идёт ровно столько, сколько в игре (1,8 с): анимация следует за ходом перезарядки, магазин встаёт на место к её концу. При повороте взгляда автомат чуть отстаёт и догоняет. Вспышка и дым — у настоящего дула.
  - **Поверх всего.** Руки висят на камере, но их глубина сжата в самую ближнюю тысячную долю буфера глубины: автомат не уходит в стену, у которой стоишь, и ближняя плоскость города (0,3 м) не срезает кисти. Свет, тени и туман на них те же, что в городе.
  - **У других игроков** автомат в обеих руках: приклад у правого плеча, ствол смотрит туда, куда смотрит игрок, вверх и вниз вместе со взглядом. Руки тянутся к нему двухзвенной IK (плечо — локоть — кисть): правое запястье к рукоятке, левое к цевью, ровно туда, где их держат руки из модели. Кисти мужчины и женщины поворачиваются так же, как у этих рук (по костяшкам пальцев), у солдата кисти остаются как в клипе. У убитого автомат падает вместе с правой рукой. Для них взят тот же автомат без рук, упрощённый втрое. Так же, обеими руками, они держат и остальное оружие (следующий пункт).
- **Оружие слотов 1–4** ([models/fp_shotgun.glb](models/fp_shotgun.glb), [fp_sniper.glb](models/fp_sniper.glb), [fp_pistol.glb](models/fp_pistol.glb), [fp_mg.glb](models/fp_mg.glb)). Дробовик Remington 870, снайперская СВД, пистолет Макарова и пулемёт FN Minimi — модели с Sketchfab (Andrei Milin, WillyG99, Martin Trafas, DJMaesen; CC BY 4.0, атрибуции в [models/README.md](models/README.md)), ужатые [tools/fp-weapons.mjs](tools/fp-weapons.mjs) до 0,2–1,4 МБ (WebP-текстуры, упаковка meshopt). Все в метрах: дуло вдоль +z, верх +y, рукоять в начале координат; загрузка — GLTFLoader с MeshoptDecoder (файлы упакованы `EXT_meshopt_compression`).
  - **В руках.** Их держат те же руки в перчатках, что и АК ([src/game/viewmodel.js](src/game/viewmodel.js), таблица `HOLD`). Автомат прячется, на его кость вешается выбранный ствол рукояткой в правую ладонь, и он живёт по клипам АК: дыхание, ходьба, бег, отдача, взятие в руки при смене оружия, перезарядка по её ходу.
  - **Хват как у АК.** Ладони стоят на каждом стволе там же, где руки модели держат АК (точки сняты с её геометрии). Правая ладонь — в 3,4 см справа от пистолетной рукоятки, сразу за её задним краем, на трёх пятых высоты, так что спуск в 9 см впереди. У дробовика правая обхватывает шейку приклада, у СВД — рукоять приклада с вырезом. Левая ладонь — в 2 см под цевьём и в 1 см левее его края, пальцы обхватывают цевьё снизу и сбоку. Раньше ладони ставились на середину ствола: кисть уходила внутрь, пальцы левой торчали над цевьём, а весь ствол стоял на 5 см правее автомата.
  - **Левая рука.** После клипа она переносится двухзвенной IK ([src/game/ik.js](src/game/ik.js)) на цевьё этого ствола: под цевьё дробовика, под деревянное цевьё СВД, под цевьё пулемёта перед коробом. Кисть сохраняет поворот из клипа, локоть — свой изгиб. Пока клип уводит руку от оружия (за магазином при перезарядке), перенос плавно гаснет. Цевьё дробовика дальше, чем достаёт рука, поэтому от первого лица дробовик отодвинут на 7 см назад (`draw`), а левое плечо выходит вперёд на оставшиеся 6 см, как у стрелка. Плечо за кадром, видна только рука на цевье.
  - **Пистолет** вынесен вперёд на вытянутых руках: правая кисть тянется к нему по IK, левая ладонь поддерживает основание рукояти снизу. Модель Макарова лежит в своём файле с креном 35° и стволом, опущенным на 30° вниз и вбок, как на подставке витрины. При загрузке [src/game/avatar.js](src/game/avatar.js) выравнивает её (`MODEL.gunAxes`: куда в файле смотрят ствол и левый бок). Вместе с ней встают на место вспышка у дула и подобранный прицел: он теперь стоит на затворе (`SIGHT_MOUNT`).
  - **Вспышка выстрела** — у дула ствола в руках.
  - **Другие игроки** держат их так же ([src/game/avatar.js](src/game/avatar.js), `heldGun`): приклад у плеча, правое запястье на рукоятке, левое на цевье или под правой рукой, ствол смотрит, куда смотрит игрок. Размер у всего оружия настоящий. Отодвигание дробовика (`draw`) их не касается, иначе приклад вылезал бы из спины.
- **Выбор персонажа.** В блоке «Играть онлайн» — «Персонаж»: солдат (по умолчанию), мужчина или женщина (модели Quaternius [models/humans/](models/humans/), CC0). Для мужчины и женщины открываются причёска (мужчине — короткая и пробор, женщине — длинные, пучки и короткая), цвет волос (тёмный, каштановый, русый, светлый, седой) и борода (мужчине). Выбор хранится в браузере вместе с ником и командой и передаётся серверу строкой `look` (например `m.1.2.1`); сервер проверяет формат и рассылает всем, боты получают случайную внешность. Причёски привязываются к тому же скелету по именам костей и красятся в выбранный цвет. Команда у людей обозначается кепкой и нарукавной повязкой цвета команды (кожу не перекрашиваем — модели текстурированные), оружие — в руке (`hand_r`), анимации: ноги свои, верх — «держит пистолет», в прыжке idle (Jump в наборе нет), смерть — полным клипом. Гражданские (пешеходы) — без кепки, повязки и оружия, полные клипы ходьбы.
- **Мировые координаты.** Страница поднимает вершины всех материалов на высоту рельефа (город строился ровным). Всё, что в игре ставится по настоящей высоте (игроки, трассы пуль, гранаты, взрывы, автомат в руках, чья позиция берётся от камеры), помечено `userData.noTerr` через [src/render/world-space.js](src/render/world-space.js) и подъёма не получает; иначе на холмах (Пороховка +20 м) они висели бы выше или ниже, чем надо.
- **Звук окружения** ([src/game/ambience.js](src/game/ambience.js)). В игре звук места, где стоит игрок, собирается в браузере из шума и нескольких осцилляторов, без файлов: ветер (сильнее на открытом месте), днём птицы на открытом месте вдали от улиц (в вечер реже), ночью тихо (сверчков нет), вода у Даугавы и прудов (до 70 м, чем ближе, тем громче), шум улицы с редкой проезжающей машиной (тон уходит вверх и вниз), гул города среди домов. Раз в 0,6 с по домам, рельефу и улицам вокруг считается, каким должен быть звук, и уровни плавно подтягиваются. Громкость: «Громкость звуков» × «Громкость окружения» (отдельный ползунок в настройках, 60 % по умолчанию).
- **Статистика игрока за всё время** ([src/game/stats.js](src/game/stats.js)): кнопка «Статистика» в панели и «Моя статистика за всё время» на стартовой карточке. Считается на этом устройстве (localStorage): убийства (в голову, по видам оружия, гранатой), смерти, убийств на смерть, выстрелы и точность, нанесённый и полученный урон, лучшая серия убийств без смерти, раунды и победы, лучший раунд, любимое оружие, время в игре; отдельная колонка «Тренировка» для игры с ботами. Сохраняется раз в 10 с, при смерти, в конце раунда и при закрытии страницы; сброс с подтверждением вторым нажатием. Сервер для этого сообщает урон в сообщении о попадании.
- **Таблица лидеров сервера** ([server/leaderboard.mjs](server/leaderboard.mjs), [src/game/leaders.js](src/game/leaders.js), [src/game/identity.js](src/game/identity.js)): кнопка «Лидеры» в панели и «Таблица лидеров сервера» на стартовой карточке. Без регистрации: браузер один раз делает случайный секретный ключ (localStorage `dpils.key`) и шлёт его при входе; сервер хранит только хеш, поэтому результаты привязаны к игроку, а не к нику, и чужой ник занять нельзя (тот, кто пришёл с другим ключом и тем же ником, станет «ник#2»). Сервер считает убийства, смерти, попадания в голову, выстрелы и точность, урон, раунды и победы, лучшую серию, время в игре; таблица за всё время и за неделю (ISO), сортировка по убийствам, К/Д (от 10 убийств), точности (от 100 выстрелов) и победам, внизу «Ваше место», если игрока нет в первых 50. Боты, тренировка в странице и вторая вкладка с тем же ключом в таблицу не попадают; чекбокс «Не участвовать в таблице лидеров» отключает отправку ключа. Хранится в JSON-файле (`LEADERBOARD=путь`, по умолчанию `server/data/leaderboard.json`, `LEADERBOARD=off` — без таблицы; сохраняется каждые 20 с и при остановке, забытые игроки с малым числом убийств удаляются через 4 месяца), отдаётся как `GET /leaderboard?period=all|week&sort=kills|kd|acc|wins&limit=50&me=<id>` (CORS, хеши наружу не отдаются). С аккаунтом (см. «Аккаунты: вход и регистрация») ключ выдаёт сервер, и результаты следуют за аккаунтом, а не за браузером.
- **Аккаунты: вход и регистрация** ([server/accounts.mjs](server/accounts.mjs), [src/ui/auth.js](src/ui/auth.js)). На стартовой карточке в блоке «Играть онлайн» — строка аккаунта и кнопка «Войти / регистрация»; страница входа и регистрации открывается поверх города в стиле стартовой карточки, а также прямо по адресу страницы с `#login` или `#register`. Аккаунт создаётся на выбранном игровом сервере: ник (2–16 символов, правила ника игры) и пароль (от 6 символов, хранится только как scrypt-хеш с случайной солью). Сервер выдаёт аккаунту секретный ключ — тот самый, по которому таблица лидеров узнаёт игрока: с ним результаты и ник следуют за аккаунтом в любой браузер, а ник принадлежит аккаунту. Ключ и ник хранятся в браузере (`dpils.account`), при входе в игру ключ отправляется серверу, поле «Ник» подставляется из аккаунта. «Выйти» возвращает гостевой режим: браузер снова делает свой случайный ключ (`dpils.key`), играть без аккаунта можно как раньше. Поле «Сервер» предлагает серверы из `servers.json` и запомненные; аккаунт действует на том сервере, где создан. Защита: один ответ на неверный ник и неверный пароль, не больше 30 попыток входа или регистрации за 10 минут с одного адреса, CORS для страницы на другом адресе (GitHub Pages). Эндпоинты: `POST /auth/register` и `POST /auth/login` (`{name, pass}` → `{ok, name, key}`), `GET /auth/me?key=…` (проверка ключа при загрузке страницы). `ACCOUNTS=путь` меняет файл (по умолчанию `server/data/accounts.json`), `ACCOUNTS=off` выключает аккаунты; файл сохраняется каждые 20 с и при остановке, как таблица лидеров. Старый сервер без `/auth` страница понимает по ответу 404 и предлагает играть без аккаунта.
- **Оформление интерфейса игры — «Арена-консоль»** ([src/style.css](src/style.css), последний блок «game interface, third pass: the arena console», разметка в [index.html](index.html), наполнение — `updatePanel` в [src/game/mp.js](src/game/mp.js)): всё боевое чтение собрано в одну стеклянную консоль внизу по центру: слева здоровье крупными цифрами и полосой (желтеет и краснеет, при низком — пульсирует), по центру название ствола, патроны крупно и полоса перезарядки под ними (во время перезарядки цифры сменяются надписью), справа квадратные чипы гранаты и аптечки с иконкой, счётчиком «×N» и клавишей (G/H, берутся из назначений игрока; пустой чип гаснет). Над консолью — пояс оружия: пять карточек с силуэтами стволов, номером клавиши и запасом патронов; активная приподнята и подсвечена янтарным. Пояс показывается только по делу: при возрождении (на 2,6 с) и при смене оружия — клавишами 1–5, колесом мыши или выбором в инвентаре; через 1,6 с после последнего выбора он плавно исчезает, оставляя экран чистым. Сверху по центру счёт: красная и синяя плашки с названием команды и крупным числом, лимит раунда посередине (в «каждый сам за себя» — «Вы N» и лидер). Слева сверху чип игрока (ник, точка цвета команды, убийства · смерти), под ним лента убийств с цветной меткой (мои — зелёная, мои смерти — красная) и список говорящих; пинг и кадры в секунду — тихой строкой в правом нижнем углу. Консоль и пояс скрываются после смерти; когда мышь не захвачена (Esc), они поднимаются над вернувшейся панелью кнопок. Нижняя панель кнопок в игре прозрачная и скрывается, пока мышь захвачена. Окна (настройки, статистика, таблица лидеров, клавиши, итог раунда) выдержаны в одном стиле: закруглённые панели с тенью, размытый фон, шапка с акцентной чертой, клавиши как «кнопки-капсы», активные вкладки цвета кирпича; таблица очков по Tab и экран смерти — тёмное стекло. Стартовая карточка: «Тренироваться» и «Играть» — широкие главные кнопки, настройки, статистика и таблица лидеров — рядом в одну строку. Анимации появления отключаются при `prefers-reduced-motion`.
- **Шаги.** Свои шаги слышны тихо (шаг раз в 2 м пешком и в 3 м на бегу, в приседе тишина, приземление после прыжка глухо ударяет); шаги других слышны до 40 м, слева или справа по их направлению, приглушены за домом, на асфальте звонче, чем на траве; присевший и прыгающий не шумят. Записи шагов по бетону и траве — Kenney (CC0, OGG), при недоступности файлов — синтез.
- **Частота кадров.** Уровней графики четыре: высокая, средняя, низкая и «минимум» (картинка в 0,7 размера, дома и деревья только вблизи, дальность 1500 м). Режим качества — **авто** или **фиксированный** уровень: выбирается в настройках (группа «Графика», там же видно текущий уровень) или кнопкой «Графика» в панели — клик переключает по кругу авто → высокая → средняя → низкая → минимум → авто. Выбор хранится в браузере (`dpils-quality-mode`, уровень — `dpils-quality2`). В авто, и в городе, и в игре, подстраивается разрешение картинки (см. «Частота кадров» в разделе об устройстве страницы). Если разрешение уже не помогает (оно на минимуме или его снижение не ускоряет кадры), а игра дважды подряд по 4 с держится меньше 28 кадров в секунду, страница снижает графику на один уровень и пишет об этом в ленте; когда игра четыре окна подряд по 4 с держит 55 и больше кадров в секунду при полном разрешении, уровень повышается обратно (первые 6 с после входа и после каждого изменения не считаются: шейдеры собираются). Фиксированный уровень отключает автоматику: качество и разрешение остаются выбранными. В углу HUD показаны кадры в секунду, пинг и разрешение, если оно ниже полного.
- **Чат.** Сообщения всем и только своей команде (в журнале помечены `[команда]`), до 140 знаков, не чаще раза в 0,7 с; журнал пропадает с экрана через 9 с, пока строка открыта, виден весь. Чужой текст попадает на страницу только как текст.
- **Голосовой чат.** Прямое соединение WebRTC между каждой парой игроков (звук идёт мимо сервера, он передаёт только рукопожатие), микрофон — по кнопке V, при первом нажатии браузер спрашивает разрешение. Слышно по правилу слушателя: товарищи на любом расстоянии (как по рации), враги — только ближе 30 м и тише с расстоянием. Ник говорящего подсвечивается, их список — в левом верхнем углу. Нужен https и микрофон; сервера TURN нет, только STUN, поэтому за строгим NAT два игрока могут друг друга не услышать. Правило «враг слышен ближе 30 м» соблюдает клиент слушателя, не сервер.
- **Карта и метки.** На мини-карте и большой карте видны товарищи; враг появляется на две секунды, когда стреляет. Ники товарищей видны сквозь стены до 250 м, врагов — только по прямой видимости до 90 м. В углу счёта показан пинг.
- **Стены.** Пуля останавливается о рельеф и здания: на луче каждые 1,5 м проверяется, не ниже ли он земли и не внутри ли контура дома ниже его крыши (высота дома хранится в `BLD[i].top`). Ту же проверку делает сервер ([server/world.mjs](server/world.mjs) читает `citydata.js` и `terrain.js`): выстрел сквозь здание не засчитывается, а трасса обрывается у стены. Рельеф сервер берёт сырой (сетка лидара 20 м, без выравнивания крепости и спидвея), поэтому дома считает с запасом в метр. Склон холма теперь тоже останавливает пулю: сервер проверяет землю на луче, как и страница. Грубый шаг 1,5 м уточняется бисекцией — у сервера до ~2 см, у страницы до ~3 мм, так что трасса обрывается у самой стены, цель перед стеной засчитывается, а за стеной — нет (запас 5 см).
- **Реалистичные выстрелы** ([src/game/impacts.js](src/game/impacts.js)). Пуля видна в полёте: короткий трассер летит от ствола к точке попадания со своей скоростью по оружию (автомат 560 м/с, дробь 380, снайперская 820), и звук попадания звучит, когда трассер долетел. На поверхности остаётся след: тёмное отверстие с пылевым ободком и трещинами, повёрнутое по настоящей нормали стены (ближайшее ребро контура дома) или по склону рельефа; точка попадания уточняется бисекцией последнего шага луча до ~3 мм. При попадании в камень и бетон летят искры и пыль, из земли — комок пыли, над точкой поднимается дымок; у своего оружия из окна eject вылетает гильза (отскакивает от земли и лежит 2,5 с), у ствола — пороховой дым и вспышка (следующий пункт). Следы живут 30 с и плавно гаснут, пулы ограничены (140 следов, 240 частиц, 24 гильзы, 80 трассеров), так что долгая перестрелка не растит память; при новом раунде всё убирается. Все частицы — один инстансированный меш (квады к камере, прозрачность через instanced-атрибут), без создания и удаления материалов в бою. Над попавшим врагом всплывает цифра урона (в голову — крупнее и оранжевее, при убийстве — красная), цифры живут 0,9 с и поднимаются ([src/game/impacts.js](src/game/impacts.js), `dmgFloat`). Звук попадания зависит от материала стены: штукатурка и бетон, камень и кирпич, дерево, металл — разные записи Kenney (карта `WALL_MAT` по стилю фасада), взрыв гранаты — запись с низким гулом под ней, эхом и стуком падающих комьев (см. «Взрыв гранаты»). Это чисто клиентский визуал и звук: урон и попадания по-прежнему считает сервер.
- **Вспышка выстрела** ([src/game/muzzle.js](src/game/muzzle.js)) — пламя, как его видит камера.
  - **Клуб огня поперёк ствола.** Несколько языков разной длины, клубы пламени и раскалённое белое сердце; так вспышка выглядит спереди и из-за спины стрелка.
  - **Две скрещённые струи вдоль ствола.** Струя колеблется, края рвутся, на конце она распадается на языки; её видно сбоку под любым углом.
  - **Мягкий ореол у дула**, всегда повёрнут к камере.

  Пламя рисуется цветами ярче белого поверх того, что за ним. Поэтому на светлом небе оно остаётся жёлто-оранжевым, а свечение страницы (bloom) заставляет его сиять, особенно ночью; ореол прибавляется сверху. Рисунки клуба и струй по четыре варианта, они попиксельно считаются из гладкого шума и пишутся на canvas один раз при входе в игру. Каждый выстрел берёт свой вариант (клуб — ещё и зеркально), свой поворот вокруг ствола, размер и длину. Вспышка живёт 40–65 мс: на первом кадре в полную силу, потом гаснет и раздувается. При очереди пламя мерцает. Размер зависит от оружия: у дробовика, снайперской и пулемёта пламя больше, чем у автомата, у пистолета меньше.
  - **У себя.** Вспышка АК висит на дуле анимированного автомата рук и рисуется поверх всего, как сами руки; у остального оружия — перед стволом.
  - **У других игроков** — у дула их оружия, вдоль ствола, на каждый их выстрел.
  - **Свет.** Один источник света на все вспышки: своя вспышка (чуть впереди дула, чтобы руки окрашивались, а не выгорали в белое) или выстрел другого игрока ближе 60 м, смотря что ярче сейчас. Число источников света не меняется, поэтому шейдеры города не пересобираются. Для этого свет стоит прямо в сцене и есть всегда, тёмный между выстрелами и в прогулке. Раньше он висел на группе оружия в руках, а three.js считает только видимые источники: оружие появлялось при старте игры, пропадало при смерти и с прицелом снайперки — и каждый раз менялось число источников у всех материалов. При старте игры это пересобирало около 70 шейдеров города: тот самый рывок.
- **Сервер:** [server/index.mjs](server/index.mjs) (Node и `ws`), геометрия попаданий — [server/combat.mjs](server/combat.mjs). Игроки двигаются сами на своих машинах, сервер ограничивает скорость (11 м/с) и откатывает телепорт. Здоровье, убийства, счёт команд и возрождения ведёт сервер; он проверяет скорострельность, дальность (160 м), стены и попадание по хитбоксам цели (голова, торс, ноги — см. «Хитбоксы»). Цель берётся там, где она была 120 мс назад плюс половина пинга (сервер хранит секунду её положений, высоты глаз и поворотов): стрелок видит чужих в прошлом, и бегущего противника иначе не достать. Положение шлётся 20 раз в секунду, снимок мира — 15 раз; чужие игроки рисуются на 120 мс в прошлом между двумя снимками.
- **Чего пока нет:** античита и мобильного управления.

```bash
npm run server
```

Сервер слушает порт 8787 (`PORT=…` меняет), `/health` отвечает числом игроков, `/auth/register`, `/auth/login` и `/auth/me` обслуживают аккаунты (`ACCOUNTS=…`, см. «Аккаунты: вход и регистрация»). Ему нужны файлы города рядом: запускать из клона репозитория. На GitHub Pages сервер не запустить: его нужно разместить отдельно за `wss://` (установка на VPS с systemd и Caddy — в [server/deploy/README.md](server/deploy/README.md)). Адрес берётся из поля «Сервер», из `?server=wss://…` или из константы `DEFAULT_SERVER` в [src/game/mp.js](src/game/mp.js); на localhost по умолчанию `ws://localhost:8787`.

С `STATIC=dist` (после `npm run build`) сервер отдаёт и саму страницу: город и сервер живут на одном адресе. Так устроен **https://dvinsk.lat**: на VPS процесс pm2 `dpils` слушает порт 3000 (за ним Traefik с сертификатом), страница, `/health`, `/leaderboard` и `wss://dvinsk.lat` — с него. Сервер `wss://dvinsk.lat` записан в [servers.json](servers.json), поэтому виден в списке и на GitHub Pages; пустое поле «Сервер» само берёт первый отвечающий сервер списка. Установка и обновление — в [server/deploy/README.md](server/deploy/README.md).

## Разработка

Страница — [index.html](index.html), код — ES-модули в [src/](src/), сборка — [Vite](https://vite.dev), three.js 0.187 из npm (без сборки — та же версия с jsDelivr через import map).

Город был настроен под three.js r128, и при переходе на 0.187 картинка сохранена так: управление цветом выключено (`THREE.ColorManagement.enabled = false` — шестнадцатеричные цвета и цвета вершин берутся как есть, шейдеры сами переводят цвета вершин из sRGB, см. `SRGB_COLOR_VERTEX`), текстуры-холсты помечены `SRGBColorSpace`, вывод — sRGB; яркость солнца и небесного света умножена на π (three.js больше не делает этого сам); мягкие тени PCFSoft убраны из three.js — тени теперь PCF и заметнее. Подъём всех вершин на рельеф (переопределённый `project_vertex`) не трогает служебные материалы PMREM: с 0.18x они рисуют грани куба через этот кусок, и поднятые на рельеф оставляли карту окружения пустой. Если при следующем обновлении изменятся куски, которые подменяет город (`color_vertex`, `opaque_fragment`), страница предупредит об этом в консоли.

- `npm run dev` — сервер разработки (http://localhost:5173) с перезагрузкой при правке.
- Правила для агентов Claude (сами пушат и мержат, владелец смотрит результат на сайте) — в [CLAUDE.md](CLAUDE.md).
- Инструменты и источники данных — в [docs/tools-and-sources.md](docs/tools-and-sources.md): рендер видов без экрана `tools/shots.js`, координаты LKS-92 `tools/lks92.js`, OSM API, Mapillary, лидар и ортофото LGIA, Commons. Там же таблица «Кто чем занят» для нескольких агентов.

- `npm run check` ([tools/check.mjs](tools/check.mjs)) — каждый импорт находит модуль и экспорт, нет необъявленных имён, а модули можно вычислить в том порядке, в каком их вычисляет браузер: ни один модуль при загрузке не читает `const`/`let` модуля, который ещё не вычислен (такое бывает при циклических импортах). Проверка запускается в CI ([.github/workflows/ci.yml](.github/workflows/ci.yml)) вместе со сборкой.
- `npm run build` — сборка в `dist/`: один бандл плюс файлы данных рядом.
- Без сборки страница тоже работает с любого статического сервера (так её показывает GitHub Pages): three.js приходит через import map с jsDelivr, модули загружает сам браузер. Старый адрес `daugavpils.html` перенаправляет на `index.html`.

Модули:
- `core/` — окружение и данные города (`env`), мелкие функции (`util`), построитель геометрии `GB` и сетка отрезков `SegGrid` (`geometry`), общее изменяемое состояние (`state`);
- `render/` — рендерер, сцена и шейдерные куски (`renderer`), процедурные текстуры, материалы, свет и небо (`lighting`), постобработка, LOD и тени (`post`), нарезка мешей на весь город на квадраты (`chunks`);
- `world/` — рельеф, данные для карты и столкновений (`data`), палитры, земля и вода, улицы и рельсы, теги OSM для 18. novembra (`street-tags`) и её светофоры (`signals`), мост Единства, путепровод на 18. novembra, контактная сеть трамвая, фонари, деревья;
- `buildings/` — стены и крыши (`walls`), типовые 5–9-этажки (`series`), сборка всех домов (`buildings`);
- `landmarks/` — общее для ориентиров (`core`, атлас деталей и вывесок `tiles`, `helpers`), по файлу на каждый ориентир, школы и их площадки (`schools`, `school-grounds`) и `index` с `buildLandmarks`;
- `fortress/` — крепость: рельеф валов, текстуры, ворота, арсеналы, памятники, сборка;
- `transit/` — транспорт по расписанию; `game/` — игрок, управление, кадр; `ui/` — места, карта, панель;
- `boot.js` — точка входа: скачивает данные города и затем загружает `main.js`, который импортирует все модули и строит город;
- `ui/loading.js` — полоса загрузки на стартовой карточке.

Загрузка. `boot.js` скачивает четыре файла данных через `fetch`, показывая мегабайты, и запускает их в прежнем порядке; модули сборки грузятся только после этого, потому что читают данные при вычислении. Сборка идёт шагами (фасады, земля, улицы, дома порциями по 4000, ориентиры, крепость, деревья, цветы в парках, транспорт, нарезка мешей на весь город на квадраты). У каждого шага своя доля полосы по весу — сколько миллисекунд он занимает на эталонной машине. Веса в `main.js` перемерены 18.11.2026 на ноутбуке с RTX 3050 и Intel UHD: доли шагов на двух видеокартах усреднены. Старые веса отставали от новых частей города, и полоса стояла на месте до 17 с: на 77 % — пока сажались деревья, на 56 % — пока строились ориентиры.

Шаг занимает основной поток: между его паузами (см. ниже) браузер рисует кадры, но первый кадр и отдельные куски шагов держат страницу дольше. Поэтому полоса не перерисовывается из скрипта, а шаг сразу получает весь свой путь как анимацию трансформации (Web Animations): такую анимацию ведёт компоновщик браузера, и она движется, даже когда основной поток занят ([src/ui/loading.js](src/ui/loading.js)). Ожидаемое время шага — его вес, умноженный на то, как быстро шли предыдущие шаги сборки на этой машине. Загрузку кода в эту оценку не берём: её время — в основном сеть. За ожидаемое время полоса проходит 75 % доли шага, дальше медленнее идёт к 99 % до двух с половиной ожидаемых времён: долгий шаг полосу замедляет, но не останавливает.

Каждый шаг начинается оттуда, где полоса видна сейчас. Это место считается по её пути и часам, а не по стилю: часы анимаций основного потока стоят, пока шаг не даёт рисовать. Быстрее 12 % длины в секунду полоса не движется, поэтому рано закончившийся шаг не даёт скачка — полоса догоняет на следующих.

Паузы внутри шагов. Шаги сборки шли одним куском по 1–3 с (ориентиры 2,7 с, земля, деревья и транспорт больше чем по 2 с), и всё это время страница не отвечала: стартовая карточка не открывала настройки, статистику и «Управление», не меняла время суток. Теперь циклы долгих шагов спрашивают `due()` и, проработав 40 мс, ждут `pause()` ([src/core/pause.js](src/core/pause.js)): браузер обрабатывает клики и рисует кадр, потом цикл идёт дальше. Пауза — сообщение странице самой себе через `MessageChannel`, а не таймер: таймеры скрытой вкладки замедляются до одного в секунду. На время паузы откладывается `STATE.GBC` (поправка высот строящейся геометрии): то, что успеет выполниться в паузе (например, пришедший файл модели), строит свою геометрию. Паузы стоят в рельефе, земле и воде (`subTrisPaused` — тот же `subTris`, разбитый генератором на части), улицах, домах, ориентирах (между ориентирами и внутри камышей Губище), крепости, сетке глубины, деревьях, цветах, маршрутах транспорта, нарезке мешей на квадраты и загрузке текстур моделей игроков; шейдеры постобработки компилируются по одному за кадр. Замер без экрана (headless Chromium с программным рендером, клик по «Управлению» каждые 0,3 с, пока строится город): самая длинная задача основного потока была 2,7 с, стала 0,27 с; их сумма — 18,7 и 5,4 с; ответ на клик ждал до 2,25 с, теперь до 0,2 с. Сборка не стала дольше. Остались куски по 0,2–0,3 с внутри отдельных ориентиров (парки, школы) и первый кадр, в котором видеокарта получает всю геометрию.

Шрифт вывесок. Вывески ориентиров рисуются на canvas шрифтом Golos Text, а латышские буквы (Ā, Ē, Ī, Ģ…) лежат в его части latin-ext, которой на стартовой карточке нет. Браузер запрашивал этот файл, только когда рисовалась первая вывеска, — посреди сборки, на шаге ориентиров (около 49 % полосы). Буквы на вывесках выходили запасным шрифтом, а сам шрифт приходил, пока страница была занята, и текст карточки раскладывался заново. Теперь `boot.js` запрашивает эти части шрифта вместе с данными и перед сборкой ждёт их (не дольше 3 с).

Цветы в парках — отдельный шаг. Раньше их сажали, когда приходили файлы моделей, куском работы в 6–7 с, который падал в случайный шаг (обычно в «Сажаю деревья») или даже после «Готово». Места для цветов ищутся только пока их хватает (те же места, что и раньше), и шаг занимает полсекунды. Перед включением кнопки шейдеры всех материалов компилируются по одному объекту между кадрами (`warmUp` в `render/post.js`), затем рисуется первый кадр, и город проявляется за карточкой — кнопка не включается раньше, чем страница готова отвечать.

Модели игроков и оружия грузятся с городом (`loadModels` в [src/game/mp.js](src/game/mp.js)). Раньше файлы игроков и оружия запрашивались только по кнопке «Играть» или «Тренироваться»: первые секунды игроки были фигурками из коробок, а в руках — коробочное оружие, потом с рывками появлялись настоящие модели (разбор файлов, компиляция шейдеров и загрузка текстур посреди игры). Теперь файлы — руки с АК, солдат и четыре ствола, мужчина и женщина Quaternius с причёсками (боты надевают их случайно) — начинают качаться в начале сборки города, пока страница занята домами и деревьями. Шаг «Одеваю игроков и раздаю оружие…» перед шейдерами ждёт их (не дольше минуты), надевает руки с оружием на камеру и ставит в сцену по одному невидимому игроку каждого вида (солдат, все причёски и борода, у каждого все пять стволов) по одному предмету карты (ящик патронов, аптечка, граната — модели `props.js`) и по одной метке боя (дырка от пули, трассер, гильза, взрыв). Общий `warmUp` компилирует их шейдеры вместе с городскими, текстуры сразу уходят в видеокарту (`renderer.initTexture`). После первого кадра образцы убираются из сцены, но их материалы не освобождаются, так что программы шейдеров остаются готовыми для игроков и пешеходов. Дуло каждого ствола ищется по вершинам один раз, а не для каждого игрока заново. Вторая причина рывка была в свете вспышки (см. «Свет» в разделе онлайн-шутера): при старте игры менялось число источников света, и пересобирались шейдеры всего города. Проверка без экрана (тренировка с 4 ботами, автонастройка графики выключена): раньше за первые 4 кадра игры компилировалось 78 новых программ шейдеров, а боты были коробками (модели ещё не пришли, их шейдеры добавлялись потом). Теперь — ни одной, и у всех ботов с первого кадра готовые модели.

Частота кадров. Город рисуется за несколько сотен вызовов отрисовки, и кадр упирался в их число и в вершины, а не в пиксели: на RTX 3050 кадр 1600×900 почти не дешевел при разрешении 160×90. Поэтому:
- Тайлы деревьев (500 м) отсекаются по своей сфере вокруг деревьев (`InstancedMesh.boundingSphere`, [src/world/trees.js](src/world/trees.js)). Раньше three.js строил её из сферы геометрии через матрицы экземпляров, а квад дальнего дерева растянут на высоту дерева — сфера выходила в километры, и все ~650 тайлов города рисовались в каждом кадре.
- 17 000 фонарей — не один меш на город, а участки по километру со своими сферами ([src/world/lamps.js](src/world/lamps.js)); столбы отбрасывают тень только с тех участков, что попали в карту теней.
- Меши на весь город (слои земли, разметка, вода, сетка глубины под землёй, общая геометрия ориентиров) после сборки режутся на квадраты по 1,5 км, и каждый отсекается отдельно ([src/render/chunks.js](src/render/chunks.js)). Треугольник на границе квадрата обрезается по ней, поэтому всё, что лежит в одном месте, попадает в один квадрат в прежнем порядке: слои земли, которые рисуются друг поверх друга без записи глубины, не перемешиваются. Исходный меш остаётся на месте (сам не рисуется) и держит свои квадраты как дочерние, так что код, который его прячет или показывает, работает как прежде.
- Мини-карта собирается из запомненных квадратов по 256 точек на уровнях масштаба через пол-октавы ([src/ui/map.js](src/ui/map.js)). Раньше её полная перерисовка каждые 0,15 с в полёте занимала до трети основного потока.
- Разрешение картинки подстраивается под частоту кадров ([src/game/perf.js](src/game/perf.js)). Если кадр дольше 1/45 с, сцена рисуется в меньшую долю буфера (`PP.scale`, шагами по 5 %, не меньше 0,55 точки CSS), а последний проход постобработки растягивает её на весь экран. Когда кадры три секунды успевают за экраном, доля возвращается на шаг вверх. Шаг вниз, после которого кадры не ускорились (страница ждёт процессор или браузер держит 30 кадров в секунду), отменяется и полминуты не повторяется. `window.__city.PERF.dyn = false` выключает подстройку; `tools/shots.js` так и делает.

Замеры (headless Chromium на ноутбуке с RTX 3050 и Intel UHD, 1600×900, подстройка разрешения выключена — кадров в секунду до и после):

| Вид | RTX 3050, «высокая» | Intel UHD, «средняя» |
|---|---|---|
| улица у площади Единства, 1,7 м | 38 → 47 | 13 → 21 |
| площадь Единства, 25 м | 38 → 70 | 13 → 25 |
| над центром, 150 м | 23 → 73 | 11 → 20 |
| луга к югу от центра, 40 м | 41 → 129 | 15 → 26 |
| полёт, 120 м | 15 → 67 | 12 → 20 |
| весь город, 400 м | 37 → 58 | 8 → 13 |

У земли вызовов отрисовки стало 440–640 вместо 870–950, треугольников 2–3,5 млн вместо 7,5. Подстройка разрешения добавляет к этому там, где кадр упирается в пиксели (на Intel в полёте — около 29 кадров в секунду).

Модули получены из прежнего единого скрипта `daugavpils.html` автоматическим разбиением по разделам; поведение не изменилось — при одинаковых случайных числах и одинаковом времени кадров старая и новая страницы дают одинаковые до пикселя кадры. Значения, которые присваивают несколько модулей (компенсация высот `GBC` у строящейся геометрии, таймеры кадра, состояние сеанса), лежат в объекте `STATE` ([src/core/state.js](src/core/state.js)): импортированную переменную модуль изменить не может.

## Как пересобрать `citydata.js`

1. Скачать OpenStreetMap через Overpass API запросами из [tools/queries](tools/queries) в файлы `build.json`, `rest.json`, `rel.json` (одна папка).
2. Скачать с data.gov.lv кадастровые SHP для Даугавпилса (`0002000_kk_shp.zip`) и Аугшдаугавского края (`0022000_kk_shp.zip`), распаковать; из `building.zip` взять XML этих же территорий.
3. Собрать здания кадастра:
   ```bash
   node tools/cadastre.js cadastre.json kk_shp kk_shp2 -- Building/0002000_*/*.xml Building/0022000_*/*.xml
   ```
4. Собрать город:
   ```bash
   node tools/process.js osm cadastre.json citydata.js
   ```

## Как обновить стоянки `parking.js`

Выгрузить город квадратами OSM API (Overpass из облака не отвечает) и собрать:
```bash
mkdir -p osm-parking && cd osm-parking
for i in 0 1 2 3 4 5 6; do for j in 0 1 2 3 4 5; do
  w=$(echo "26.44+$i*0.03" | bc); s=$(echo "55.825+$j*0.02" | bc)
  curl -sS -o "t_${i}_${j}.osm" "https://api.openstreetmap.org/api/0.6/map?bbox=$w,$s,$(echo "$w+0.03" | bc),$(echo "$s+0.02" | bc)"; sleep 1
done; done
cd .. && node tools/parking.js citydata.js parking.js osm-parking/*.osm
```
Если API ответит на квадрат ошибкой 400 (больше 50 тыс. точек), его надо разделить на четыре.

## Как обновить дворы `yards.js`

Те же квадраты OSM, что для `parking.js`; районы — границы OSM (relation), их можно перечислить несколько:
```bash
node tools/yards.js citydata.js yards.js --relation 5464161 osm-parking/*.osm
```

## Как обновить междугородние автобусы `intercity.js`

Скачать и распаковать GTFS ATD ([atd.lv](https://www.atd.lv/sites/default/files/GTFS/gtfs-latvia-lv.zip) или копию [Mobility Database](https://storage.googleapis.com/storage/v1/b/mdb-latest/o/lv-riga-valsts-sia-autotransporta-direkcija-atd-gtfs-992.zip?alt=media)), затем:
```bash
node tools/intercity.js gtfs citydata.js intercity.js
```

## Как обновить расписание поездов `trains.js`

Скачать и распаковать GTFS поездов ([vivi.lv/uploads/GTFS.zip](https://vivi.lv/uploads/GTFS.zip)) и выгрузить OSM вокруг вокзала ([api.openstreetmap.org/api/0.6/map?bbox=26.52158,55.87172,26.53279,55.87756](https://api.openstreetmap.org/api/0.6/map?bbox=26.52158,55.87172,26.53279,55.87756)), затем:
```bash
node tools/trains.js gtfs citydata.js station.osm trains.js
```

## Как обновить расписание `transit.js`

Скачать и распаковать свежий GTFS «Daugavpils satiksme», затем:
```bash
node tools/transit.js gtfs citydata.js transit.js
```
