# Правила для параллельных агентов

Над проектом одновременно работают несколько ИИ-агентов (Claude, Chatbox и др.) на одной машине. Общий рабочий каталог `C:/Users/igors/Desktop/DPILS` — **чужая рабочая зона**: в нём прямо сейчас может лежать незакоммиченная работа соседа. Однажды `git checkout` + `reset` в общем каталоге уже стёрли несохранённые правки другого агента. Правила ниже обязательны для всех.

Рабочий процесс (ветки, `npm run check` / `npm run build`, PR, авто-мерж, что нельзя) описан в [CLAUDE.md](CLAUDE.md) и распространяется на всех агентов, не только Claude. Этот файл добавляет протокол изоляции.

## Продакшен — только VPS (объявление от 19.11.2026)

Единственный рабочий сайт проекта — **https://dvinsk.lat** (VPS `kicad-vps`, pm2-процесс `dpils` с `STATIC=dist` отдаёт собранный `dist/`). GitHub Pages больше не используется: ни как цель деплоя, ни как место проверки результата.

- Владелец смотрит результат только на https://dvinsk.lat; в итоговом ответе агента ссылка тоже на него.
- После мержа PR агент **сам обновляет VPS**: `ssh kicad-vps "bash -lc 'source ~/.nvm/nvm.sh; cd ~/dpils && git pull && npm run build && pm2 restart dpils'"` (подробности — [server/deploy/README.md](server/deploy/README.md)). Без этого шага задача не считается доведённой до сайта.
- VPS отдаёт только собранный `dist/`: каждый новый runtime-файл (текстура, модель, звук, данные) обязан попасть в список `STATIC` в [vite.config.mjs](vite.config.mjs), иначе на сайте 404.

## 1. Каждый агент — в своём worktree

Вся работа (правки, сборки, тесты) идёт в **собственном git worktree**, а не в общем каталоге:

```powershell
git -C C:/Users/igors/Desktop/DPILS fetch origin
git -C C:/Users/igors/Desktop/DPILS worktree add -b <prefix>/<branch> `
  C:/Users/igors/Desktop/DPILS/.claude/worktrees/<branch> origin/main
# node_modules в worktree не ставим заново — junction из общего каталога:
New-Item -ItemType Junction -Path <worktree>/node_modules -Target C:/Users/igors/Desktop/DPILS/node_modules
```

- `<prefix>` — `chatbox/` для Chatbox, `claude/` для Claude.
- Worktree создаётся **от `origin/main`**, а не от локального `main` (локальный может отставать или стоять на чужой ветке).
- В общем каталоге допускаются только read-only команды (`status`, `log`, `fetch`, `worktree add/list`, `show`).

## 2. Запрещено в общем каталоге и в чужих worktree

- `git checkout` / `switch` / `reset` / `restore` / `stash` / `clean` — всё, что меняет чужое рабочее дерево или индекс;
- любые правки, удаление или «приборка» файлов, которые ты не создавал в этой сессии (в т.ч. `tools/tmp-*`, чужие `*.mjs`, кадры, логи);
- force-push и удаление чужих веток; коммиты в чужую ветку;
- массовое убийство процессов (`Stop-Process -Name node` и т.п.). Убивать только свои процессы, отфильтровав по командной строке: `Get-CimInstance Win32_Process | Where CommandLine -like '*<твой-скрипт>*'`.

Если обнаружил в общем каталоге чужую ветку или грязное дерево — **не чини и не откатывай**: это работа соседа. Создай свой worktree и работай там.

## 3. Ранние коммиты

Незакоммиченная работа не переживает чужие ошибки. Коммить в свою ветку рано и часто (WIP-коммит допустим, причешешь перед PR). Долгие сборки артефактов (модели, текстуры) — сразу коммитить результат, источники держать в своём sandbox сессии.

## 4. Таблица «Кто чем занят»

Перед началом правок впиши себя в таблицу в [docs/tools-and-sources.md](docs/tools-and-sources.md) (кто, ветка, задача, файлы), перед финальным мержем убери строку. Правила таблицы:

- в коммит попадают **только твои строки**: в своём worktree файл приходит из `main`, чужие незакоммиченные строки из общего каталога туда не копируй;
- если задача задевает файлы из чужой строки — выбери другую зону или дождись мержа соседа, затем влей свежий `origin/main`.

## 5. Порты, серверы, тесты

- Каждый агент поднимает тестовые серверы на **своих портах** (например, 8765 + номер сессии); порт 8766 из `.claude/launch.json` может быть занят соседом — не убивай чужой сервер, возьми другой порт.
- Headless-браузеры и фоновые процессы — только свои (см. п. 2); по завершении прибери их.
- Временные скрипты и кадры — в sandbox своей сессии, не в `tools/` общего репозитория.

## 6. Мерж и уборка

- Политика ветки требует актуальности с `main`: если `gh pr merge` отвечает «base branch policy prohibits the merge» — влей `origin/main` в свою ветку, заново прогони `npm run check && npm run build`, запушь; авто-мерж сработает сам. `--admin` не нужен.
- После мержа убери **свой** worktree: сначала удали junction `node_modules` (`cmd /c rmdir "<worktree>\node_modules"` — rmdir снимает только junction, не содержимое), затем `git worktree remove <worktree>` и `git worktree prune`. Чужие worktree не трогай.
- Локальный `main` в общем каталоге не обновляй (`git pull` там меняет чужое дерево) — свежий код бери через `fetch` + `origin/main`.
